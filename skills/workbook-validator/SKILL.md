# 워크북 정합성 검증 게이트 (Workbook Validator)

## Phase 0 — 무결성 확인 (본론 착수 전 1회)

본 스킬은 검증 규율을 누적해 온 파일이며, 다른 TP 스킬과 서로를 지목하며 맞물려 동작한다.
경고문이 지워지거나 구버전이 섞이면 오류를 검출하는 대신 **주입**하게 되므로, 본론에 들어가기
전에 정본 여부를 먼저 확인한다.

**실행 방법 — 스킬 폴더를 탐색해서 이동한 뒤 실행한다.**

```bash
D=$(find ~ / -maxdepth 8 -type d -name "workbook-validator" -path "*skills*" 2>/dev/null | head -1)
cd "$D" && python3 scripts/verify_skills.py
```

⚠️ **스킬이 안내하는 base directory 경로를 그대로 쓰지 말 것.** 그 경로는 Windows 형식
(`C:\Users\...`)인데 명령을 실행하는 셸은 **Linux 경로 체계**를 쓴다. 같은 폴더인데 이름이
달라 `No such file or directory`가 난다(실행 검증에서 실제로 확인한 오류다).
위 탐색 방식은 **경로 체계와 무관하게 동작**하며 약 1초 걸린다.

폴더 안에서 실행하면 **인자가 필요 없다.** 스크립트가 루트와 대상 스킬을 스스로 판별한다.

- **합격** — 그대로 진행한다. 별도로 보고하지 않는다.
- **변조·누락** — **작업을 중단하고 사용자에게 고지**한다. 어느 파일이 정본과 다른지 알린다.
  사용자가 진행을 지시하면 「무결성 미확인 상태」임을 답변에 명시하고 진행한다.
- **실행 불가**(경로·스크립트·매니페스트 없음) — 검증을 **생략하되 침묵하지 않는다.**
  한 줄로 「무결성 확인 미실행」을 알리고 진행한다.
- **`[미설치] tp-case-law`가 보이면** — 본 스킬이 조문·판례 검증을 tp-case-law에 맡기는
  부분은 실행되지 않는다. 해당 단계에서 그 사실을 고지하고, 조문 인용은 「확인 필요」로 표기한다.

⚠️ **이 절차는 변조를 막지 못한다. 드러나게 할 뿐이다.** 매니페스트(`scripts/MANIFEST.sha256`)가
함께 바뀌면 검증은 통과한다. 배포 시에는 매니페스트를 변경 이력이 남는 곳에도 보관하고 대조한다.

## 0. 기본 원칙

- **전제**: 워크북은 여러 도구(ABC_TP_Tool, DB 추출, Claude for Excel 프롬프트, 수작업)가
  채운 시트의 집합이므로 코드 체계·표기·수치가 어긋나 있을 수 있다. Claude는 스크립트
  (openpyxl 등)로 **전수 재계산·교차 대조**하고, 발견사항의 처리는 **항상 사용자가 확정**한다.
- **실행 시점**: 워크북 완성 직후 · tp-report-writer Step 0 착수 직전. 보고서는 워크북 수치를
  그대로 전기하므로, 오류는 반드시 이 게이트에서 워크북 단계에 수정한다.
- **게이트 원칙**: 각 Phase는 「검증 → 발견사항 보고(심각도 분류) → 사용자 확정」을 거치고
  `progress.md`에 기록한다. 구동 지시어는 "Phase N 실행", 순서는 0 → 1 → 2 → 3 → 4.
- **검증이지 재분석이 아니다**: 비교가능회사 선정의 타당성(comparable-search-review 소관),
  특성분류·Tested Party 논거(characterization-gate 소관), 방법 선택 논거(Tap16 프롬프트 소관)는
  범위 밖. 본 스킬은 수리·표기·전기(轉記) 정합성만 다룬다.

### 심각도 분류 (모든 발견사항에 부여)

| 등급 | 정의 | 처리 |
|---|---|---|
| **A (결론 영향)** | 정상범위·판정·기여율·평가단위가 달라질 수 있는 오류 (사분위 오계산, 시트 간 범위 상이, 논리 오류, **원본의 다른 PLI 행을 전기한 오류**) | 최우선 확정 — 미해결 시 게이트 불합격 |
| **B (표기·라벨)** | 결론은 같으나 보고서 전기 시 혼선 유발 (PLI 명칭 상충, 코드 이중 사용, 거래방향 반대 기재) | 정본 표기 확정 후 통과 가능 |
| **C (데이터 품질)** | 이상 징후 (연도 간 동일값 복제, 결측, 단위 혼재) | 사유 확인·기록 후 통과 가능 |

## 1. Phase 0 — 인수 및 기준선 설정

1. **워크북 원본 xlsx** — 수식 보존 상태. 값 붙여넣기 시트는 원본 산출 파일을 함께 요청.
2. **선행 게이트 검토조서 인수** — characterization-gate 검토조서(코드 대응표·Tested Party
   요약표)와 comparable-search-review 방어 패키지가 있으면 인수하여 **해당 항목은 재검증하지
   않고 인용**한다. 없으면 Phase 1에서 코드 검증을 직접 수행한다.
3. **평가단위 목록 확정** — 평가단위코드 × 분석대상법인 × PLI × 방법의 기준표를 사용자와 확정.
   이 표가 Phase 2~3의 검증 단위가 된다.
4. **정상가격 산출 원본** (필수) — Tap17이 전기해 온 산출 파일(예: `정상가격분석_*.xlsx`).
   ⚠️ **워크북 내부 검증만으로는 전기 오류를 검출할 수 없다.** Tap17은 사분위·조정 구조가
   내부적으로 완전히 일관하면서도 원본의 **다른 PLI 행**을 옮겨온 상태일 수 있다
   (실전 검출례: 원본이 8종 PLI를 병렬 산출하는데 채택 행이 아닌 첫 행 Gross margin이
   전기되어 정상범위가 3배로 뒤바뀐 사례). 미제출 시 **Phase 2-0을 수행할 수 없으므로
   그 사실과 재현 한계를 검증 보고서에 명시**하고 조건부로만 진행한다.
   원본이 복수 시나리오 시트(예: 기본 / 평균방식 상이 / 특정비용 조정)를 포함하면
   **정본 시나리오를 사용자에게 확정**받는다.

게이트: 워크북 인수 + 평가단위 기준표 확정 + 정상가격 산출 원본 인수(또는 미제출 사유 기록).

## 2. Phase 1 — 구조·코드·표기 스캔

전 시트를 스캔하여 사전(dictionary)을 구축하고 상충을 검출한다.

1. **시트 완비성** — Tap1~Tap18 표준 체계 대비 존재·누락·추가 시트 목록.
2. **코드 사전** — 법인코드, 평가단위코드, 거래코드(TRE_00n/TR00n)의 전 시트 출현 위치 수집:
   - 거래코드 이중 체계의 대응표 확정 (예: Tap3/14의 TRE_00n vs Tap16 서술의 TR00n)
   - 법인코드와 평가단위코드의 중복 사용 검출 (예: G1이 법인이자 평가단위) [등급 B]
3. **PLI 표기 사전** — Tap14·16·17·18에서 평가단위별 PLI 명칭·산식을 수집하고 상충 검출.
   ⚠️ 실전 검출례: Tap17 헤더 "영업이익률(OM)" vs Tap18 "영업이익/총원가(총원가가산이익률)",
   Tap17 "매출총이익률(GM)" vs Tap18 "원가가산이익률" — 값은 같고 라벨만 다른 경우와
   산식 자체가 다른 경우를 구분해 보고한다 [전자 B / 후자 A].
   ⚠️ **라벨 상충은 표기 문제로 단정하지 말 것** — 실전에서 Tap17 라벨("영업이익률(OM)")과
   Tap18 서술("총원가가산이익률")이 어긋난 사안의 실제 원인은 표기가 아니라 **원본에서 다른
   PLI 행(Gross margin)을 전기한 오류**였다. 본 Phase에서는 상충 사실만 기록하고,
   **실질 판정은 Phase 2-0의 원본 대조로 확정**한다.
4. **거래방향** — 사용료 등 방향성 거래의 제공↔지급 방향이 시트 간 반대로 기재되지 않았는지.
5. **단위·통화** — 천원/백만원/EUR 등 단위 표기의 시트 간 일관성, %와 소수 혼용 검출.
6. **법령 인용 검증** — 전 시트에서 `국조법|국조령|국조칙|OECD TPG` 인용을 정규식으로
   수집하고 **국가법령정보센터 현행 조문과 대조**한다. 워크북 내부 일관성만으로는 검출되지 않으므로
   외부 대조가 필수다. **대조는 tp-case-law 스킬을 경유하되, 그 스킬의 「주요 조문(현행)」 표에서
   [검증됨]으로 표시된 항목만 근거로 채택**한다.
   - ⓐ **조번호 실재 여부** — 특히 「~의2」 가지조문은 실재하지 않는 경우가 있다 [등급 A]

## 3. Phase 2 — Tap17 수치 전수 재계산

평가단위별로 정상가격 산출표를 독립 재현한다.

**0. 원본 전기 대조 (선행 필수)** — Phase 0에서 인수한 정상가격 산출 원본과 Tap17을 대조한다.
   - **채택 PLI 행의 특정** — 원본이 복수 PLI를 병렬 산출하는 경우(Gross margin, Cost-plus
     Markup, Berry Ratio, Operating margin, Cost Cover Ratio 등), 보고서가 채택한 행을
     **라벨과 산식(예: `G/(B+D)` = PBT/총원가)까지 명시적으로 특정**한다.
   - **전수 대조** — 비교가능회사별 PLI 값·사분위(Q1/Med/Q3)·분석대상 실현치가 **채택 행에서
     전기되었는지 회사 단위로 전건 대조**한다. 다른 행에서 왔으면 [등급 A].
   - **분석대상 ↔ 비교대상 PLI 정합** — 양측이 동일 행(동일 산식)에서 산출되었는지 확인한다.
     의도적으로 다른 지표를 적용한 경우(예: 비교대상 PBT / 분석대상 EBIT) **그 자체가 오류는
     아니나**, 근거(회계 계상 위치 차이 등)가 문서화되어 있는지 확인하고 미문서화 시 [등급 B].
   - **시나리오 혼용 검출** — 원본에 복수 시나리오 시트가 있을 때, 정상범위와 실현치가
     **서로 다른 시나리오에서 인용되지 않았는지** 확인한다 [등급 A].

     연도별/합계)을 순회 대조하여 **실제 산출 기준을 역으로 식별**하고 보고한다.

1. **사분위 재계산** — 조정전·조정후·연도별·평균 각각에 대해 Q1/Median/Q3를 재계산.
   보간 방식(QUARTILE.INC / EXC)을 식별해 명기하고, 방식 선택 근거를 기록한다.

## 8. 경계 (중요)

- 오류를 발견해도 Claude가 워크북을 직접 수정하지 않는다 — 수정 주체는 실무자이며,
  본 스킬은 위치(시트·셀)·등급·권고안을 보고한다.
- 정상범위 방식(사분위 보간법, 다중연도 가중치)의 규범적 타당성 판단이 필요하면
  tp-case-law 스킬로 근거(**국조령 §15⑤·⑥**, TPG paras. 3.55~3.66)를 확인해 인용한다.
  **「국조령 §15의2」는 인용하지 않는다** — 존재하지 않는 가지조문이다(현행 §22).
- **조번호만 확인하고 통과시키지 않는다.** 조문 인용의 검증은 **표제까지** 대조해야 하며,
  구 번호도 현행법에 실재하되 다른 내용을 규정하므로 실재 확인만으로는 오류가 검출되지 않는다.
- 값 붙여넣기로 수식이 소실된 시트는 재현 한계를 보고서에 명시한다 (재현 불가 ≠ 오류).
- **외부 대조는 본 스킬의 범위에 포함된다.** 「검증이지 재분석이 아니다」는 원칙은 비교가능회사
  선정·특성분류 등 **판단**의 재수행을 금지하는 것이지, 법령 조문·산출 원본 등 **사실**의 대조를
  금지하는 것이 아니다. 워크북 내부 정합성만 보는 검증은 「내부적으로 일관된 오류」를 통과시킨다 —
  Case 002에서 법령 오인용 12건과 PLI 오전기가 모두 이 경로로 게이트를 통과하였다.
- 정상가격 산출 원본이 미제출된 상태의 "합격"은 **조건부 합격**이며, 그 취지(전기 대조 미실시)를
  검증 보고서와 progress.md에 명시한다. 원본 확보 후 Phase 2-0만 재실행한다.
