# 워크북 정합성 검증 게이트 (Workbook Validator)

## Phase 0 — 무결성 확인 (본론 착수 전 1회)

본 스킬은 검증 규율을 누적해 온 파일이며, 다른 TP 스킬과 서로를 지목하며 맞물려 동작한다.
경고문이 지워지거나 구버전이 섞이면 오류를 검출하는 대신 **주입**하게 되므로, 본론에 들어가기
전에 정본 여부를 먼저 확인한다.

**실행 방법 — 스킬 폴더를 탐색해서 이동한 뒤 실행한다.**

```bash
D=$(find ~ / -maxdepth 8 -type d -name "workbook-validator" -path "*skills*" 2>/dev/null | head -1)
cd "$D" && python3 scripts/verify_skills.py
```

⚠️ **스킬이 안내하는 base directory 경로를 그대로 쓰지 말 것.** 그 경로는 Windows 형식
(`C:\Users\...`)인데 명령을 실행하는 셸은 **Linux 경로 체계**를 쓴다. 같은 폴더인데 이름이
달라 `No such file or directory`가 난다(실행 검증에서 실제로 확인한 오류다).
위 탐색 방식은 **경로 체계와 무관하게 동작**하며 약 1초 걸린다.

폴더 안에서 실행하면 **인자가 필요 없다.** 스크립트가 루트와 대상 스킬을 스스로 판별한다.

- **합격** — 그대로 진행한다. 별도로 보고하지 않는다.
- **변조·누락** — **작업을 중단하고 사용자에게 고지**한다. 어느 파일이 정본과 다른지 알린다.
  사용자가 진행을 지시하면 「무결성 미확인 상태」임을 답변에 명시하고 진행한다.
- **실행 불가**(경로·스크립트·매니페스트 없음) — 검증을 **생략하되 침묵하지 않는다.**
  한 줄로 「무결성 확인 미실행」을 알리고 진행한다.
- **`[미설치] tp-case-law`가 보이면** — 본 스킬이 조문·판례 검증을 tp-case-law에 맡기는
  부분은 실행되지 않는다. 해당 단계에서 그 사실을 고지하고, 조문 인용은 「확인 필요」로 표기한다.

⚠️ **이 절차는 변조를 막지 못한다. 드러나게 할 뿐이다.** 매니페스트(`scripts/MANIFEST.sha256`)가
함께 바뀌면 검증은 통과한다. 배포 시에는 매니페스트를 변경 이력이 남는 곳에도 보관하고 대조한다.

## 0. 기본 원칙

- **전제**: 워크북은 여러 도구(ABC_TP_Tool, DB 추출, Claude for Excel 프롬프트, 수작업)가
  채운 시트의 집합이므로 코드 체계·표기·수치가 어긋나 있을 수 있다. Claude는 스크립트
  (openpyxl 등)로 **전수 재계산·교차 대조**하고, 발견사항의 처리는 **항상 사용자가 확정**한다.
- **실행 시점**: 워크북 완성 직후 · tp-report-writer Step 0 착수 직전. 보고서는 워크북 수치를
  그대로 전기하므로, 오류는 반드시 이 게이트에서 워크북 단계에 수정한다.
- **게이트 원칙**: 각 Phase는 「검증 → 발견사항 보고(심각도 분류) → 사용자 확정」을 거치고
  `progress.md`에 기록한다. 구동 지시어는 "Phase N 실행", 순서는 0 → 1 → 2 → 3 → 4.
- **검증이지 재분석이 아니다**: 비교가능회사 선정의 타당성(comparable-search-review 소관),
  특성분류·Tested Party 논거(characterization-gate 소관), 방법 선택 논거(Tap16 프롬프트 소관)는
  범위 밖. 본 스킬은 수리·표기·전기(轉記) 정합성만 다룬다.

### 심각도 분류 (모든 발견사항에 부여)

| 등급 | 정의 | 처리 |
|---|---|---|
| **A (결론 영향)** | 정상범위·판정·기여율·평가단위가 달라질 수 있는 오류 (사분위 오계산, 시트 간 범위 상이, 논리 오류, **원본의 다른 PLI 행을 전기한 오류**, **최종 표본의 확인 기록 부재 또는 티어 상충**) | 최우선 확정 — 미해결 시 게이트 불합격 |
| **B (표기·라벨)** | 결론은 같으나 보고서 전기 시 혼선 유발 (PLI 명칭 상충, 코드 이중 사용, 거래방향 반대 기재) | 정본 표기 확정 후 통과 가능 |
| **C (데이터 품질)** | 이상 징후 (연도 간 동일값 복제, 결측, 단위 혼재) | 사유 확인·기록 후 통과 가능 |

## 1. Phase 0 — 인수 및 기준선 설정

1. **워크북 원본 xlsx** — 수식 보존 상태. 값 붙여넣기 시트는 원본 산출 파일을 함께 요청.
2. **선행 게이트 검토조서 인수** — characterization-gate 검토조서(코드 대응표·Tested Party
   요약표)와 comparable-search-review 방어 패키지가 있으면 인수하여 **해당 항목은 재검증하지
   않고 인용**한다. 없으면 Phase 1에서 코드 검증을 직접 수행한다.
3. **평가단위 목록 확정** — 평가단위코드 × 분석대상법인 × PLI × 방법의 기준표를 사용자와 확정.
   이 표가 Phase 2~3의 검증 단위가 된다.
4. **정상가격 산출 원본** (필수) — Tap17이 전기해 온 산출 파일(예: `정상가격분석_*.xlsx`).
   ⚠️ **워크북 내부 검증만으로는 전기 오류를 검출할 수 없다.** Tap17은 사분위·조정 구조가
   내부적으로 완전히 일관하면서도 원본의 **다른 PLI 행**을 옮겨온 상태일 수 있다
   (실전 검출례: 원본이 8종 PLI를 병렬 산출하는데 채택 행이 아닌 첫 행 Gross margin이
   전기되어 정상범위가 3배로 뒤바뀐 사례). 미제출 시 **Phase 2-0을 수행할 수 없으므로
   그 사실과 재현 한계를 검증 보고서에 명시**하고 조건부로만 진행한다.
   원본이 복수 시나리오 시트(예: 기본 / 평균방식 상이 / 특정비용 조정)를 포함하면
   **정본 시나리오를 사용자에게 확정**받는다.

5. **비교가능회사 검색 과정표** (필수) — comparable-search-review 방어 패키지 1(최종 검색과정 표).
   **Phase 1 항목 8의 검사 대상**이다. T3 사안은 **대리 지표표(방어 패키지 8)도 함께 인수**한다.
   ⚠️ 워크북 시트에는 재판정 근거·티어가 없다. 과정표를 인수하지 않으면 최종 표본의 확인 이행
   여부와 티어 정합을 확인할 수단이 없다. 미제출 시 **[등급 A]로 기록하고 조건부로만 진행**한다 —
   「과정표 미인수」는 「확인 기록 없음」과 같은 위험이며, 조용히 건너뛰지 않는다.
   평가단위·트랙이 복수이면 해당 과정표를 모두 인수한다.

6. **종전 실행 기록 대조** (선행 산출물이 있는 경우 필수) — 워크북에 선행 workbook-validator
   산출물(`WV_*` 시트 등)이 있으면 **그 실행 버전·실행일·대상 워크북 판본**을 확인하고,
   **현행 스킬 버전과의 개정 이력 차분을 재검사 대상으로 명시**한다.
   - 종전 「합격」은 **그 시점 요건 기준의 합격**이다. 이후 신설된 요건에 대해서는 미검증이며,
     합격 표시를 근거로 신설 항목을 생략하지 아니한다.
   - **실행 버전이 기재되어 있지 않으면 산출물의 구성으로 역추정**한다. 검증 보고서 시트 수가
     **현행 §5가 요구하는 종수에 미달**하면 그 자체가 구버전 실행의 표지다. 역추정한 경우
     그 사실과 추정 근거를 검증 보고서에 적는다.
   - 종전 실행의 **발견사항 목록을 함께 인수**한다. 검출된 항목이 실제로 정정되었는지는
     **Phase 2 항목 6ⓓ**에서 확인한다 — 검출과 정정은 별개다.

   ⚠️ 실전 검출례(Case 002): 종전 실행은 **v1.1 / 2026-07-20 / 대상 v22**였고 `WV_1~WV_5`만
   남아 있어 「합격」이 현행 요건까지 통과한 것처럼 보였다. v1.2(법령 인용·마스터 시트·동일 시트
   정합성·평가단위 완전성)·v1.5(확인 기록·티어 정합)·v1.6(자료형·스왑) 신설분이 전부 미검증
   상태였고, 재실행에서 **A등급 11건**이 검출되었다.

7. **01 → 03 전기 대조 (Phase 0-α · 신설)** — 워크북에 옮겨 적힌 값이 **회사 원본자료(01)의 어느 값에서
   왔는지**를 본론 착수 전에 대조한다. 워크북 내부 검증의 **선행 단계**이며, 다른 게이트는 이 대조표가
   없으면 조건부로만 진행한다(§8 사안 착수 규율 1).

   **대조 대상(최소)**
   - ⓐ **Tap3 거래별 금액 ↔ 거래별 원천**(인보이스 명세·거래처 원장 등). 거래별 금액이 원천 없이
     **상대방별 총액에서 승격·배분**되었으면 [등급 A]
   - ⓑ **Tap3 합계 ↔ 감사보고서 특수관계자 주석의 통제합계**(상대방별 총액)
   - ⓒ **Tap1-1 지분율 및 지분 보유 경로 ↔ 감사보고서 종속·관계기업 주석·구조도** — 경로는 **단계(중간지주
     개재 여부) 단위로** 대조한다. 각 단계가 100%이면 **지분율만으로는 경로 차이가 검출되지 아니한다**
     [불일치 시 등급 A]. ⚠️ 실전 검출례(Case 003 Inbound): 원본 구조도 2단계 ↔ Tap1-1 3단계, 지분율은 전건 일치
   - ⓓ **Tap3-2·3-3 재무 블록 ↔ 각 법인 감사보고서** — **라벨의 법인명과 출처 파일의 법인명이 같은지**
     확인한다. 라벨만 보면 정상이므로 출처 파일을 열지 않으면 검출되지 않는다 [불일치 시 등급 A]
   - ⓔ **방향성 거래(사용료·수수료 등)의 통화·단위** — 천원/원/EUR/USD의 오인 [등급 A]

   **산출물** — 「원천값(A블록) → 산식 → 워크북 재기재(B블록) → 통제합계 잔액(C블록)」 3블록 대조표를
   워크북에 시트로 남긴다. 잔액은 **「기타·미확인」으로 두고 회사 확인요청 항목으로 넘긴다** —
   **잔액을 맞추기 위해 거래를 조작하지 않는다.** 통제합계 잔액이 ±5% 이내이고 미확인이면 [등급 B(기록)].

   ⚠️ 01 원본자료가 인수되지 않았으면 **본 항목을 수행할 수 없다.** 미실시 사실과 그 범위를 검증
   보고서에 적고 조건부로만 진행한다 — 「대조 결과 이상 없음」으로 적지 않는다.
   ⚠️ 실전 검출례(Case 002 재설정): Tap3 거래별 금액이 감사보고서 주석의 상대방별 총액(51,443·54,921
   백만원)이었고, 사용료 「EUR 1,574,686」은 주석의 「매입 등」 **1,574,686천원**을 통화 오인한 값이었다.
   전 시트가 같은 값을 옮겨 적었으므로 내부 대조는 전건 일치였다.

게이트: 워크북 인수 + 평가단위 기준표 확정 + 정상가격 산출 원본 인수(또는 미제출 사유 기록)
+ **검색 과정표 인수(또는 미제출 A등급 기록)** + **종전 실행 기록 대조(선행 산출물이 있는 경우)**
+ **Phase 0-α 01→03 전기 대조표 작성(또는 미실시 사유 기록)**.

## 2. Phase 1 — 구조·코드·표기 스캔

전 시트를 스캔하여 사전(dictionary)을 구축하고 상충을 검출한다.

1. **시트 완비성** — Tap1~Tap18 표준 체계 대비 존재·누락·추가 시트 목록. **추가 시트에는 선행 게이트·본 게이트·
   실무자 요청으로 신설한 시트(`WV_*`·`CSR_*`·근거 회수 시트 등)도 전건 포함**하고 신설 주체·출처·인용 위치를
   적는다(§8 검증 규율 3).
2. **코드 사전** — 법인코드, 평가단위코드, 거래코드(TRE_00n/TR00n)의 전 시트 출현 위치 수집:
   - 거래코드 이중 체계의 대응표 확정 (예: Tap3/14의 TRE_00n vs Tap16 서술의 TR00n)
   - 법인코드와 평가단위코드의 중복 사용 검출 (예: G1이 법인이자 평가단위) [등급 B]
3. **PLI 표기 사전** — Tap14·16·17·18에서 평가단위별 PLI 명칭·산식을 수집하고 상충 검출.

## 8. 경계 (중요)

### 사안 착수 규율 3항 (전 게이트 공통)

**1. 01(회사 원본자료) → 03(워크북) 전기 대조 조서를 인수한다.**
게이트 체인은 워크북 **내부**의 정합성만 본다. 원천에서 워크북으로 옮겨 적는 구간의 오류는
전 시트가 같은 값을 옮겨 적으므로 **내부 대조로는 원리상 검출되지 않는다**.
- 대조 조서(「원천값 → 산식 → 워크북 재기재 → 통제합계 잔액」 3블록 대조표)는
  **workbook-validator(-inbound) Phase 0-α**가 작성한다. 본 게이트는 그 조서의 **존재와 대상 범위만
  확인**하고 대조 자체를 대행하지 않는다.
- 조서가 없으면 **조건부로만 진행**하고 그 사실을 조서 첫머리에 적는다. 「대조 결과 이상 없음」이
  아니라 **「미실시」**로 적는다 — 둘은 다른 진술이다.

**2. 02 결정기록을 Phase 0에서 함께 읽는다.**
사안 폴더에 `02_결정기록*.xlsx`가 있으면 인수한다. 결정의 이유가 남지 않으면 매 회차 처음부터
재조사하게 되고 같은 쟁점이 판본마다 다르게 정리된다.
- 「채택」 행은 **재판단하지 않고 인수**한다. 재판단이 필요하면 기존 행을 고치지 않고
  **새 행(D-nn)으로 제안**한다.
- 「제외」·「미결」 항목을 **확정 사실처럼 인용하지 않는다.** 미결은 「잠정」 표기와 회사 확인요청
  번호를 함께 적는다.
- 02는 5칸(쟁점 → 대안 → 채택 → 이전가격상 이유 → 03 위치)을 유지하고, 「03 위치」는 `시트!범위`
  형식으로 적어 스크립트 대조가 가능하게 한다. **진행 경위·내부 논의·세무조사 언급은 02에 쓰지
  않는다** — 02는 제출되어도 무방한 문서로 유지한다(아래 R2).

**3. 사안 착수 규칙 R1~R4를 적용한다.**

| 규칙 | 내용 |
|---|---|
| **R1 기준연도** | 분석 기준연도 **이후**의 회사 자료(경영진 보고자료·차년도 실적)는 **참조용으로만** 읽고 분석·서술의 근거로 쓰지 않는다 |
| **R2 비인용** | 세무조사 결과·소명서·합의 내용은 02·03 어디에도 인용하지 않는다 |
| **R3 정본 경로** | 검색·산출 파일은 **지정 폴더의 것만** 쓴다. 회사 폴더의 유사 파일은 해시 대조 후 이력으로만 둔다 |
| **R4 원문 정본** | 비교가능회사 재무·감사보고서 원문은 지정 폴더 기준으로 하나만 둔다. 선행 사례 폴더는 **복사만 하고 이동·삭제·수정하지 않는다**(동결) |

### 검증 규율 3항 (전 게이트 공통)

**1. 원자료를 확인하기 전에 「통제 부재」를 단정하지 않는다.**
게이트가 「통제가 없다」·「기준이 이름만 있다」·「설계가 잘못되었다」고 **판정하려면, 그 판정을
뒤집을 수 있는 원자료를 먼저 확인**한다. 집계 지표(결측률·분포·비율·공란 개수)만으로 설계
결함을 단정하지 아니한다.
- 판정을 조서에 **기재하기 전에** 「이 수치가 정상 설계에서도 나올 수 있는가」를 1회 자문한다.
- 원자료를 확인할 수 없으면 **「미확인」으로 적는다. 「없다」로 적지 않는다** — 둘은 다른 진술이다.
- 이 규율은 **발견을 줄이려는 것이 아니다.** 틀린 A등급은 진짜 A등급의 신뢰를 함께 떨어뜨린다.

**2. 다른 게이트·다른 단위의 판단을 원용할 때는 그 현재 상태를 직접 확인한다.**
「선행 게이트에서 해소되었다」·「같은 기준을 적용하였다」·「전기 조서에서 확인되었다」는 기재는
**그 자체가 검증 대상**이다. 원용하기 전에 그 판단의 현재 상태를 직접 확인하고, 확인 방법을
조서에 적는다.
- **기록과 실제는 갈릴 수 있다.** 「해소」로 적힌 것이 미해소일 수 있고, 「동일 기준」이라 적힌
  것이 실제로는 다른 기준일 수 있다.
- 확인하지 못했으면 **원용하지 않는다.** 원용을 생략하고 직접 판단하거나, 미확인 사실을 함께 적는다.

⚠️ 실전 검출례(Case 002) — 규율 1: Tap17 G1 조정후 표의 공란을 「조정 미실시」로 볼 수 있었으나
실제는 **원본에 조정 자료가 미수록**이고 **조정 미적용이 확정**된 상태여서 **A→C로 강등**되었다.
규율 2: 선행 게이트 조서·선행 `WV_*` 산출물을 인용할 때는 그 **실행 판본**을 먼저 확인한다(Phase 0 항목 6).

**3. 본인 또는 선행 게이트가 신설·정정한 산출물을 검증 대상에서 제외하지 아니한다.**
신설 시트·덧붙임 블록·정정 부기도 표준 체계 대비 **「추가」로 전건 열거**하고,
**누가·언제·왜 신설했는지와 그 시트가 인용되는 위치**를 함께 기록한다.
- 자기가 만든 것은 눈에 띄지 않는다. **「내가 만들었으니 맞다」가 가장 흔한 누락 사유**다.
- 선행 게이트가 만든 `IAR_*`·`CG_*`·`CSR_*`·`WV_*` 계열 시트와 실무자 요청으로 신설한 근거 시트도
  같은 규율을 적용한다 — 존재를 보고하고, 원천과 인용 위치를 적는다.

⚠️ 실전 검출례(Case 003 Inbound 재설정) — 규율 3: 게이트 2가 회사 구 워크북에서 회수해 신설한
`Tap9-1` 시트가 표준 체계(Tap1~17)에 없는 추가 시트인데도 게이트 4 「시트 완비성」 보고에서 **누락**
되었다. 검토자 본인이 만든 시트였다. 사용자 질문으로 드러났다.

### 사안 종결 규율 3항 (전 게이트 공통)

「사안 착수 규율 3항」과 짝을 이룬다. 게이트는 **「워크북이 정합한가」**를 보고, 본 규율은
**「이 문서가 밖으로 나가도 되는가」**를 본다. 어느 게이트에서 사안이 끝나든 적용한다.

**1. 전달본(03 export)을 내부 판본에서 분리한다.**

전달본에서 **제거**한다
- ① 정정이력 시트 — 판본별 「정정 전 → 정정 후 → 근거」 기록 전부
- ② 게이트 산출 시트 (`IAR_`·`CG_`·`CSR_`·`WV_`·`PILOT_` 계열)
- ③ 산출 원본의 「보고서 대조」 시트 — 전달본과의 차이를 항목별로 정리한 표
- ④ 보고서 정정표 — 전달본의 오류를 열거한 문서
- ⑤ 내부 식별자 — 판본번호(vNN)·게이트 번호·Phase·발견번호(G-·C-·W-·G5-)
- ⑥ 「미검증」·「재검정」·「종전 기재가 틀렸다」·「~는 잔재였다」류 **경위 서술**
- ⑦ 02 결정기록의 「게이트」·「원 발견번호」 열

전달본에 **남긴다**
- 「정본 아님(이력)」 표시 — 종전 표가 물리적으로 남아 있으면 오독 방지에 필요하다
- 현재 상태의 지시(어느 블록이 정본인가) — 다만 판본·게이트 번호를 떼고 적는다

**기계 검사** — 전달본 생성 후 **전 파일**을 대상으로 아래 정규식을 돌려 **잔여 0건**이어야 한다.
```
게이트|Phase\s*[0-9]|\[v[0-9]|\b[GCW]-[0-9]{2}\b|G5-[0-9]{2}|정정이력|미검증|재검정|정정 전|종전 기재|보고서 대조
```

⚠️ **오류를 숨기는 것이 아니다.** 정정 결과는 재발행 문서 자체가 담고, 정정 경위는 회계법인이 보관한다.
회사 파일에 「무엇이 틀렸었는지」를 시계열로 남기지 아니한다. 전달본에 정정표를 넣지 않는 대신
**「갱신 예정 안내」**로 현재 상태를 알린다.
※ 「원본을 덮지 않는다」(정정은 원 시트를 덮지 않고 신설 시트·덧붙임 블록·새 버전으로 하며 원 시트는 이력으로
보존한다)는 원칙과 **충돌하지 아니한다.** 정정이력은 **만들되 내보내지 않는다** — 회계법인이 보관하고,
전달본에서만 분리한다.

**2. 잠정 항목과 회사 확인요청의 대응표를 인계한다.**
workbook-validator(-inbound) Phase 4 「잠정 항목 목록」의 각 행이 **어느 회사 확인요청 번호에 걸려 있는지**를
전달패키지 안내문에 적는다. 확인요청 회신 전에는 어느 잠정 항목도 확정 문언으로 바꾸지 않는다.

**3. 정본 기준선을 명문으로 고지한다.**
어느 파일·어느 시트·어느 블록이 정본인지를 전달본 안내문에 적는다. 판본·게이트 번호 없이,
「현재 상태의 지시」로만 적는다(위 1의 「남긴다」).

⚠️ 실전 검출례(Case 003 Inbound 재설정): 전달본 워크북에 `V6_정정이력` 시트(94셀)가 그대로 들어갔다.
ⓐ 전달 보고서의 근거가 자기모순이었다는 기록 ⓑ 정상가격범위 하한 여유가 좁아진 경위 ⓒ 법령 오인용 이력
ⓓ 확정되지 않은 불리한 잠재 쟁점이 한 화면에 시계열로 정리되어 있었다. **어느 게이트도 검출하지 않았고
사용자 지적으로 발견되었다.** 같은 유형이 산출 원본 `11_보고서대조` 시트·보고서 정정표·02의 「원 발견번호」
열·전 시트의 내부 식별자 141셀에 있었고, Case 002(호원) 전달패키지에도 동일 유형(워크북 67셀·02 15셀·
산출 원본·과정표 11셀)이 확인되었다.


- 오류를 발견해도 Claude가 워크북을 직접 수정하지 않는다 — 수정 주체는 실무자이며,
  본 스킬은 위치(시트·셀)·등급·권고안을 보고한다.
- 정상범위 방식(사분위 보간법, 다중연도 가중치)의 규범적 타당성 판단이 필요하면
  tp-case-law 스킬로 근거(**국조령 §15⑤·⑥**, TPG paras. 3.55~3.66)를 확인해 인용한다.
  **「국조령 §15의2」는 인용하지 않는다** — 존재하지 않는 가지조문이다(현행 §22).
- **조번호만 확인하고 통과시키지 않는다.** 조문 인용의 검증은 **표제까지** 대조해야 하며,
  구 번호도 현행법에 실재하되 다른 내용을 규정하므로 실재 확인만으로는 오류가 검출되지 않는다.
- 값 붙여넣기로 수식이 소실된 시트는 재현 한계를 보고서에 명시한다 (재현 불가 ≠ 오류).
- **외부 대조는 본 스킬의 범위에 포함된다.** 「검증이지 재분석이 아니다」는 원칙은 비교가능회사
  선정·특성분류 등 **판단**의 재수행을 금지하는 것이지, 법령 조문·산출 원본 등 **사실**의 대조를
  금지하는 것이 아니다. 워크북 내부 정합성만 보는 검증은 「내부적으로 일관된 오류」와
  **「내부적으로 일관된 미검증」**을 함께 통과시킨다 — Case 002에서 법령 오인용 12건과 PLI
  오전기가 모두 이 경로로 게이트를 통과하였다. 후자는 전 시트의 수치가 서로 맞는데
  **그 수치의 원천을 아무도 확인하지 않은** 상태를 말하며, **옮겨 적기는 언제나 정합하므로**
  내부 대조로는 원리상 검출되지 않는다. **미검증 항목이 정상범위·판정을 좌우하면 통과시키지
  않는다**(Phase 1 항목 8).
- 정상가격 산출 원본이 미제출된 상태의 "합격"은 **조건부 합격**이며, 그 취지(전기 대조 미실시)를
  검증 보고서와 progress.md에 명시한다. 원본 확보 후 Phase 2-0만 재실행한다.
- **대리 검증(T3)을 결함으로 취급하지 않는다.** 관할에 따라 원문이 공개되지 않는 것은 사실의
  문제이며, OECD TPG paras. 3.30~3.34가 그 제약을 인정한다. 본 스킬이 차단하는 것은 대리 자체가
  아니라 **① 확인 기록의 부재**와 **② 티어에 맞지 않는 확인**(확보 가능한데 대리로 갈음)이다.
  대리의 **충분성 판단**은 comparable-search-review §4-B.4 소관이며 본 스킬은 관여하지 않는다.
