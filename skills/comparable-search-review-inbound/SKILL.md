# Inbound 비교가능회사 검색 검토·자문 절차 (Comparable Search Review — Inbound)

## Phase 0 — 무결성 확인 (본론 착수 전 1회)

본 스킬은 검증 규율을 누적해 온 파일이며, 다른 TP 스킬과 서로를 지목하며 맞물려 동작한다.
경고문이 지워지거나 구버전이 섞이면 오류를 검출하는 대신 **주입**하게 되므로, 본론에 들어가기
전에 정본 여부를 먼저 확인한다.

**실행 방법 — 스킬 폴더를 탐색해서 이동한 뒤 실행한다.**

```bash
D=$(find ~ / -maxdepth 8 -type d -name "comparable-search-review-inbound" -path "*skills*" 2>/dev/null | head -1)
cd "$D" && python3 scripts/verify_skills.py
```

⚠️ **스킬이 안내하는 base directory 경로를 그대로 쓰지 말 것.** 그 경로는 Windows 형식
(`C:\Users\...`)인데 명령을 실행하는 셸은 **Linux 경로 체계**를 쓴다. 같은 폴더인데 이름이
달라 `No such file or directory`가 난다(실행 검증에서 실제로 확인한 오류다).
위 탐색 방식은 **경로 체계와 무관하게 동작**하며 약 1초 걸린다.

폴더 안에서 실행하면 **인자가 필요 없다.** 스크립트가 루트와 대상 스킬을 스스로 판별한다.

- **합격** — 그대로 진행한다. 별도로 보고하지 않는다.
- **변조·누락** — **작업을 중단하고 사용자에게 고지**한다. 어느 파일이 정본과 다른지 알린다.
  사용자가 진행을 지시하면 「무결성 미확인 상태」임을 답변에 명시하고 진행한다.
- **실행 불가**(경로·스크립트·매니페스트 없음) — 검증을 **생략하되 침묵하지 않는다.**
  한 줄로 「무결성 확인 미실행」을 알리고 진행한다.
- **`[미설치] tp-case-law`가 보이면** — 본 스킬이 조문·판례 검증을 tp-case-law에 맡기는
  부분은 실행되지 않는다. 해당 단계에서 그 사실을 고지하고, 조문 인용은 「확인 필요」로 표기한다.

⚠️ **이 절차는 변조를 막지 못한다. 드러나게 할 뿐이다.** 매니페스트(`scripts/MANIFEST.sha256`)가
함께 바뀌면 검증은 통과한다. 배포 시에는 매니페스트를 변경 이력이 남는 곳에도 보관하고 대조한다.

## 0. 기본 원칙

- **전제**: 사람(실무자)이 상용 DB(KIS-Line 등)에서 후보를 다운로드하고 검색전략을 수행한다. Claude는 국조법 제8조(정상가격의 산출방법)·국조령 제14조(정상가격 산출방법의 선택)·OECD TPG(2022) 제III장 수준에서 그 과정을 **검토·자문**하며, **최종 판단 권한은 항상 사람에게 있다**.
- **게이트 원칙**: 모든 Phase는 「검토 → 발견사항 보고 → 사용자 확정」을 거친다. 확정 사항은 `progress.md`에 기록한 후 다음 Phase로 진행한다.
- **구동 방식**: 채팅 지시어 "Phase N 실행"(예: "Phase 1A 실행", "Phase 3B 실행"). 순서는 0 → **0-B** → 1A → 1B → 1C → **1D** → 2 → 3 → **3B** → 4 → 5. 순서를 건너뛰려는 요청이 있으면 선행 게이트 미통과 사실을 고지하고 사용자 확인 후 진행한다.
- **규범 쟁점**: 법령·판례 해석이 필요하면 tp-case-law 스킬로 확인하고 출처(조문·문단 번호)와 함께 인용한다. **조문은 표제를 병기**한다(§10 참조).
- **연계**: tp-report-writer-inbound의 Step 6(제VII장 작성)은 본 절차 Phase 5 완료를 전제로 실행한다.
- **Inbound 사안 전제** (전 Phase 공통):
  ① Tested Party = 한국법인 단독이 통상 → **비교군 지역 = KR 고정**이 일반적
  ② 결정 인수 시트 = **Tap12(특성결정)·Tap16(방법선택)** (Tap14 없음)
  ③ Tap18이 없어 하류 무효화 범위는 **Tap15·17**로 한정
  ④ 검색이 **복수 트랙**(예: 상품중계업·서비스 제공업)으로 병렬 수행될 수 있다 — 트랙별로 워터폴을 각각 검증하고 최종 표본은 트랙 합산으로 평가한다.
  Outbound 사안(Tap14·18 존재)으로 판명되면 본 스킬을 중단하고 comparable-search-review로 전환한다.

### 0-1. 유료·로그인 자료원 접근 원칙 (전 Phase 공통 · 필수)

**Claude는 사용자 계정으로 로그인하지 않으며 아이디·비밀번호 등 자격증명을 입력하지 않는다.** 로그인이 필요한 자료원에 접근해야 하는 상황이 발생하면 **작업을 중단하고 사용자에게 질문 형식으로 고지**한다. 임의로 우회하거나, 미확인 상태로 조용히 진행하거나, 추정값으로 대체하지 않는다.

**대상 자료원 (예시)**: NiceBiz(나이스비즈인포) · **NiceValue** · KIS-Line · TS2000 · KISVALUE · 그 밖의 유료 기업정보·신용정보 서비스.

**고지 시점**: 해당 자료가 필요하다고 판단된 **즉시**. Phase 종료 시점까지 미루지 않는다. Phase 0에서 자료원 접근성을 일괄 점검하는 것이 원칙이나, 검토 도중에 필요성이 새로 발생하면 그 자리에서 고지한다.

**고지 문안 표준** — 아래 4요소를 반드시 포함하고 선택지를 제시한다.

```
[자료원 접근 확인 필요]
① 필요 자료 : {회사명} — {항목}  (예: 주식회사 OO — 최근 3개년 주주 구성 및 지분율)
② 사용 목적 : Phase {N} {검토항목} — 이 값이 없으면 {판정/게이트}를 확정할 수 없음
③ 대체 가능성 : {DART 등 무료 소스로 대체 가능 여부와 그 한계}
④ 선택지
   (a) 직접 조회 후 값 전달 — 사용자가 NiceBiz/NiceValue에서 조회하여 수치를 알려준다
   (b) 무료 대체 소스로 우회 — DART 감사보고서·기업개황 등으로 확인 (권장, 가능한 경우)
   (c) 미확인 처리 — 해당 항목을 확인 불가로 기록하고 검토 한계를 조서에 명시한 뒤 진행
```

**무료 대체를 먼저 검토한다.** 외부감사 대상 법인의 재무제표·주석·지배구조·특수관계자 거래는 대부분 **DART 감사보고서 원문으로 대체 가능**하다(Phase 3B 참조). 상용 DB가 아니면 얻을 수 없는 항목(신용등급, 비외감 소기업 재무, 산업 통계, 대량 스크리닝)에 한하여 (a)를 요청한다.

**선택지 (c)를 택한 경우**: 미확인 항목·사유·영향 범위를 검토조서와 방어 패키지에 반드시 기록한다. 그 항목이 사분위 형성 회사에 관한 것이면 Phase 4 민감도 분석에 「해당 회사 제외」 시나리오를 추가한다.

### 0-2. DB 필드는 증거가 아니다 (Phase 3B의 존재 이유)

상용 DB(KIS-Line 등)의 재무·특수관계 필드는 **결측이 공란 또는 0으로 표시되며 그 구분이 없다**. 필터는 그 값을 그대로 참으로 취급하므로, **DB 필드만으로 판정한 표본은 검증된 표본이 아니다**. 실전에서 다음 두 유형이 모두 발생했다.

- **거짓 통과** — 특수관계거래 필드가 공란이어서 독립성 기준(≤20%)을 통과했으나, 감사보고서 주석 확인 결과 **매출의 100%가 특수관계자 거래**였던 사안. 이 회사는 하사분위를 형성하고 있었고, 제외 시 분석대상법인의 실현치가 정상범위를 이탈했다.
- **거짓 의심** — 매출채권·재고자산 필드가 공란이어서 「결측 아니냐」는 의심을 받았으나, 감사보고서 확인 결과 **계정 자체가 없는 실제 미보유**였던 사안. 다만 같은 확인 과정에서 그 회사가 **자산의 91%가 지분법투자인 실질 지주회사**임이 드러났다.

두 경우 모두 DB 필드·주요상품 필드만 보아서는 검출되지 않는다. **감사보고서 원문 확인이 유일한 검출 경로다.**

### 0-2-1. 필드별 정본(正本) 기준표

§0-2의 원칙은 「모든 필드를 원문으로 검증하라」는 뜻이 아니다. 필드군별로 정본 소스를 아래와 같이 확정하고, 정본이 아닌 소스는 참고치로만 취급한다. 상용 DB(KISVALUE 등)를 정식 계약으로 사용하는 것을 전제로 한다.

| 필드군 | 해당 단계(예시) | 정본 | 정본 외 소스의 지위 |
|---|---|---|---|
| 모집단·스크리닝 필드 — KSIC, 시장구분, 매출규모, 상품매출 비중, R&D·광고비, 재고비중 등 | Step 1~5·7 | **상용 DB** | DART 원문은 검증·보완용 |
| 감사의견 | Step 2 | **상용 DB 허용** | 원문 표제부와 상충 시 원문 우선. **적정 외 의견(한정·부적정·의견거절) 표시가 있거나 감사인 변경 이력이 있는 회사는 원문 표제부를 확인**한다 — DB 누락 시 부적격 회사가 표본에 잔존한다 |
| 독립성 — 특수관계 매출·매입 비중 | Step 6 | **DART 감사보고서 주석** | DB 필드는 참고치. **판정 근거로 사용 금지** (§0-2 실전례) |
| 정성 판정 — 주된 영업활동·기능 실체 | Step 9 / Phase 3 | **원문(주석 1 회사의 개요) + 공개정보** | DB 주요상품 필드는 참고치 |
| **최종 선정사의 PLI 산출 재무수치** — 매출액·매출원가·판관비·영업손익, 운전자본 조정 계정 | Phase 3B 항목 7 / profitability-analysis | **DART 감사보고서 원문** | DB 수치는 원문 대조 후에만 확정 |
| 최신 연도 보완 — DB 미반영 결산연도 | 전 단계 | **DART 원문** | DB 반영 시차 구간은 원문이 유일 소스 |

**운용 원칙**:
1. 정본과 참고치가 상충하면 **정본을 따르고 상충 사실·수치를 조서에 기록**한다.
2. 스크리닝 필드라도 Phase 3B에서 이상 징후(자릿수 이상치, 동종 상위기업 간 서열 모순, 결측 의혹)가 발견되면 **해당 회사·필드에 한하여 원문 우선으로 전환**하고 전환 사유를 기록한다(1D ②ⓐ 연동).
3. 과정표·보고서 제VII장에는 **필드군별 정본 소스**를 명시한다(예: 「Step 2~5·7: KISVALUE {버전·추출일} / Step 6·9: DART 감사보고서 주석」). 검색 과정표 헤더 주석에 재판정 사실을 기재하는 현행 방식을 표준으로 한다(§4-B.5 산출물 규격 참조).

### 0-3. 제작 라인과 검토 라인 (중요)

TP 업무의 스킬은 성격이 다른 두 라인으로 나뉜다. 본 스킬은 **검토 라인**에 속한다.

```
[제작 라인] 워크북 작성 → comparable-search-strategy(검색전략 수립) → 실무자 DB 검색 실행 → Tap15 기재
[검토 라인] industry-analysis-review-inbound → characterization-gate-inbound
            → comparable-search-review-inbound → workbook-validator-inbound
            → tp-report-writer-inbound
                     └ Phase 1D 반송 판정 시에만 제작 라인으로 되돌린다
```

**comparable-search-strategy를 검토 라인의 고정 단계로 실행하지 않는다.** 이미 수행된 검색을 대상으로 사후에 검색전략을 재수립하면 산출물의 소비처가 없다. 표본을 다시 만들지 여부는 **본 스킬 Phase 1D에서만 판정**하고, 반송이 결정된 경우에 한하여 제작 라인의 전략 스킬을 호출한다.

## 1. Phase 0 — 입력물 인수 기준

검토 착수 전 아래 5종을 점검한다. **미비하면 검토를 개시하지 않고** 부족 항목을 보고한다(TPG para. 3.46 투명성·재현가능성). 아울러 **Engagement Type이 Inbound인지 확정**한다 — Header 표기가 실제와 반대인 실전 사례가 있으므로 거래 방향으로 확인한다.

1. **검색 원본 xlsx** — 필터 수식 또는 단계별 Y/N 판정과 원천 재무데이터가 보존된 상태.
2. **DB 추출조건 기록** — DB명·버전, 추출일자, 검색조건(KSIC, 외감 여부, 재무연도 범위), 추출 시점 모집단 수. **복수 트랙 사안은 트랙별로 각각** 기록.
3. **검색전략 문서**(Tap15 또는 표 VII-3 초안) + Tested Party의 기능·위험 프로파일 요약(FAR).
4. **전기 보고서의 비교가능회사 목록**(연속성 검토용).
5. **정상가격 산출 원본** — 선정된 비교가능회사의 PLI·사분위·운전자본 조정을 산출한 파일. 검색 원본과 **별도 파일인 경우가 많다**.
   ⚠️ 원본이 복수 PLI를 병렬 산출하면 **채택 행을 라벨·산식까지 특정**하고, 파일 내부에 `(2)`·`복사본`·`최종` 등으로 분기한 **중복 시트가 있으면 정본을 사용자에게 확정**받는다. Summary·요약 시트가 아니라 **계산식이 살아 있는 산출 시트를 정본으로 삼는다** — 실전에서 정정본 Summary에도 행 참조 오류가 남아 있었다.

|---|---|---|

| OpenDART API | 무료·인증키 필요 | 대량 조회 시 사용. 사용자가 키를 보유했는지 질문 |

## 1-B. Phase 0-B — Tested Party 근거 검토

Phase 0이 「자료가 있는가」(형식 점검)라면, 0-B는 「**Tested Party 결정 논리가 성립하는가**」(실질 검토)다. Tested Party가 잘못 식별되면 1A 입력부터 1C 검토 방향까지 연쇄로 틀어지므로 **1A 착수 전 필수 게이트**다.

Inbound는 한국법인(제한적 기능·위험)이 더 단순한 당사자로서 Tested Party가 되는 것이 통상이며 비교군 지역 = KR이다. 다만 이 역시 **논거 성립을 확인**하는 것이지 기계적으로 전제하지 않는다. **characterization-gate-inbound의 「Tested Party 결정 논거 요약표」가 있으면 인수·인용만 하고 재작성하지 않는다.**

**검토 방식 — 목적 지향 추출** (전수 정독 금지): FAR 요약 시트(Tap9)를 1차 소스로 읽고, 상세 시트는 요약과의 모순 검증용으로만 스캔한다.

| 검토 목적 | 대상 시트(예시) | 추출 항목 |
|---|---|---|
| 구조 파악 | Tap1-1 지분구조 | 특수관계 성립 경로, 지배구조 |
| 거래 식별 | Tap3 특수관계분석, Tap3-1 제3자거래분석, Tap3-2 재무분석 | 거래별 양 당사자·규모, **내부 비교대상 존재 여부(Y/N)** |
| 기능 심도 | Tap5 생산공정, Tap6 연구개발, Tap8·8-1 인터뷰 | 판매지원·중개 기능의 범위, R&D·마케팅 수행 여부 |
| FAR 판정 | Tap9 FAR분석 종합 (Scale 0~5) | 당사자별 기능·위험 Scale → 단순(한국법인) vs 복잡(HQ/Principal) 판정 |
| 결정 인수 | **Tap12(특성결정 §5) + Tap16(방법선택)** | Tested Party·방법·PLI 확정값 |

**산출물 — 「Tested Party 결정 논거 요약표」**: 분석대상 거래 → 양 당사자 기능 프로파일 → 선택된 Tested Party와 근거(TPG paras. 3.18~3.19) → PLI → **비교군 지역(KR)** → FAR상 통제 방향(R&D·광고비 상한 등 검색 필터 시사점).

게이트: 결정 논거 요약표 확정(또는 선행 게이트 요약표 인수) + 내부 비교대상 Y/N 기록.

## 2. Phase 1 — 삼각검증 (1A 선례 + 1B 산업분석 + 1C 규범)

구조: 규범(1C)이 정점, 1A·1B는 **증거 수집만** 수행한다. 판단은 1C에서만 하며, 1C는 1A·1B 산출물을 인용만 하고 재검토하지 않는다.

### 2.1 Phase 1A — 선례 지식DB 사전검토

**Step 1 — 입력 수집** (Phase 0-B 요약표가 있으면 자동 공급):
① 산업(취급 제품 산업 + 기능 산업) ② 거래유형 표준코드 — `MFG` `DIST` `MFG-DIST` `DIST-SVC` `SVC` `SVC-MKT` `SVC-TECH` `R&D` `AGENT` `IP-ROY` `MIXED` (Inbound 판매지원 전형: `SVC-MKT`·`AGENT`·`DIST`) ③ 지역(통상 `KR`) ④ 현행 검색전략(트랙별) ⑤ **자기참조 확인** — 현행 프로젝트가 DB에 등재되어 있으면 매칭에서 제외하고 그 사실을 기록.

**Step 2 — 표준 SQL 실행** (sqlite3로 그대로 실행, 산업어 치환만 허용):

```sql
-- Q1. 세션 매칭
SELECT id, file_name, year, industry, industry_master, trade_type_std, region_std,
       tested_party, selected_method, final_comp_count, industry_codes_all, industry_ksic
FROM search_sessions
WHERE record_status = 'OK'
  AND (industry LIKE '%{산업어}%' OR industry_master LIKE '%{산업어}%')
  AND trade_type_std = '{거래유형코드}'
  AND region_std = '{지역코드}'
ORDER BY year DESC;

-- Q2. 매칭 세션의 검색단계
SELECT session_id, step_no, step_type, search_method, search_criteria, search_purpose
FROM search_steps
WHERE session_id IN ({매칭 세션 ID 목록})
  AND step_type != 'X-JUNK' AND record_status = 'OK'
ORDER BY session_id, step_no;

-- Q3. 제외사유·선정 현황
SELECT session_id, selected_yn, rejection_stage, rejection_reason, COUNT(*) AS n
FROM comparables
WHERE session_id IN ({매칭 세션 ID 목록})
GROUP BY session_id, selected_yn, rejection_stage, rejection_reason;
```

> **Inbound 매칭 유의**: 지식DB가 Outbound 중심이면 `SVC-MKT`·`AGENT` 매칭이 3건 미만일 수 있다. 이 경우 **지역 조건 완화보다 거래유형 인접 코드(`SVC`·`DIST-SVC`) 확장을 우선**한다 — 지역을 완화하면 비교군 지역(KR) 전제와 충돌한다. 매칭 부족 자체를 제한사항에 기록한다(선례 부재는 이탈이 아니다).

**Step 3 — 선례대조표 작성** (7개 섹션): ① 매칭요약 ② 단계설계대조 ③ 임계치벤치마크 ④ KSIC코드이력(세대 포섭관계 확인 필수) ⑤ 제외사유·선정 ⑥ 검토메모(이탈 항목 → **1C 안건 이관** 필수) ⑦ 제한사항 및 재현 근거.

> **고정 문구**: 본 선례대조표는 AI(Claude)가 선례 지식DB를 의미 기반으로 매칭하여 작성한 것으로, 매칭 판단에 재량이 개입되어 실행 시점·세션에 따라 매칭 범위가 달라질 수 있다. 이를 보완하기 위해 (a) 실행한 SQL 쿼리 전문, (b) 매칭 채택·배제 판단 근거, (c) 지식DB 버전을 본 대조표에 기록하며, 동 기록에 따라 동일 결과의 재현이 가능하다. 본 대조표는 검토 보조자료이며 최종 판단은 실무자가 수행한다.

게이트: 대조표 생성 + 자기참조 제외 확인 + 이탈 항목 1C 이관 완료.

### 2.2 Phase 1B — 산업분석 연계 검토 (Additive Approach)

1. **후보 리스트 작성** — Inbound 판매지원 사안은 취급 제품 산업의 경쟁사가 아니라 **기능 관점의 동종회사**(수입상품 중개·판매지원·사무지원·시장조사)를 후보 기준으로 삼는다.
2. **교차검증(핵심)** — 후보들이 모집단에 포착되었는지 확인. 미포착이면 KSIC 정의가 협소하다는 신호. 포착 후 중간 탈락했다면 탈락 사유 개별 점검.
3. **경계 사례 이관** — 판단이 갈리는 회사는 Phase 3 목록으로 이관.

※ 내부 비교가능거래 검토의 VI장 연계는 **보류** 상태다(§8 참조). case별 존재 여부(Y/N)와 판단 경위를 Phase 0-B에 수동 기록한다.

게이트: 후보 리스트 + 모집단 교차검증 완료, 경계 사례 Phase 3 이관.

### 2.4 Phase 1D — 재검색 실행여부 판정 (Phase 1 종결 게이트)

**판정은 재량이 아니라 요건 충족 여부로 한다.**

| 판정 | 발동 요건 (하나라도 충족) | 조치 |
|---|---|---|

| **③ 불요** | 위 요건 전부 미해당 | 현행 표본 확정, Phase 2 진행 |

**Phase 3B가 미실행 상태에서는 1D를 「③ 불요」로 확정할 수 없다.** 3B 결과에 따라 ②ⓕ가 발동할 수 있으므로, 1D는 **잠정 판정**으로 두고 3B 종료 후 확정한다.

게이트: 3단계 판정(요건 번호 명시), ① 판정 시 반송 통지·하류 무효화 범위 고지, ② 판정 시 보완 대상 목록 확정.

## 3. Phase 2 — 수식·데이터 정합성 검증

**복수 트랙 사안은 트랙별로 각각 수행한다.**

0. **PLI 원본 대조** — 정상가격 산출 원본에서 **채택 PLI 행을 라벨·산식까지 특정**하고, 비교가능회사별 값·사분위·분석대상 실현치가 그 행에서 전기되었는지 **전건 대조**. 재현되지 않으면 각 후보 행과 기간 조합(3개년/5개년, 연도별/합계)을 순회 대조하여 실제 산출 기준을 역으로 식별한다. 함께 확인할 것 — ① 분석대상과 비교대상이 **동일 지표**에서 산출되었는지 ② 정상범위와 실현치가 **서로 다른 시나리오·시트**에서 인용되지 않았는지 ③ 원가기반 가감의 사유.
1. **기준 대조** — 표 VII-3 서술 vs 실제 판정: 임계치, 비교 연산자, 대상 연도 범위.
2. **분모·분자 정의** — Berry Ratio 사안의 OE 정의(판관비 단독 vs 판관비+기타)의 트랙 간·회사 간 통일.
3. **논리 구조** — AND/OR 논리 오류.
4. **미기재 필터** — 워크북에 있으나 보고서 표에 없는 필터의 적용 여부·미기재 사유.
5. **워터폴 재계산** — 모집단부터 최종까지 단계별 잔여 수를 독립 재현(트랙별 + 합산).
   ⚠️ **워터폴은 단계별 Y 개수가 아니라 누적 통과로 계산한다.** 검색 과정표는 각 단계 판정을 독립적으로 기재하므로 단순 카운트는 기재값과 어긋난다(실전에서 어느 단계의 단순 Y가 43, 누적 잔여가 24였다). 「직전 단계 통과자 중 당해 단계 Y」로 순차 계산할 것.
6. **데이터 품질** — 결측치 처리 원칙, 감사보고서 주석 데이터의 신뢰성, **동일 회사 중복 등재**(실전 검출례: 모집단 43사 중 1사 중복 → 실질 42사), 탈락 회사에 후행 단계 판정이 부여된 표기 혼선.

발견된 불일치는 **각각 사용자가 택일 확정**: ① 수식·판정을 서술에 맞게 수정 ② 서술을 실제에 맞게 수정 ③ 의도된 것이므로 논거 보강.

게이트: 불일치 전건 확정, 워터폴 재현 일치(트랙별).

## 4. Phase 3 — 정성 판단의 객관화

정성적 제외(사업구조 확인)는 과세당국이 가장 먼저 공격하는 지점(TPG para. 3.44).

**회사별 판단 매트릭스**: 회사명 | 확인 자료원 | 제외 사유(유형 코드화: R-FUNC 기능 상이 / R-PROD 제품·사업 비교불가 등) | 판단자 | Claude 교차확인 결과.
Inbound 판매지원 사안의 핵심: **가격결정권 미보유·위험 부담 수준·보상 구조**가 Tested Party와 유사한지.

**양방향 일관성 테스트**: ① 제외된 회사가 실제로 비교불능인지 ② 잔존 회사 중 동일 논리로 제외되었어야 할 회사가 없는지 ③ (복수 트랙) 동일 회사가 트랙 간 상이한 기준으로 판정되지 않았는지.

판단이 갈리는 회사는 **경계 사례(borderline)** 로 표기하고 Phase 4에서 정량화한다.

게이트: 매트릭스 완성, 양방향 테스트 통과.

## 4-B. Phase 3B — 감사보고서 원문 정밀 검토 (필수)

DB 필드로 통과·탈락한 판정을 **감사보고서 원문으로 검증**한다. Phase 3이 「사업 내용이 유사한가」라면, 3B는 「**DB 필드가 사실인가, 그리고 그 회사가 정말 비교가능한가**」다.

### 4-B.1 검토 대상 — 3군

| 군 | 대상 | 사유 |
|---|---|---|
| **A. 사분위 형성 회사 (필수·전건)** | 최종 표본 중 Q1·중앙값·Q3를 형성하는 회사. n=7이면 통상 4~5개사 | 이 회사들의 값이 정상범위를 직접 결정한다. **1사만 빠져도 판정이 뒤집힐 수 있다** |
| **B. 최종 표본 잔여 회사 (필수)** | A군 외 최종 선정 회사 전부 | 표본 전체가 방어 대상이므로 예외를 두지 않는다 |
| **C. 축출된 잠재적 비교가능회사 (필수·선별)** | ① 최종 단계(정성·주요산업)에서 탈락한 회사 ② 기능·제품이 Tested Party와 가장 가까운데 재무 필터에서 탈락한 회사 ③ **DB 필드 결측·공란을 이유로 탈락한 회사** | 부당 탈락은 현행 표본만 보아서는 검출되지 않는다. 표본 보완이 필요해질 때 후보 풀이 된다 |

C군 선별 기준: 최종 단계 탈락자 전건 + 그 직전 단계 탈락자 중 **기능 근접성 상위 5사 내외**. 모집단 전체를 검토하지 않는다.

### 4-B.2 조회 소스와 접근 방법

**우선순위: ① DART(무료) → ② OpenDART API(무료·인증키) → ③ 유료 DB(§0-1 고지 후)**

**① DART 전자공시 (dart.fss.or.kr) — 1차 소스, 로그인 불요**
외부감사 대상 법인은 감사보고서가 전량 공시되며 무료다. 상용 DB의 2차 가공 데이터보다 우선한다.
- 절차: `기업개황`에서 회사 식별(동명이인 다수 — **영문명·법인등록번호·주소·업종명 중 2개 이상으로 특정**) → `제출보고서검색` → 감사보고서 → 문서목차에서 재무상태표·손익계산서·주석 열람.
- 뷰어는 `https://dart.fss.or.kr/dsaf001/main.do?rcpNo={접수번호}` 로 직접 접근할 수 있다. 검색 결과에서 링크의 `rcpNo`를 추출해 이동하면 팝업 차단을 피할 수 있다.
- 뷰어 우상단 검색창에 `특수관계자`, `회사의 개요` 등을 입력하면 해당 주석으로 바로 이동한다.
- ⚠️ **정정공시 확인**: 제출보고서 목록에 보고서명 앞 `[기재정정]` 접두가 있으면 감사보고서가 재제출된 것이다. **최신 접수번호(rcpNo)를 정본으로 채택**하고, 정정 전 rcpNo로 이미 작성된 조서·과정표가 있으면 갱신한 뒤 정정 사실(정정 전·후 rcpNo, 정정 일자, 영향 항목)을 조서에 기록한다.

**② OpenDART API (opendart.fss.or.kr) — 대량 조회용, 무료 인증키 필요**
C군까지 확대해 수십 개사를 훑을 때 사용한다. 사용 전 **사용자가 인증키를 보유했는지 질문**한다(§0-1 준용).
- `corpCode.xml` 고유번호 → `company.json` 기업개황(법인등록번호·업종) → `list.json` 공시검색(감사보고서 접수번호) → **`document.xml` 공시서류원본파일**(접수번호만으로 원문 ZIP 다운로드).
- `list.json` 결과에 동일 보고서의 정정 제출 건이 있으면 **접수일자가 가장 늦은 접수번호를 채택**한다(정정 여부는 보고서명 `[기재정정]` 접두로 판별). 조서에는 채택한 rcpNo와 함께 정정 이력 유무를 기록한다.
- ⚠️ **정기보고서 재무정보 API(`fnlttSinglAcnt` 등)는 사용할 수 없다.** 대상이 「상장법인 + 사업보고서 제출대상 주요 비상장법인」으로 한정되는데, 통상의 비교가능회사는 **외감법인(기타법인)**으로 감사보고서만 제출하므로 조회되지 않는다. **원문 XML을 파싱해야 한다.**

**③ 유료 DB (NiceBiz · NiceValue · KIS-Line 등) — 로그인 필요**
DART로 얻을 수 없는 항목(신용등급, 비외감 소기업 재무, 산업 통계, 대량 스크리닝)에 한하여 사용한다. **접근이 필요하다고 판단되면 §0-1의 고지 문안으로 사용자에게 질문하고 답을 받은 뒤 진행한다.** Claude가 직접 로그인하지 않는다.

### 4-B.3 확인 항목 7종

각 회사에 대해 다음을 확인하고 표로 고정한다.

1. **회사의 개요(주석 1)** — 설립 경위, 지배구조(최상위 지배기업·지분율), 주된 영업활동. ⚠️ **분할 설립된 그룹 내부 기능 자회사**인지 확인 — Tested Party와 구조가 같으면 비교가능성이 높지만, 독립성 요건은 위배할 수 있다.
2. **특수관계자와의 거래(주석)** — 특수관계자별 영업수익·영업비용. **특수관계 매출 ÷ 총매출을 직접 계산**하여 독립성 기준(통상 ≤20%)과 대조한다. **DB 필드가 공란·0이어도 반드시 계산할 것** — 실전에서 필드가 비어 통과한 회사의 실제 비중이 100%였다.
3. **재무상태표 계정 구성** — 매출채권·재고자산·매입채무의 **계정 존재 여부**. 계정이 아예 없으면 실제 미보유이고, 계정이 있는데 DB가 공란이면 결측이다. 이 구분이 운전자본 조정의 전제를 결정한다.
4. **자산 구성** — 지분법적용투자주식·투자부동산 등이 총자산의 과반을 차지하면 **영업회사가 아니라 지주·투자회사**다. 영업 지표(Berry Ratio 등)가 계산되더라도 기능 프로파일이 다르다.
5. **손익 구조** — 영업손익과 영업외손익의 관계. **영업손실을 영업외수익(지분법이익 등)으로 메우는 구조**이면 저수익의 원인이 「비교가능한 영업 실적」이 아니다.
6. **판관비 구성·인력 규모** — 급여 비중과 계정 수. 판매지원 기능 수행 실체가 확인되는지.
7. **PLI 구성 계정의 원문 대조 (A·B군 전건 · C군 생략 가능)** — 채택 PLI의 분자·분모를 구성하는 계정(매출액·매출원가·판매비와관리비·영업손익, 운전자본 조정 적용 시 매출채권·재고자산·매입채무의 연도말 잔액)을 **감사보고서 원문 값과 전건 대조**한다.
   - 직전연도 값은 당기 감사보고서의 **전기 비교표시 금액**으로 확인할 수 있다(profitability-analysis의 표기 규칙과 동일 — 별도 연도 보고서 조회를 줄인다).
   - 불일치 발견 시: §0-2-1에 따라 **원문을 정본으로 확정**하고, 그 수치 변경이 사분위·범위 판정에 미치는 영향을 즉시 산정한다. 판정이 변동하면 1D ②ⓐ 발동, 산출 원본·Tap17이 이미 작성된 상태이면 workbook-validator-inbound 재실행 필요를 사용자에게 고지한다.
   - 항목 3(계정 존재 확인)과의 관계: 항목 3은 존재 여부, 항목 7은 **금액 일치**를 본다. 항목 3에서 「실제 미보유」로 확인된 계정은 항목 7 대조에서 0으로 취급한다.

### 4-B.4 판정과 이관

| 결과 | 처리 |
|---|---|
| 검색기준 위반 확인 (예: 특수관계 매출 >20%) | **Phase 1D ②ⓕ 발동** — 해당 회사 제외 후 사분위 재계산, 표본 보완 필요 여부 판단 |
| **PLI 구성 계정 수치 불일치 (항목 7)** | 원문을 정본으로 확정(§0-2-1), 사분위·범위 판정 영향 즉시 산정. 판정 변동 시 **1D ②ⓐ 발동** + 산출 원본·Tap17 기작성 시 workbook-validator-inbound 재실행 고지 |
| 기능 프로파일 상이 확인 (지주회사·이종 기능 등) | Phase 3 경계 사례로 등급 상향, Phase 4에서 포함·제외 영향 정량화, **존치 시 서면 논거 필수** |
| DB 결측 의혹 해소 (실제 미보유 확인) | 기록 후 통과 — 다만 **같은 확인 과정에서 드러난 다른 사실을 반드시 함께 평가**할 것 |
| 자료 접근 불가 (유료 DB 필요·사용자가 (c) 선택) | 미확인 항목·사유·영향 범위를 조서에 기록하고, 해당 회사 제외 시나리오를 Phase 4 민감도에 추가 |
| C군에서 유력 후보 발견 | 표본 보완 후보로 등재, Phase 4 민감도에 편입 시나리오 추가 |

**확인 결과는 반드시 「그래서 비교가능한가」로 이어져야 한다.** 데이터 검증(3번 항목)에서 「결측 아님」이 확인되었다고 검토를 종료하지 않는다 — 실전에서 결측 의혹은 해소되었으나 같은 문서에서 훨씬 중대한 사실(지주회사 실체)이 드러났다.

### 4-B.5 산출물 규격 — 검색 과정표에의 반영

Phase 3B의 재판정 결과는 조서(방어 패키지 8)에만 남기지 않고 **검색 과정표 자체에 반영**한다. 세무조사 시 과정표 단독으로 판정 근거에 즉답할 수 있어야 한다.

1. **재판정 근거 열 추가** — 원문 재판정이 개입한 Step(통상 Step 6·9, §4-B.3 항목 7 대조 포함)에는 과정표 우측에 「재판정 근거」 열을 추가하고 회사별로 다음을 기재한다: `rcpNo(최신·정정 반영) / 주석 번호 또는 항목 / 재판정일`.
   예: `20260315000123 / 주석 28 특수관계자거래 / 2026-08-03`

## 5. Phase 4 — 결과의 경제적 타당성 검토

3. **범위 검토** — Tested Party 실현 PLI의 범위 내 여부, **하사분위·상사분위와의 여유 폭**. 여유가 좁으면(예: 0.03 미만) 그 사실과 함의를 명시적으로 보고한다.

## 10. 경계 (중요)

- 본 스킬은 검색 과정의 **검토**이지 검색 대행이 아니다. 표본을 다시 만드는 것은 Phase 1D 판정 후 제작 라인의 소관이다.
- **Claude는 유료·회원제 자료원에 로그인하지 않고 자격증명을 입력하지 않는다.** 접근이 필요하면 §0-1의 고지 문안으로 사용자에게 질문한다 — 임의 우회·추정 대체·무언의 생략을 금지한다.
- Phase 3B에서 감사보고서를 확인하되, **재무수치를 임의로 대체하지 않는다** — 발견사항으로 보고하고 사용자 확정 후 반영한다.
- 회사 식별 시 동명이인에 주의한다. 영문명·법인등록번호·주소·업종명 중 최소 2개로 특정하고, 특정 근거를 조서에 기록한다.
- DART 조회 결과는 접수번호(rcpNo)·기수·감사인을 함께 기록하여 재현 가능하게 하고, **정정본이 있으면 최신본 기준임을 명시**한다.
- 국내 조문 인용(국조법·국조령·국조칙 조번호)은 **tp-case-law로 실재·적합 여부를 확인한 뒤** 사용하고, **반드시 표제를 병기**한다(예: 「국조법 §8(정상가격의 산출방법)」). 2020.12.22. 전부개정(법률 제17651호, 2021.1.1. 시행)으로 번호 체계가 전면 교체되었으며, **구 번호도 현행법에 실재하되 다른 내용을 규정**하므로 조번호 실재 확인만으로는 오류가 검출되지 않는다. 「~의2」 가지조문(예: 국조령 §15의2)은 특히 주의한다.
- **법령이 정하지 않은 임계치를 법령 근거로 서술하지 않는다.** 특수관계 비중 20%, 상품매출 비중, R&D 상한, **사분위 산정방식·보간법**, 최종 표본 6개 미만 기준 등은 **국조법령에 규정이 확인되지 않는 실무 관행**이다. 관행임을 명시하고 채택 사유를 조서에 기록한다. ※ **비교대상 「둘 이상」은 관행이 아니라 법령 요건**이다 — 국조령 §15⑤(정상가격 산출방법의 적용)이 「둘 이상의 거래를 토대로 정상가격 범위를 산정」하도록 정하며, 범위 자체의 근거도 §15⑤·⑥이다.
