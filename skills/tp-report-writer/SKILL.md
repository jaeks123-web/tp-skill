# 이전가격 보고서 단계별 작성 (TP Report Writer)

## Phase 0 — 무결성 확인 (본론 착수 전 1회)

본 스킬은 검증 규율을 누적해 온 파일이며, 다른 TP 스킬과 서로를 지목하며 맞물려 동작한다.
경고문이 지워지거나 구버전이 섞이면 오류를 검출하는 대신 **주입**하게 되므로, 본론에 들어가기
전에 정본 여부를 먼저 확인한다.

**실행 방법 — 스킬 폴더를 탐색해서 이동한 뒤 실행한다.**

```bash
D=$(find ~ / -maxdepth 8 -type d -name "tp-report-writer" -path "*skills*" 2>/dev/null | head -1)
cd "$D" && python3 scripts/verify_skills.py
```

⚠️ **스킬이 안내하는 base directory 경로를 그대로 쓰지 말 것.** 그 경로는 Windows 형식
(`C:\Users\...`)인데 명령을 실행하는 셸은 **Linux 경로 체계**를 쓴다. 같은 폴더인데 이름이
달라 `No such file or directory`가 난다(실행 검증에서 실제로 확인한 오류다).
위 탐색 방식은 **경로 체계와 무관하게 동작**하며 약 1초 걸린다.

폴더 안에서 실행하면 **인자가 필요 없다.** 스크립트가 루트와 대상 스킬을 스스로 판별한다.

- **합격** — 그대로 진행한다. 별도로 보고하지 않는다.
- **변조·누락** — **작업을 중단하고 사용자에게 고지**한다. 어느 파일이 정본과 다른지 알린다.
  사용자가 진행을 지시하면 「무결성 미확인 상태」임을 답변에 명시하고 진행한다.
- **실행 불가**(경로·스크립트·매니페스트 없음) — 검증을 **생략하되 침묵하지 않는다.**
  한 줄로 「무결성 확인 미실행」을 알리고 진행한다.

⚠️ **이 절차는 변조를 막지 못한다. 드러나게 할 뿐이다.** 매니페스트(`scripts/MANIFEST.sha256`)가
함께 바뀌면 검증은 통과한다. 배포 시에는 매니페스트를 변경 이력이 남는 곳에도 보관하고 대조한다.

TP 분석 워크북을 유일한 데이터 소스로 삼아 보고서를 **단원 단위로 작성 → 사용자 검토 → 최종 병합**한다.
한 번에 전체를 생성하지 않는 이유: 단원별 품질 게이트 확보, 수정 시 해당 단원만 재작성, 컨텍스트 한계 회피.

## 입력·출력

| 구분 | 내용 |
|---|---|
| 입력 1 (필수) | TP 분석 워크북 .xlsx — Tap1(법인), Tap3(거래), Tap4(산업), Tap5~9(공정·R&D·조직·인터뷰·FAR), Tap12(가치사슬), Tap14~18(평가방법·검색·방법선택·산출결과·정책) |
| 입력 2 (권장) | 전기 보고서 .docx — 문체·표 서식의 스타일 레퍼런스 |
| 입력 3 (권장) | 표준문구 샘플 .docx — 방법론 이론·법령 인용 보일러플레이트 |
| 산출 (중간) | 작업폴더/sections/01_개요.docx ~ 09_사용료_결론.docx |
| 산출 (최종) | 이전가격보고서_회사명_과세연도_초안.docx |
| 관리 | progress.md — 단계 상태·확정 규칙·질의 이력. 세션이 끊겨도 이 파일로 재개 |

작업폴더는 사용자가 연결한 폴더 하위에 `프로젝트코드_보고서작성/` 형태로 생성한다.

## 표준 목차 (10개 장)

```
I.   개요 (목적·범위 / 거래현황 / 절차·구성 / 분석결과 요약)   ← 맨 마지막에 작성
II.  모회사(국내법인) 분석 (회사개요·사업부 기능·취급제품·특수관계·거래개요)
III. 산업분석 (국내 산업 + 현지국 경제환경 + 산업요소 평가)
IV.  해외관계회사 기능분석  ← 법인별 반복: 개요/DEMPE/기능/위험/자산/특성분류
V.   정상가격 산출방법 (이론 보일러플레이트: 정상가격원칙·비교가능성·5방법·PLI 5종)
VI.  가장 합리적인 방법의 선택  ← 평가단위별: 채택·배제 논거(국조법 §8①각호·OECD TPG 인용)
VII. 비교가능회사 검색  ← Tested Party별: DB/검색단계/결과 목록
VIII.정상가격 산출(경제적 분석)  ← 평가단위별: 사분위·조정·분석결과
IX.  사용료 거래의 정상가격 분석 (해당 시)
X.   결론 및 이전가격 정책 (결론 종합·운영원칙·사후관리·문서화 점검표)
```

법인·평가단위가 늘어나도 목차는 불변 — 반복 모듈만 늘린다.

## 실행 단계 (Step 0~11)

각 Step은 "작성 → 검증 보고 → 사용자 승인" 게이트를 거친 후 다음으로 진행한다.
사용자는 "Step N 실행"이라고만 지시하면 된다.

| Step | 단원 | 주 데이터 소스 시트 |
|---|---|---|
| 0 | 준비: 워크북 검증, 법인·평가단위 확정, progress.md 생성 | 전체 시트 스캔 |
| 1 | V. 방법론 이론 (데이터 무관 — 먼저 확정해 이후 인용) | 표준문구 샘플 |
| 2 | II. 모회사 분석 | Tap1, 1-1, 1-2, 2, 3, 3-3, 5, 6, 7 |
| 3 | III. 산업분석 | Tap4, 4-1, 4-2 |
| 4~5 | IV. 기능분석 — 법인별 (S1, S2, …) | Tap5, 7, 8, 9, 9-1/9-2/9-3, 12 |
| 6 | VI. 방법 선택 | Tap14, 16 |
| 7 | VII. 비교가능회사 검색 | Tap15 (+Tap17 비교거래 목록) |
| 8 | VIII. 경제적 분석 | **Tap18 Section 3** (아래 '데이터 우선순위' 참조) |
| 9 | IX. 사용료 + X. 결론·정책 | Tap18 전체 |
| 10 | I. 개요 — 본문 확정 후 요약 (수치 불일치 원천 차단 목적) | 본문 산출물 |
| 11 | 병합·표지·목차·부록목록·최종검증 | sections/ 전체 |

작성 순서 원칙: **이론(불변) → 사실관계 → 분석 → 결론 → 요약(개요)**.

### Step 0에서 반드시 확인할 것 (실전에서 발견된 함정)

워크북은 여러 도구가 채운 시트의 집합이라 표기 체계가 어긋나 있을 수 있다. 착수 전 대조하고,
상충이 있으면 **작성하지 말고 사용자에게 확정을 요청**한다:

1. **거래코드 체계**: Tap3/14의 `G1_TRE_00n`과 Tap16 서술의 `TR00n`이 다른 번호를 가리킬 수 있다
   (예: TR004=TRE_005). 대응표를 사용자에게 확인받고 보고서는 TRE_00n으로 통일한다.
2. **평가단위 vs 법인코드 충돌**: 법인코드 G1((주)호원)과 평가단위 G1이 중복 사용될 수 있다. 단일 체계 확정.
3. **거래 방향**: 사용료 거래는 기술제공방향과 대가지급방향이 시트마다 반대로 기재될 수 있다.
   서술 기준(기술제공방향 권장)을 확정하고, 본문에서는 "A가 기술 제공, B가 사용료 지급"처럼 양방향을 명시해 모호성을 없앤다.
4. **데이터 우선순위 — Tap17 vs Tap18**: 두 시트의 정상범위·실현치가 다를 수 있다.
   **판정(정상/이탈)까지 포함하고 전기 보고서와 일치하는 Tap18 Section 3이 원칙적 기준**이나,
   결론이 달라지는 중대한 상충이므로 반드시 사용자에게 표로 비교 제시 후 확정받는다.
5. **PLI 명칭**: Tap16(영업이익/총원가)과 Tap17 헤더(영업이익률 OM)가 상충할 수 있다. Tap18 표기를 따른다.
6. **법령 인용의 실재성** (v1.1 신설): 워크북의 조문 인용을 **그대로 전기하지 말 것**. 국가법령정보센터
   현행 조문과 대조하여 ⓐ 조번호가 실재하는지 ⓑ 조문 제목이 인용 취지와 맞는지 ⓒ 2021년 전부개정
   (법률 제17651호) 전후의 구 번호가 섞여 있지 않은지 확인한다.
   ⚠️ 실전 검출례: 「국조령 §15의2(정상가격 범위)」— **존재하지 않는 조문**(제15조 다음이 제16조).
   「국조령 §6(거래 통합)」— 제6조는 실제로 **재판매가격방법**이며 거래 통합은 §15②.
   문서화 근거를 「국조법 §11-2」로 기재 — 2021년 전부개정 전 번호이며 현행은 **제16조**.
   이 3유형이 characterization-gate·comparable-search-review·workbook-validator 3개 게이트를
   모두 통과하였다. 어느 게이트도 조문을 실제 법령과 대조하지 않기 때문이다.
7. **마스터 시트 우선순위** (v1.1 신설): 같은 사실이 복수 시트에 기재된 경우 **어느 시트가 마스터인지**를
   Step 0에서 확정한다. 지분율은 Tap1-1, 거래 배정은 Tap14, 산업 조정점수는 IAR 확정표가 마스터다.
   ⚠️ 실전 검출례: Tap1-2 관계도가 「100% 자회사」로 기재했으나 마스터인 Tap1-1은 82.63%·50.96%였다.
8. **평가단위 수 = 검색 섹션 수** (v1.1 신설): Tap14의 평가단위 개수와 Tap15의 검색 섹션 개수를 대조한다.
   ⚠️ 실전 검출례: 평가단위는 3개(S1·G1·T1)인데 Tap15에는 §1·§2만 있어 **T1 검색과정이 통째로 누락**되어
   있었다. 데이터는 산출 원본에 온전히 존재하였으므로, 누락은 워크북의 구조적 공백이지 자료 부재가 아니다.

9. **02 결정기록·전기 대조표·잠정 목록의 인수** (v1.2 신설): 사안 폴더에 `02_결정기록*.xlsx`가 있으면
   Step 0에서 함께 읽는다. 「채택」 행은 재판단하지 않고 인수하고, **「제외」·「미결」 항목을 확정 사실처럼
   인용하지 않는다** — 미결은 본문에 「잠정」으로 표기하고 회사 확인요청 번호를 병기한다.
   workbook-validator **Phase 0-α의 01→03 전기 대조표**와 **Phase 4의 잠정 항목 목록**도 함께 인수한다.
10. **거래 개요 금액의 기준** (v1.2 신설): 제II장 거래 개요 표의 금액은 **거래별 원천 기준**으로 적고,
   감사보고서의 **상대방별 총액**은 「대조」 문장으로 병기한다(예: 「거래별 합계 ○○원 — 감사보고서 주석의
   상대방별 총액 △△원과의 차액 □□원은 …로 확인 중」).
   ⚠️ 실전 검출례: 주석의 상대방별 총액이 **거래 행으로 승격**되어 워크북 전체에 퍼졌고, 전 시트가 같은
   값을 옮겨 적었기 때문에 게이트 5종이 모두 통과시켰다. 보고서가 그 값을 그대로 전기하면 회사가
   제시한 거래별 자료와 맞지 않는다.

### v1.2 신설 규격 — 사용료 서술·판정 방향·거래상대방 재무·rev 관리

**1. 사용료(Step 9)는 3단으로 서술한다.**
「① 계약 요율(계약서 원문) → ② 실제 수취·지급액(장부) → ③ 실효율(잠정 여부)」의 순서로 적는다.
- **역산값을 기재하지 않는다.** 「금액 ÷ 그 금액이 목표 비율이 되는 매출」로 만든 요율은 근거가 아니다.
- 계약상 **산정기준 매출**을 확인할 수 없으면 총매출 대비 **실효율을 「잠정」으로 표기**하고 회사
  확인요청 번호를 병기한다.
- 계약 요율과 실효율이 다르면 그 차이를 **설명**하되, 어느 쪽도 다른 쪽에 맞추어 조정하지 않는다.
- 비교거래 요율표(DB)의 요율은 **비교 대상**이지 실현치가 아니다. 같은 표에 섞어 적지 않는다.

**2. 판정 문장에는 방향을 적는다(Step 8·10).**
「범위 내/밖」만으로 결론을 끝내지 않는다. **누구의 이익이 어느 쪽으로 벗어났고 그것이 국내 소득에
어떤 의미인지**를 한 문장으로 적는다.
- 검증대상이 **국외**법인이고 **하회** → 「국내 소득 과소계상 아님 → 조정 불요」
- 공급자인 **국내**법인이 **상회** → 동일(조정 불요)
- 검증대상이 **국내**법인이고 **하회** → 「조정 검토」

**3. 거래상대방의 재무 현황을 제II장에 둔다.**
검증대상이 아닌 국외특수관계인도 **재무 요약 표**를 둔다(회계기준·통화·결산월 병기). 비교 판단의
전제가 본문에 없으면 독자가 판정을 검증할 수 없다.

**4. 개정판(rev)은 스크립트로 생성한다.**
`make_revN.py` 형태로 **정정 위치를 문단·표 인덱스로 남겨** 재현·검토가 가능하게 한다. 표를 새로
삽입하면 **이후 표 인덱스가 밀리므로** 그 사실을 스크립트 주석에 남긴다. Step 11 정규식 잔존 검사

## 공통 작성 규칙

1. **사실 창작 금지**: 매핑된 시트에 없는 내용이 필요하면 중단하고 질의. 자료 미비 항목은
   회색 이탤릭 placeholder(`[○○ 자료 수취 후 보완 예정 — 사유]`)로 표시하고 progress.md에 기록.
2. **수치 그대로 전기**: 재무수치는 원본 값·단위(천원, EUR 등) 그대로. 비율은 소수점 2자리 %.
   임의 환산·자체 계산 금지(워크북 기계산 값만 사용).
2-1. **「워크북에 없으면 없는 것」으로 처리하지 말 것** (v1.1 신설): 워크북은 산출 원본을 요약한 2차
   자료이며 누락이 발생한다. 단원 집필 시 해당 단원의 산출 원본을 **함께 열어 대조**하고, 워크북에
   없으나 원본에 있는 항목은 워크북에 보완한 후 전기한다. 특히 **평가단위별로 원본 파일이 다른 경우**
   (S1·G1·T1이 각기 다른 산출 원본을 가지는 등) 전 평가단위에 대해 빠짐없이 수행한다.
3. **문체**: 스타일 레퍼런스의 경어체(~습니다)·서술 밀도를 따른다. 법인 약칭은 최초 정의 후 통일.
   원본의 명백한 오탈자는 문맥으로 정정하되 검증 보고에 명시.
4. **내부 참조 정리**: 시트 셀에 남은 내부 도구 참조("Tap8: IP기능 0.19", "ABC Tool" 등)는
   보고서 문체("제IV장 기능분석 참조")로 변환한다.
5. **단원 자체검증 후 보고**: 생성 직후 (a) 원본 수치 대조 (b) 목차·표 번호 연속성 (c) 코드/용어
   통일(정규식으로 구 코드 잔존 검사)을 수행하고 결과와 질의 목록을 채팅으로 보고한다.
