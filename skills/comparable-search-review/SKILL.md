# 비교가능회사 검색 검토·자문 절차 (Comparable Search Review)

## Phase 0 — 무결성 확인 (본론 착수 전 1회)

본 스킬은 검증 규율을 누적해 온 파일이며, 다른 TP 스킬과 서로를 지목하며 맞물려 동작한다.
경고문이 지워지거나 구버전이 섞이면 오류를 검출하는 대신 **주입**하게 되므로, 본론에 들어가기
전에 정본 여부를 먼저 확인한다.

**실행 방법 — 스킬 폴더를 탐색해서 이동한 뒤 실행한다.**

```bash
D=$(find ~ / -maxdepth 8 -type d -name "comparable-search-review" -path "*skills*" 2>/dev/null | head -1)
cd "$D" && python3 scripts/verify_skills.py
```

⚠️ **스킬이 안내하는 base directory 경로를 그대로 쓰지 말 것.** 그 경로는 Windows 형식
(`C:\Users\...`)인데 명령을 실행하는 셸은 **Linux 경로 체계**를 쓴다. 같은 폴더인데 이름이
달라 `No such file or directory`가 난다(실행 검증에서 실제로 확인한 오류다).
위 탐색 방식은 **경로 체계와 무관하게 동작**하며 약 1초 걸린다.

폴더 안에서 실행하면 **인자가 필요 없다.** 스크립트가 루트와 대상 스킬을 스스로 판별한다.

- **합격** — 그대로 진행한다. 별도로 보고하지 않는다.
- **변조·누락** — **작업을 중단하고 사용자에게 고지**한다. 어느 파일이 정본과 다른지 알린다.
  사용자가 진행을 지시하면 「무결성 미확인 상태」임을 답변에 명시하고 진행한다.
- **실행 불가**(경로·스크립트·매니페스트 없음) — 검증을 **생략하되 침묵하지 않는다.**
  한 줄로 「무결성 확인 미실행」을 알리고 진행한다.
- **`[미설치] tp-case-law`가 보이면** — 본 스킬이 조문·판례 검증을 tp-case-law에 맡기는
  부분은 실행되지 않는다. 해당 단계에서 그 사실을 고지하고, 조문 인용은 「확인 필요」로 표기한다.

⚠️ **이 절차는 변조를 막지 못한다. 드러나게 할 뿐이다.** 매니페스트(`scripts/MANIFEST.sha256`)가
함께 바뀌면 검증은 통과한다. 배포 시에는 매니페스트를 변경 이력이 남는 곳에도 보관하고 대조한다.

## 0. 기본 원칙

- **전제**: 사람(실무자)이 상용 DB에서 후보를 다운로드하고 검색전략을 수행한다. Claude는 국조법 제8조(정상가격의 산출방법)·국조령 제14조(정상가격 산출방법의 선택)·OECD TPG(2022) 제III장 수준에서 그 과정을 **검토·자문**하며, **최종 판단 권한은 항상 사람에게 있다**.
- **게이트 원칙**: 모든 Phase는 「검토 → 발견사항 보고 → 사용자 확정」을 거친다. 확정 사항은 `progress.md`에 기록한 후 다음 Phase로 진행한다.
- **구동 방식**: 채팅 지시어 "Phase N 실행"(예: "Phase 1A 실행", "Phase 3B 실행"). 순서는 0 → **0-B** → 1A → 1B → 1C → **1D** → 2 → 3 → **3B** → 4 → 5. 순서를 건너뛰려는 요청이 있으면 선행 게이트 미통과 사실을 고지하고 사용자 확인 후 진행한다.
- **규범 쟁점**: 법령·판례 해석이 필요하면 tp-case-law 스킬로 확인하고 출처(조문·문단 번호)와 함께 인용한다. **조문은 표제를 병기**한다(§10 참조).
- **연계**: tp-report-writer의 Step 7(제VII장 작성)은 본 절차 Phase 5 완료를 전제로 실행한다.

### 0-1. 유료·로그인 자료원 접근 원칙 (전 Phase 공통 · 필수)

**Claude는 사용자 계정으로 로그인하지 않으며 아이디·비밀번호 등 자격증명을 입력하지 않는다.** 로그인이 필요한 자료원에 접근해야 하는 상황이 발생하면 **작업을 중단하고 사용자에게 질문 형식으로 고지**한다. 임의로 우회하거나, 미확인 상태로 조용히 진행하거나, 추정값으로 대체하지 않는다.

**대상 자료원 (예시)**: Orbis / TP Catalyst (Moody's·구 Bureau van Dijk) · Compustat · S&P Capital IQ · RoyaltyStat · ktMINE · **NiceBiz · NiceValue** · KIS-Line · TS2000 · 그 밖의 유료 기업정보·신용정보 서비스.

**고지 시점**: 해당 자료가 필요하다고 판단된 **즉시**. Phase 종료 시점까지 미루지 않는다.

**고지 문안 표준** — 아래 4요소를 반드시 포함하고 선택지를 제시한다.

```
[자료원 접근 확인 필요]
① 필요 자료 : {회사명/관할} — {항목}  (예: XX GmbH(독일) — 주주 구성 및 BvD Independence Indicator)
② 사용 목적 : Phase {N} {검토항목} — 이 값이 없으면 {판정/게이트}를 확정할 수 없음
③ 대체 가능성 : {공적 등기소·거래소 공시 등 무료 소스로 대체 가능 여부와 그 한계}
④ 선택지
   (a) 직접 조회 후 값 전달 — 사용자가 Orbis/NiceBiz 등에서 조회하여 수치를 알려준다
   (b) 무료 대체 소스로 우회 — 관할별 공적 등기소·거래소 공시 등 (권장, 가능한 경우)
   (c) 미확인 처리 — 해당 항목을 확인 불가로 기록하고 검토 한계를 조서에 명시한 뒤 진행
```

**무료 대체를 먼저 검토한다.** 다만 Outbound 사안의 비교가능회사는 대부분 외국법인이므로, 한국의 DART처럼 전량 무료 공시되는 체계를 기대할 수 없다. 관할별 확보 가능성은 Phase 3B의 티어 표를 참조한다.

**선택지 (c)를 택한 경우**: 미확인 항목·사유·영향 범위를 검토조서와 방어 패키지에 반드시 기록한다. 그 항목이 사분위 형성 회사에 관한 것이면 Phase 4 민감도 분석에 「해당 회사 제외」 시나리오를 추가한다.

### 0-1-1. 데이터 반출과 크레딧 — 화면 조회와 내보내기는 다르다

유료 DB는 **조회는 정액이나 반출은 건별 과금**인 경우가 있다. 사용자의 크레딧을 소모시키는
동작을 게이트가 임의로 실행하지 않는다.

**실행 금지(사용자 확인 없이는 클릭하지 않는다)**

| DB | 경로 |
|---|---|
| TP Catalyst / Orbis | 상단 **`Excel`** · `Actions > Companies > **Export companies**` · `BvD ID numbers` |
| 그 밖의 DB | 「내보내기」·「다운로드」·「보고서 생성」 계열 버튼 전반 |

**차감 없이 가능한 것(2026-08 실측)** — 열 구성 변경(`Add/remove columns`) · 뷰 관리 ·
화면 표시와 페이지 이동 · **뷰 정의의 Export**(열 구성만 내보내며 회사 데이터가 아니다).
⚠️ 계약 조건은 화면으로 확인되지 않는다. 단정하지 말고 필요하면 `Manage account`·`Contact us`로
사용자가 확인하도록 안내한다.

**서식 고정 권고** — 같은 열 구성을 반복해 쓰려면 DB의 **View 기능**(TP Catalyst: `Manage views`
→ `Create new` / `Set as default` / `Share` / `Export`)으로 표준 뷰를 만들고, **Export한 뷰 정의를
사안 폴더에 보관**한다. 케이스가 바뀌어도 취득 서식이 흔들리지 않는다.

**머리글에 필드코드 표시** — `Settings > Display options > Show the field codes in the column headers`를
켠 상태로 취득한다. 라벨만으로는 계정 계열을 구분할 수 없고, 실제로 라벨과 내용이 어긋난 열이
확인됐다.

### 0-2. DB 필드는 증거가 아니다

상용 DB의 재무·특수관계 필드를 그대로 참으로 취급한 표본은 **검증된 표본이 아니다**. DB별로 실패 양상이 다르므로 대응도 달라야 한다.

| DB 유형 | 실패 양상 | 대응 |
|---|---|---|
| **국내 DB (KIS-Line 등)** | **결측과 0을 구분하지 않는다.** 공란이 0으로 해석되어 필터를 통과한다. 실전 검출례: 특수관계거래 필드가 공란이어서 독립성 기준(≤20%)을 통과했으나 실제는 **매출의 100%가 특수관계자 거래**였고, 그 회사가 하사분위를 형성하고 있어 제외 시 실현치가 정상범위를 이탈했다 | 감사보고서 주석 원문으로 직접 계산 (Phase 3B Tier 1) |
| **Orbis 등 해외 DB** | **결측을 `n.a.`로 명시하므로 0과 혼동되지는 않는다.** 대신 ① **필드 자체가 없는 항목**이 있고(특수관계 거래액이 대표적) ② n.a.가 많은 필터는 **실질적으로 작동하지 않는다** | 대리 지표로 갈음하고 그 사실을 명시 (Phase 3B Tier 3) + 필터별 n.a. 비율 검사 (Phase 2-7) |

두 경우 모두 **DB 필드만 보아서는 검출되지 않는다**는 점은 같다.

**필드별 정본 기준** — 비교군 지역이 한국인 사안(모회사 Tested Party 등, §1-B 호원 G1 유형)은 **comparable-search-review-inbound §0-2-1 「필드별 정본 기준표」를 준용**한다(스크리닝 필드 = 상용 DB 정본 / 독립성·정성·최종 선정사 PLI 재무 = DART 원문 정본). 해외 관할 사안은 원문 확보 가능성이 티어별로 다르므로 필드별 정본을 일률 확정하지 않고, §4-B.2 티어 판별 결과에 따라 T1·T2는 원문, T3는 대리 지표를 정본 대체로 삼되 그 사실을 명시한다(§4-B.4).

### 0-3. 제작 라인과 검토 라인 (중요)

TP 업무의 스킬은 성격이 다른 두 라인으로 나뉜다. 본 스킬은 **검토 라인**에 속한다.

```
[제작 라인] 워크북 작성 → comparable-search-strategy(검색전략 수립) → 실무자 DB 검색 실행 → Tap15 기재
[검토 라인] industry-analysis-review → characterization-gate → comparable-search-review
            → workbook-validator → tp-report-writer
                     └ Phase 1D 반송 판정 시에만 제작 라인으로 되돌린다
```

**comparable-search-strategy를 검토 라인의 고정 단계로 실행하지 않는다.** 이미 수행된 검색을 대상으로 사후에 검색전략을 재수립하면 산출물의 소비처가 없다. 표본을 다시 만들지 여부는 **본 스킬 Phase 1D에서만 판정**하고, 반송이 결정된 경우에 한하여 제작 라인의 전략 스킬을 호출한다.

> 실전 근거 — Case 002(호원): 검토 라인에서 전략 스킬을 실행하였으나 결론은 "실행 결과는 내용만 인지하고 Tap15는 현재 상태로 유지"였다. 정작 표본을 바꾼 것(단위 오류 검출 → YEPSAN 편입, 11→12개사)은 본 스킬 Phase 1B였다.

## 1. Phase 0 — 입력물 인수 기준

검토 착수 전 아래 5종을 점검한다. **미비하면 검토를 개시하지 않고** 부족 항목을 보고한다(TPG para. 3.46).

1. **검색 원본 xlsx** — 필터 수식이 보존된 상태(값 붙여넣기 금지).
2. **DB 추출조건 기록** — DB명·버전(Orbis는 **디스크/업데이트 버전**과 추출일이 결과를 좌우하므로 반드시 기록), 추출일자, 검색조건(NACE/SIC/KSIC, 지역, 상장 여부, 재무연도 범위, Independence Indicator 조건), 추출 시점 모집단 수.

   **2-1. 검색정의 export 파일이 제공되는 DB는 그 파일을 정본 첨부물로 인수한다.** 손으로 옮겨 적은 조건표는 전기(轉記) 오류에 노출되며, 기계 판독도 되지 않는다.

   | DB | 파일 | 담긴 정보 |
   |---|---|---|
   | **TP Catalyst / Orbis** | **`.tpbm`** (zip 안 `XMLData`) | `DBVersion` · `DBDate` · `Date`(실행일시) · `Analyst` · `Currency` · `Unit` · `AccountType` · `ConsType` · `Year`/`NofYear` · **`InterQuartileCalcMethod`** · 검색 단계별 파라미터 전문 |
   | 그 밖의 DB | 검색 조건 저장·내보내기 기능이 있으면 동일하게 인수 | — |

   ⚠️ **URL 경로의 버전 표기보다 파일 안의 값을 우선한다.** 실측(2026-08-26): URL은 `202606-1`, 파일은 `DBVersion 195 / DBDate 20260630`.
   ⚠️ **파일의 헤더 값과 실제 열 선택이 어긋날 수 있다.** 실측: 헤더는 `OsirisDataFormatType="Global"`인데 추출된 재무 열은 개별 선택 결과였다. 헤더는 **분석 설정**이고 열 계열은 **열마다 따로** 정해진다 — 조서에 둘을 구분해 적는다.
   ⚠️ `Year`/`NofYear`와 실제 추출 연도가 다를 수 있다. 실측: `Year=2025 NofYear=3`인데 열은 2022~2024.

   본 파일에서 `0_DB추출조건` 시트(또는 조서의 추출조건표)를 **자동 생성**할 수 있다. 자동 생성한 경우 그 사실과 생성일을 시트에 적는다.

   **2-A. 필터 정의 2요소 — 없으면 재현되지 않는다.**

   조건의 문구가 같아도 아래 두 가지가 정해지지 않으면 결과가 갈린다. 과정표·조서에 **반드시 명문화**하고, 기재가 없으면 Phase 1에서 재현 불가로 처리한다.

   | 요소 | 정의해야 할 것 | 미정의 시 |
   |---|---|---|
   | **① 지분 기준의 주주 범위** | 「상위주주 지분 N% 미만」이 **법인주주만**인지 개인 포함인지 | 실측: 법인만 28사 ↔ 개인 포함 4사 — **7배** |

## 2. Phase 1 — 삼각검증 (1A 선례 + 1B 산업분석 + 1C 규범)

규범(1C)이 정점, 1A·1B는 **증거 수집만** 수행한다.

### 2.1 Phase 1A — 선례 지식DB 사전검토

**Step 1 — 입력 수집**: ① 산업 ② 거래유형 표준코드 — `MFG` `DIST` `MFG-DIST` `DIST-SVC` `SVC` `SVC-MKT` `SVC-TECH` `R&D` `AGENT` `IP-ROY` `MIXED` ③ 지역 — `KR` `ASIA` `NA` `EU` `GLOBAL` `OVERSEAS` ④ 현행 검색전략 ⑤ **자기참조 확인**.

**Step 2 — 표준 SQL 실행** (sqlite3로 그대로 실행, 산업어 치환만 허용):

```sql
-- Q1. 세션 매칭
SELECT id, file_name, year, industry, industry_master, trade_type_std, region_std,
       tested_party, selected_method, final_comp_count, industry_codes_all, industry_ksic
FROM search_sessions
WHERE record_status = 'OK'
  AND (industry LIKE '%{산업어}%' OR industry_master LIKE '%{산업어}%')
  AND trade_type_std = '{거래유형코드}'
  AND region_std = '{지역코드}'
ORDER BY year DESC;

-- Q2. 매칭 세션의 검색단계
SELECT session_id, step_no, step_type, search_method, search_criteria, search_purpose
FROM search_steps
WHERE session_id IN ({매칭 세션 ID 목록})
  AND step_type != 'X-JUNK' AND record_status = 'OK'
ORDER BY session_id, step_no;

-- Q3. 제외사유·선정 현황
SELECT session_id, selected_yn, rejection_stage, rejection_reason, COUNT(*) AS n
FROM comparables
WHERE session_id IN ({매칭 세션 ID 목록})
GROUP BY session_id, selected_yn, rejection_stage, rejection_reason;
```

매칭 완화는 ①정확·부분 일치 → ②의미 기반 유사 산업어 → ③산업대분류 순서로 진행하고, **어느 단계에서 매칭됐는지와 채택·배제 근거를 대조표에 명기**한다.

**Step 3 — 선례대조표 작성** (7개 섹션): ① 매칭요약 ② 단계설계대조 ③ 임계치벤치마크(**Independence Indicator 등급 조합 포함**) ④ 산업코드이력(NACE·SIC·KSIC 세대 포섭관계 확인 필수) ⑤ 제외사유·선정 ⑥ 검토메모(이탈 항목 → **1C 이관** 필수) ⑦ 제한사항 및 재현 근거.

> **고정 문구**: 본 선례대조표는 AI(Claude)가 선례 지식DB를 의미 기반으로 매칭하여 작성한 것으로, 매칭 판단에 재량이 개입되어 실행 시점·세션에 따라 매칭 범위가 달라질 수 있다. 이를 보완하기 위해 (a) 실행한 SQL 쿼리 전문, (b) 매칭 채택·배제 판단 근거, (c) 지식DB 버전을 본 대조표에 기록하며, 동 기록에 따라 동일 결과의 재현이 가능하다. 본 대조표는 검토 보조자료이며 최종 판단은 실무자가 수행한다.

게이트: 대조표 생성 + 자기참조 제외 확인 + 이탈 항목 1C 이관 완료.

### 2.2 Phase 1B — 산업분석 연계 검토 (Additive Approach)

1. **후보 리스트 작성** — 산업분석의 경쟁사·밸류체인 참여자·산업협회 회원사에서 후보군 추출(웹서치 병행).
2. **교차검증(핵심)** — 후보들이 모집단에 포착되었는지 확인. 명백한 경쟁사가 모집단에 없으면 산업코드 정의가 협소하다는 신호. 포착 후 중간 탈락했다면 탈락 사유 개별 점검.
3. **경계 사례 이관** — 판단이 갈리는 회사는 Phase 3 목록으로 이관.

※ 내부 비교가능거래 검토의 VI장 연계는 **보류** 상태다(§8). case별 Y/N과 판단 경위를 Phase 0-B에 수동 기록한다.

게이트: 후보 리스트 + 모집단 교차검증 완료, 경계 사례 Phase 3 이관.

## 3. Phase 2 — 수식·데이터 정합성 검증

검증 항목 8종:

0. **PLI 원본 대조** — 정상가격 산출 원본에서 **채택 PLI 행을 라벨·산식까지 특정**하고, 비교가능회사별 값·사분위·분석대상 실현치가 그 행에서 전기되었는지 **전건 대조**. 재현되지 않으면 각 후보 행과 기간 조합을 순회 대조하여 실제 산출 기준을 역으로 식별한다. 함께 확인할 것 — ① 분석대상과 비교대상이 **동일 지표**에서 산출되었는지 ② 정상범위와 실현치가 **서로 다른 시나리오·시트**에서 인용되지 않았는지 ③ 원가기반 가감의 사유.
1. **기준 대조** — 표 VII-3 서술 vs 수식: 임계치, 비교 연산자, 대상 연도 범위.
2. **분모·분자 정의** — 비율 산식의 분모 일치 여부. **연결(C1/C2)과 별도(U1/U2) 재무제표가 회사 간 혼재하지 않는지** 확인.
3. **논리 구조** — AND/OR 논리 오류.
4. **미기재 필터** — 워크북에 있으나 보고서 표에 없는 필터의 적용 여부·미기재 사유.
5. **워터폴 재계산** — 모집단부터 최종까지 단계별 잔여 수를 독립 재현.
   ⚠️ **워터폴은 단계별 통과 표시 개수가 아니라 누적 통과로 계산한다.** 검색 과정표가 각 단계 판정을 독립적으로 기재하는 형식이면 단순 카운트는 기재값과 어긋난다(실전에서 어느 단계의 단순 통과 표시가 43, 누적 잔여가 24였다). 「직전 단계 통과자 중 당해 단계 통과」로 순차 계산할 것.
6. **데이터 품질** — 결측치 처리 원칙, **동일 회사 중복 등재**(실전 검출례: 모집단 43사 중 1사 중복 → 실질 42사), 탈락 회사에 후행 단계 판정이 부여된 표기 혼선, 통화 단위 혼재(해외 사안은 EUR/USD/현지통화 혼재가 흔하다).
7. **필터별 결측(n.a.) 비율 산정 (해외 DB 사안 필수)** — 각 필터에 사용된 필드의 n.a. 비율을 단계별로 계산한다.
   **문제의 구조**: 필터는 **값이 있는 회사만 거른다.** n.a.인 회사는 통상 「검증 없이 통과」로 처리되므로, n.a. 비율이 높으면 **그 통제는 이름만 있고 모집단의 일부에만 적용된 것**이다. 예: 모집단 200사 중 R&D 필드가 140사(70%)에서 n.a.이면, 「R&D 상한 통제」는 나머지 60사에만 적용되었고 워터폴에는 그 사실이 드러나지 않는다.
   **왜 문제인가**: 보고서는 「R&D 1% 초과 기업을 제외하여 무형자산 보유 기업을 통제하였다」고 서술하는데, 최종 표본의 어느 회사를 지목해 「이 회사의 R&D는 확인하였는가」를 물으면 답할 수 없다.
   **조치**: 비율과 그 함의를 조서에 기록하고, **30%를 넘으면 해당 통제의 방어력 판단을 Phase 1C로 환송**한다(이는 계산 오류가 아니라 「이 통제가 규범적으로 충분한가」라는 판단 문제이기 때문이다). 1C의 선택지는 ⓐ n.a. 기업 배제(보수적이나 표본 축소) ⓑ 다른 통제로 보완(무형자산 계정 잔액·특허 보유·사업설명 텍스트 등) ⓒ 현행 유지 + **보고서에 미검증 비율 명시**.
   ※ 30%는 실무 기준이며 법령·TPG상 근거는 없다. 사무소 관행에 따라 조정 가능하되, 채택한 값을 조서에 기록한다.

발견된 불일치는 **각각 사용자가 택일 확정**: ① 수식을 서술에 맞게 수정 ② 서술을 수식에 맞게 수정 ③ 의도된 것이므로 논거 보강.

게이트: 불일치 전건 확정, 워터폴 재현 일치, **필터별 n.a. 비율표 완성**.

## 4. Phase 3 — 정성 판단의 객관화

정성적 제외는 과세당국이 가장 먼저 공격하는 지점(TPG para. 3.44).

**회사별 판단 매트릭스**: 회사명 | 확인 자료원 | 제외 사유(유형 코드화: R-FUNC 기능 상이 / R-PROD 제품·사업 비교불가 등) | 판단자 | Claude 교차확인 결과.

**양방향 일관성 테스트**: ① 제외된 회사가 실제로 비교불능인지 ② 잔존 회사 중 동일 논리로 제외되었어야 할 회사가 없는지.

판단이 갈리는 회사는 **경계 사례(borderline)** 로 표기하고 Phase 4에서 정량화한다.

게이트: 매트릭스 완성, 양방향 테스트 통과.

## 4-B. Phase 3B — 비교가능회사 실체 검증 (필수)

DB 필드로 통과·탈락한 판정을 **1차 자료로 검증**한다. Phase 3이 「사업 내용이 유사한가」라면, 3B는 「**DB 필드가 사실인가, 그리고 그 회사가 정말 비교가능한가**」다.

> ⚠️ **Inbound 절차와의 결정적 차이**: 한국 사안(comparable-search-review-inbound)은 외감법인 감사보고서가 DART에 전량 무료 공시되어 **주석까지 원문 확인이 가능**하다. 반면 **Orbis는 표준화 재무데이터를 제공할 뿐 감사보고서 원문(특히 주석)을 제공하지 않으며**, 특수관계 거래액 필드 자체가 없다. 따라서 Inbound의 3B를 그대로 이식할 수 없고, **관할별 티어 + 대리 지표 검증**으로 재설계한다.

### 4-B.1 검토 대상 — 3군

| 군 | 대상 | 사유 |
|---|---|---|
| **A. 사분위 형성 회사 (필수·전건)** | 최종 표본 중 Q1·중앙값·Q3를 형성하는 회사 | 이 회사들의 값이 정상범위를 직접 결정한다. **1사만 빠져도 판정이 뒤집힐 수 있다** |
| **B. 최종 표본 잔여 회사 (필수)** | A군 외 최종 선정 회사 전부 | 표본 전체가 방어 대상 |
| **C. 축출된 잠재적 비교가능회사 (필수·선별)** | ① 최종(정성) 단계 탈락자 ② 기능·제품이 Tested Party와 가장 가까운데 재무 필터에서 탈락한 회사 ③ **결측(n.a.)을 이유로 탈락한 회사** | 부당 탈락은 현행 표본만 보아서는 검출되지 않는다. 표본 보완 시 후보 풀이 된다 |

C군 선별 기준: 최종 단계 탈락자 전건 + 직전 단계 탈락자 중 **기능 근접성 상위 5사 내외**.

### 4-B.2 관할별 원본 확보 티어

**착수 전 반드시 티어를 판별한다.**

**판별로 끝내지 않고 판정 근거를 남긴다.** 근거 없는 티어는 우회로가 된다 — 확보 가능한 관할인데 T3로 분류하면 대리 지표로 갈음할 수 있기 때문이다. 회사별로 `티어 / 티어 판정 근거`를 검색 과정표에 기재한다(§4-B.6).

판정 근거는 **「해당 관할·법인 유형에서 어떤 문서가 공개되는가」**로 적는다.

- 좋은 예: `T3 / 태국 비상장 유한회사 — 등기소가 요약재무만 공개하고 주석은 비공개`
- 좋은 예: `T1 / 영국 사기업 — Companies House에 full accounts 제출, 주석 포함`
- ⛔ **「Orbis에 없음」은 판정 근거가 아니다.** DB 미수록과 관할의 공개 여부는 다른 문제다. DB에 없어도 등기소에 있으면 T1·T2이며, 대리로 갈음할 수 없다.
- ⛔ 「시간·비용이 부족함」도 판정 근거가 아니다. 그것은 T2의 **미확보 사유**이지 티어가 아니다.

| 티어 | 관할·유형 | 확보 경로 | 수행 |
|---|---|---|---|
| **T1 — 원문 확보 가능** | 상장사(전 관할) · 한국 외감법인 · 영국 · 덴마크 · 노르웨이 · 독일 · 프랑스 등 연차보고서 공시가 발달한 관할 | 거래소·IR 공시 / DART / Companies House / CVR / Brønnøysund / Bundesanzeiger / Infogreffe·Pappers 등 **공적 등기소** | **아래 확인 항목 7종 전건 수행.** 하위 경로: 한국 외감법인·상장사 = **T1-KR**(DART), 미국 SEC 등록사 = **T1-US**(SEC/Massive 커넥터). 각각 아래 절차를 따른다 |
| **T2 — 부분 확보** | Orbis `Reports`·`Documents` 모듈에 원본 PDF가 첨부된 회사 · 등기소에서 건당 유료 취득 가능한 관할(아일랜드 CRO, 인도 MCA21, 싱가포르 ACRA, 호주 ASIC 등) | Orbis 첨부문서 → 없으면 등기소 유료 취득 | **A군 우선 확보.** B·C군은 비용 대비 판단 — 취득 여부와 사유를 조서에 기록 |
| **T3 — 확보 불가** | 원본이 공개되지 않는 관할 · 소규모 비상장사 · 요약재무만 제출하는 법인 | — | **4-B.4 대리 지표 검증으로 전환** + 한계 명시 |

**Orbis 자체가 로그인 자료원이다.** T2에서 `Reports` 모듈 확인이 필요하면 §0-1 고지 문안으로 사용자에게 질문한다.

**정정·재제출 문서의 처리 (전 티어 공통)** — 감사보고서·연차보고서가 정정 또는 재제출된 경우 **최신 제출본을 정본으로 채택**하고, 구본으로 이미 작성된 조서는 갱신한 뒤 정정 이력(구·신 문서 식별번호, 제출일, 영향 항목)을 기록한다. 관할별 식별 방법: 한국 DART는 보고서명 `[기재정정]` 접두, 영국 Companies House는 filing history의 amended/replacement 표기, 기타 등기소는 제출일자 최신본. Orbis 첨부문서(T2)는 갱신 시차가 있으므로 **원 등기소의 최신본과 문서 일자를 대조**한다.

#### T1-KR — DART 조회 절차 (비교군 지역이 한국인 사안)

호원 G1 유형처럼 **모회사가 Tested Party여서 비교군 지역 = 한국**이 되는 사안은, 비교사가 한국 외감법인이므로 감사보고서 주석까지 원문 확보가 가능하다. 이 경우 아래 절차를 따른다. 상세 운용과 그 근거는 **comparable-search-review-inbound SKILL.md의 §4-B.2·§4-B.3을 직접 열람하여 적용**한다(요약이 아니라 원문 절차를 따를 것).

**우선순위: ① DART(무료) → ② OpenDART API(무료·인증키) → ③ 유료 DB(§0-1 고지 후)**

- **① DART 전자공시 (dart.fss.or.kr)** — 외부감사 대상 법인은 감사보고서가 전량 무료 공시되며, 상용 DB의 2차 가공 데이터보다 우선한다.
  - `기업개황`에서 회사 식별 — **동명이인이 다수이므로 영문명·법인등록번호·주소·업종명 중 2개 이상으로 특정**하고 특정 근거를 조서에 기록한다.
  - 뷰어는 `https://dart.fss.or.kr/dsaf001/main.do?rcpNo={접수번호}` 로 직접 접근할 수 있다. 검색 결과에서 링크의 `rcpNo`를 추출해 이동하면 팝업 차단을 피할 수 있다.
  - 뷰어 우상단 검색창에 `특수관계자`, `회사의 개요` 등을 입력하면 해당 주석으로 바로 이동한다.
  - ⚠️ **정정공시**: 보고서명 앞 `[기재정정]` 접두가 있으면 재제출본이다. **최신 rcpNo를 정본으로 채택**하고 정정 이력(정정 전·후 rcpNo, 정정 일자, 영향 항목)을 조서에 기록한다.
- **② OpenDART API (opendart.fss.or.kr)** — C군까지 수십 개사를 훑을 때 사용한다. 사용 전 **사용자의 인증키 보유 여부를 질문**한다(§0-1 준용).
  - `corpCode.xml` → `company.json` → `list.json` → **`document.xml` 공시서류원본파일**(접수번호만으로 원문 ZIP 다운로드).
  - `list.json`에 동일 보고서의 정정 제출 건이 있으면 **접수일자가 가장 늦은 접수번호를 채택**한다.
  - ⚠️ **정기보고서 재무정보 API(`fnlttSinglAcnt` 등)는 사용할 수 없다.** 대상이 「상장법인 + 사업보고서 제출대상 주요 비상장법인」으로 한정되는데, 통상의 비교가능회사는 **외감법인(기타법인)**으로 감사보고서만 제출하므로 조회되지 않는다. **원문 XML을 파싱해야 한다.**
- **③ 유료 DB (NiceBiz · NiceValue · KIS-Line · KISVALUE 등)** — DART로 얻을 수 없는 항목(신용등급, 비외감 소기업 재무, 산업 통계, 대량 스크리닝)에 한하여 §0-1 고지 후 사용한다.

**산출물 규격** — T1-KR 사안은 검색 과정표에 「재판정 근거」 열(`rcpNo(최신·정정 반영) / 주석 번호 또는 항목 / 재판정일`)과 필드군별 정본 소스 표기를 적용한다(**comparable-search-review-inbound §4-B.5 준용**).


#### T1-US — SEC 공시 기반 조회 절차 (미국 SEC 등록 비교사)

미국 SEC 등록사(상장사 및 등록 신고인)는 **Massive Market Data 커넥터**로 재무제표를 직접 조회할 수 있다. **유료 로그인 자료원이 아니라 연결된 커넥터이므로 §0-1 고지 절차가 필요 없다.**

**사용 엔드포인트** (CIK 또는 ticker 기준):

| 엔드포인트 | 제공 항목 | 용도 |
|---|---|---|
| `/stocks/financials/v1/income-statements` | 매출액·매출원가·판관비·영업손익 등 (quarterly / annual / TTM) | **§4-B.3 항목 7** PLI 분자·분모 대조 |
| `/stocks/financials/v1/balance-sheets` | 자산·부채·자본 (기간말 스냅숏) | 항목 3·7 — 매출채권·재고자산·매입채무 잔액 |
| `/stocks/financials/v1/ratios` | ROA·ROE·부채비율 등 TTM 비율 | 항목 4·5 보조 (지주회사·손익구조 판별) |
| `/v3/reference/tickers/{ticker}` | SIC 분류·시가총액·CIK 등 | 회사 식별, 1B 후보 교차검증 |

**운용 규칙**:
- **연도 특정** — `fiscal_year`·`timeframe=annual`·`period_end`로 **과세연도에 대응하는 기간**을 명시 지정한다. 기본 정렬이 `period_end` 오름차순이므로 무지정 조회는 원하는 연도가 아닐 수 있다.
- ⚠️ **`filing_date`는 원 제출일이 아니다** — SEC 공시는 비교표시로 과거 기간을 재기재하므로, `filing_date`는 「그 기간 데이터를 포함한 가장 최근 공시일」이다. **재현 가능한 출처 기록에는 `cik` + `period_end` + `fiscal_year`를 사용**하고, 원 제출일이 필요하면 EDGAR 공시 색인으로 별도 확인한다(§10 문서 식별번호 기록 의무).
- **재기재(restatement) 주의** — 같은 `period_end`에 복수 레코드가 있으면 **최신 `filing_date` 건을 정본**으로 채택하고 그 사실을 조서에 기록한다(§4-B.2 정정·재제출 규칙과 동일 취지).
- **항목 7 대조** — 채택 PLI의 분자·분모 계정을 API 값과 전건 대조한다. **DB(Orbis) 표준화 수치와 불일치하면 SEC 원문 값을 정본으로 확정**하고 §4-B.5 판정표의 「PLI 구성 계정 수치 불일치」로 처리한다.

**적용 범위와 한계**:
- ⭕ **미국 SEC 등록사 한정**이다. EU·아시아 비상장 비교사는 여전히 T1(등기소)·T2·T3로 처리한다.
- ⚠️ **연결/별도 구분** — SEC 재무제표는 원칙적으로 **연결** 기준이다. Orbis Consolidation code(C1/C2/U1/U2)와 혼재하지 않는지 확인한다(Phase 2-2 연동).
- ⚠️ **특수관계자 거래 주석은 이 API로 제공되지 않는다.** 항목 2(독립성)는 여전히 10-K 본문·주석을 직접 확인하거나 §4-B.4 대리 지표로 처리한다 — **항목 7이 자동화된다고 항목 2까지 해결되지는 않는다.**
- 회계기준이 US GAAP이므로 K-IFRS·IFRS 비교사와 **계정 정의 차이**가 있을 수 있다. 판관비·영업손익의 구성이 다르면 Phase 2-2(분모·분자 정의)에서 조정 여부를 판단한다.

### 4-B.3 확인 항목 7종 (T1·T2)

1. **회사의 개요·연혁** — 설립 경위, 지배구조(최상위 지배기업·지분율), 주된 영업활동. ⚠️ **분할 설립된 그룹 내부 기능 자회사**인지 확인 — Tested Party와 구조가 같으면 비교가능성이 높지만 독립성 요건은 위배할 수 있다.
2. **특수관계자와의 거래(주석)** — 특수관계자별 매출·매입. **특수관계 매출 ÷ 총매출을 직접 계산**하여 독립성 기준과 대조한다. **DB 필드가 공란·0·n.a.여도 반드시 계산할 것.**
3. **재무상태표 계정 구성** — 매출채권·재고자산·매입채무의 **계정 존재 여부**. 계정이 없으면 실제 미보유, 계정이 있는데 DB가 결측이면 결측이다.
4. **자산 구성** — 금융자산·관계기업투자·투자부동산이 총자산의 과반이면 **영업회사가 아니라 지주·투자회사**다.
5. **손익 구조** — 영업손익과 영업외손익의 관계. **영업손실을 지분법이익·금융수익으로 메우는 구조**이면 저수익의 원인이 「비교가능한 영업 실적」이 아니다.
6. **판관비 구성·인력 규모** — 급여 비중, 종업원 수. 해당 기능 수행 실체가 확인되는지.
7. **PLI 구성 계정의 원문 대조** — **T1-KR·T1-US 사안은 A·B군 전건 필수**(C군 생략 가능). 그 외 T1·T2는 원문을 확보한 회사에 한하여 수행하고, 미수행 회사·사유를 조서에 기록한다. **T3는 해당 없음**(항목 7 미수행 사실과 그 한계를 §4-B.4 대리 지표표에 명시).
   - 채택 PLI의 분자·분모를 구성하는 계정(매출액·매출원가·판매비와관리비·영업손익, 운전자본 조정 적용 시 매출채권·재고자산·매입채무의 연도말 잔액)을 **원본 재무제표 값과 대조**한다. 직전연도 값은 당기 보고서의 **전기 비교표시 금액**으로 확인할 수 있다.
   - 불일치 발견 시: **원문을 정본으로 확정**하고 그 수치 변경이 사분위·범위 판정에 미치는 영향을 즉시 산정한다. 판정이 변동하면 1D ②ⓐ 발동, 산출 원본·Tap17이 이미 작성된 상태이면 workbook-validator 재실행 필요를 사용자에게 고지한다.
   - 항목 3(계정 존재 확인)과의 관계: 항목 3은 존재 여부, 항목 7은 **금액 일치**를 본다. 항목 3에서 「실제 미보유」로 확인된 계정은 항목 7 대조에서 0으로 취급한다.

### 4-B.4 T3 대리 지표 검증 (Orbis 필드 기반)

원본을 확보할 수 없을 때 Orbis에서 **실제로 조회 가능한 필드**로 위 항목 1~6을 최대한 대리한다. **항목 7(PLI 구성 계정 원문 대조)은 원문이 전제이므로 T3에서는 대리가 성립하지 않는다** — 미수행 사실과 「DB 표준화 재무수치가 원문과 일치하는지 확인되지 않았다」는 한계를 반드시 기록한다. 각 대리 항목의 **대리 한계도 반드시 함께 기록**한다.

| 확인 목적 | Orbis 대리 지표 | 대리 한계 |
|---|---|---|
| **독립성 (항목 2 대리)** | **BvD Independence Indicator** · Shareholders 목록과 지분율 · GUO(Global Ultimate Owner)·DUO 여부 · Subsidiaries 목록 | **지분 독립성만 측정하며 거래 독립성은 측정하지 못한다.** 지분상 독립이어도 매출이 특정 관계사에 집중될 수 있고, 그 반대도 가능하다 |
| 지주회사 판별 (항목 4) | Financial fixed assets / Total assets · Shares in group companies · Subsidiaries 수 | 계정 세분도가 낮아 관계기업투자와 단순 금융자산이 구분되지 않는 경우가 있다 |
| 손익 구조 (항목 5) | Operating P/L vs Financial P/L vs P/L before tax | 영업외수익의 내역(지분법이익 여부)을 알 수 없다 |
| 실체 (항목 6) | Number of employees · Costs of employees | n.a. 비율이 높은 관할이 많다 |
| 기능 (항목 1) | Trade description · Products & services · NACE 주·부 코드 · Standardised legal form | 텍스트가 짧고 갱신이 늦은 경우가 있다 |
| 재무제표 성격 (항목 3) | Consolidation code (C1/C2/U1/U2) · 계정별 n.a. 여부 | 요약재무만 제출한 회사는 계정 자체가 비어 있다 |

#### BvD Independence Indicator — 등급 정의와 실무 기준

| 등급 | 정의 |
|---|---|
| **A** (A+ · A · A−) | 직접·합산 지분 **25% 초과 주주가 없음** |
| **B** (B+ · B · B−) | 25~50% 주주는 있으나 **50% 초과 주주가 없음** |
| **C** (C+ · C) | 합산·계산합산 지분 **50% 초과** 주주 존재 |
| **D** | **직접 지분 50% 초과** 주주 존재 |
| **U** | 독립성 정도 불명 |

⚠️ **`+` / `−`는 독립성 강도가 아니라 지표의 신뢰도(정보 출처·식별된 주주 수)를 나타낸다.** A−가 A보다 덜 독립적인 것이 아니다. 따라서 「A 계열만」처럼 +/− 로 등급을 자르는 설계는 근거가 없다.

**실무 채택 기준 (표준)**

> **A+, A, A−, B+, B, B− 채택 / C+, C, D, U 배제**

즉 **「50% 초과 지배주주가 없는 회사」** 를 독립기업으로 본다. A 계열만으로 좁히면 모집단이 과도하게 축소되어 표본 확보가 어려워지고, 25~50% 주주가 있다는 사실만으로 거래 독립성이 부정되지도 않는다. C·D는 50% 초과 지배로 그룹 계열사일 개연성이 높고, U는 확인 불가이므로 배제한다.

#### T3 최소 검증 수준 — 2축을 모두 충족해야 통과

대리 지표표를 채웠다고 검증이 성립하는 것이 아니다. **회사별로 아래 두 축을 모두 만족**해야 T3 통과로 본다.

| 축 | 최소 요건 | 기록 |
|---|---|---|
| **독립성 축** | BvD Independence Indicator 등급 + 주주 지분율(GUO 포함) 확인. 실무 채택 기준(A·B 채택 / C·D·U 배제) 적용 | 등급·GUO 지분율·조회일 |
| **기능·실체 축** | Orbis Trade description **외에 공개정보 1건 이상** — 회사 웹사이트·IR 페이지·현지 공시 요약·업계 보도 중 하나로 **주된 영업활동과 사업 실체를 교차 확인** | 자료원 URL·조회일·확인 내용 1~2줄 |

⚠️ **Orbis 필드 하나로 항목 1·6을 끝내지 않는다.** 위 대리 한계표에 적은 대로 Trade description은 텍스트가 짧고 갱신이 늦다. 기능이 바뀐 회사, 영업을 중단한 회사, 지주회사로 전환한 회사를 구분하지 못한다. **한 소스만 본 것은 교차 확인이 아니다.**

**2축 미충족 회사가 사분위 형성 회사이면 T3 통과 불가** — Phase 4 민감도에 제외 시나리오를 넣고 사용자에게 고지한다. 사분위 비형성사는 미충족 사유를 조서에 기록하고 통과할 수 있다.

**대리로 갈음한 사실 자체는 결함이 아니다.** OECD TPG paras. 3.30~3.34가 공개정보의 한계를 인정한다. 결함이 되는 것은 **갈음한 사실을 적지 않는 것**이다.

**T3에서의 독립성 처리 원칙 (중요)**

거래 기준 독립성을 검증할 수 없으므로 **지분 기준을 적용하고, 그 대체 사실을 보고서에 명시**한다. 이것이 T3 사안에서 방어 가능한 구성이다.

- 기본: 위 실무 채택 기준(**A·B 계열 채택, C·D·U 배제**) 적용.
- 병행: GUO 지분율 상한(50%) 명시 적용, 필요 시 Subsidiaries 수로 지주 성격 보완 확인.
- **더 좁히는 것은 신중히.** A 계열 한정은 모집단 축소 효과가 크므로, 채택하려면 **그 사유(예: Tested Party가 완전 독립기업이고 표본이 충분함)를 조서에 기록**하고 Phase 4 민감도에 「A·B 채택 시」 시나리오를 병기한다.
- **서술 예시** — 보고서 제VII장과 방어 패키지에 그대로 기재한다.
  > 「비교가능회사가 소재한 관할에서는 특수관계자 거래 내역을 포함한 감사보고서 주석이 공개되지 않아 거래 기준 독립성(특수관계 매출 비중)을 직접 검증할 수 없다. 이에 지분 기준 독립성(BvD Independence Indicator A+·A·A−·B+·B·B−, 즉 50% 초과 지배주주가 없는 회사)을 적용하여 갈음하였으며, 이는 OECD TPG paras. 3.30~3.34가 인정하는 공개정보의 제약에 따른 것이다.」

**규범적 근거** — OECD TPG는 감사보고서 원문 확인을 요구하지 않는다. para. 3.44는 「제외 근거를 유지·설명할 수 있을 것」을, paras. 3.30~3.34는 **공개정보의 한계와 그에 따른 실무적 제약을 인정**한다. 따라서 T3에서 원문을 확보하지 못한 것 자체는 절차 위반이 아니며, **한계를 명시하고 대리 지표로 갈음한 사실을 문서화하면 방어가 성립**한다. 반대로 그 명시를 누락하면 「검증했다고 주장했으나 검증하지 않은」 상태가 되어 방어력이 급격히 떨어진다.

### 4-B.5 판정과 이관

| 결과 | 처리 |
|---|---|
| 검색기준 위반 확인 (예: 특수관계 매출 >20%, **Independence Indicator C·D·U**) | **Phase 1D ②ⓕ 발동** — 해당 회사 제외 후 사분위 재계산, 표본 보완 필요 여부 판단 |
| **PLI 구성 계정 수치 불일치 (항목 7)** | 원문을 정본으로 확정, 사분위·범위 판정 영향 즉시 산정. 판정 변동 시 **1D ②ⓐ 발동** + 산출 원본·Tap17 기작성 시 workbook-validator 재실행 고지 |
| 기능 프로파일 상이 확인 (지주회사·이종 기능 등) | Phase 3 경계 사례로 등급 상향, Phase 4에서 포함·제외 영향 정량화, **존치 시 서면 논거 필수** |
| 결측 의혹 해소 (실제 미보유 확인) | 기록 후 통과 — 다만 **같은 확인 과정에서 드러난 다른 사실을 반드시 함께 평가**할 것 |
| T3 대리 지표로만 확인 | 대리 지표 결과 + **대리 한계**를 조서에 기록. 해당 회사가 사분위 형성 회사이면 Phase 4 민감도에 「제외」 시나리오 추가 |
| 자료 접근 불가 (§0-1 (c) 선택) | 미확인 항목·사유·영향 범위 기록 + 제외 시나리오 추가 |
| C군에서 유력 후보 발견 | 표본 보완 후보로 등재, Phase 4 민감도에 편입 시나리오 추가 |
| **티어와 확인 주체의 상충** — T1·T2 회사인데 확인 주체가 `게이트대리` | **3B 게이트 통과 불가.** 원문 확보가 가능한 관할에서 대리로 갈음한 것이므로, 원문을 확보하거나 **티어 판정을 정정**한다. 정정하는 경우 판정 근거를 다시 적는다 |
| **T1·T2 회사의 확인 주체가 `실무자기재`·`미확인`** | ① **사분위 형성사** 또는 **단독 배제 시 판정 반전사**이면 **필수** 등급 — 확인 전까지 Phase 4 확정·후속 게이트 진행 중단 고지. ② 그 밖의 최종 표본은 **권고** 등급 — 사유·영향 범위 기록 + Phase 4 민감도에 제외 시나리오 추가 |
| **T3 회사가 §4-B.4 2축 미충족** (`Orbis필드` 단독 등) | 사분위 형성사이면 **통과 불가**, 그 밖은 미충족 사유 기록 후 통과. 어느 경우든 **대리 한계를 조서에 명시**한다 |

**확인 결과는 반드시 「그래서 비교가능한가」로 이어져야 한다.** 데이터 검증에서 「결측 아님」이 확인되었다고 검토를 종료하지 않는다 — 실전에서 결측 의혹은 해소되었으나 같은 문서에서 훨씬 중대한 사실(자산의 91%가 지분법투자인 지주회사)이 드러났다.

### 4-B.6 산출물 규격 — 검색 과정표에의 반영

Phase 3B의 결과는 조서에만 남기지 않고 **검색 과정표 자체에 반영**한다. 세무조사 시 과정표 단독으로 판정 근거에 즉답할 수 있어야 한다.

1. **재판정 근거 열 추가** — 원문·대리 재판정이 개입한 Step(통상 Step 6·9, 항목 7 대조 포함)에는 과정표 우측에 다음 7개 필드를 회사별로 기재한다.

   `티어 / 티어 판정 근거 / 문서식별번호 / 주석·항목 / 재판정일 / 확인 주체 / 확인 수단`

   예: `T1-KR / 한국 외감법인 — DART 감사보고서 주석 공시 / 20250403001822 / 주석 12 특수관계자거래 / 2026-08-12 / 게이트원문 / DART뷰어`
   예: `T3 / 태국 비상장 유한회사 — 등기소 요약재무만 공개 / Orbis 2025-12-31 / Independence B+, GUO 34% / 2026-08-12 / 게이트대리 / Orbis필드+공개정보`

   **문서식별번호는 관할별로 다르다** — 한국 `rcpNo` / 미국 `CIK + period_end + fiscal_year`(⚠️ `filing_date`는 원 제출일이 아니다, §4-B.2 T1-US) / 그 밖의 등기소 filing 번호 / T3는 `Orbis 추출일`.

2. **어휘를 고정한다.** 자유 서술을 허용하면 기계 검사(workbook-validator Phase 1 항목 8)가 성립하지 않는다.

   | 확인 주체 | 뜻 |
   |---|---|
   | `게이트원문` | 본 게이트가 **이번 검토에서** 원문(감사보고서·연차보고서·SEC 공시)을 직접 확인했다 |
   | `게이트대리` | 본 게이트가 **이번 검토에서 대리 지표로** 확인했다(§4-B.4 2축). **T3의 정당한 수행이며 미이행이 아니다** |
   | `사용자제공` | 게이트 요청으로 사용자가 조회하여 값을 전달했다(§0-1 (a)). 출처·조회일 병기 |
   | `실무자기재` | 워크북·과정표에 기재되어 있을 뿐이다. **게이트는 기재 사실만 대조했다** |
   | `미확인` | 확인하지 못했다(§0-1 (c)) |

   | 확인 수단 | 비고 |
   |---|---|
   | `DART뷰어` · `OpenDART` | T1-KR |
   | `등기소` | Companies House · CVR · Brønnøysund · Bundesanzeiger · Infogreffe/Pappers 등. **등기소명 병기** |
   | `SEC(Massive)` | T1-US 커넥터 |
   | `IR공시` | 거래소 공시·연차보고서 IR 게재본 |
   | `Orbis첨부` | T2 — Reports·Documents 모듈의 원본 PDF |
   | `Orbis필드` | T3 대리 — **단독으로는 §4-B.4 2축을 충족하지 못한다** |
   | `공개정보` | 회사 웹사이트·IR 페이지·현지 공시 요약·업계 보도. **URL·조회일 병기 필수** |
   | `상용DB` | Orbis 외 상용 자료원. **자료원명·조회일 병기 필수.** 독립성 판정의 단독 근거로는 사용할 수 없다 |
   | `없음` | 확인 주체가 `실무자기재`·`미확인`인 경우 |

   복수 수단을 쓴 경우 `+`로 잇는다(예: `Orbis필드+공개정보`).

   ⚠️ **확인 주체·수단은 이번 검토 시점 기준으로 적는다.** 전기 조서·선례 세션의 값을 승계하지 않는다. 승계하면 최초 1회의 확인이 무기한 유효한 것처럼 되어, 정정·재제출과 결산연도 갱신이 반영되지 않는다.

3. **헤더 주석 표준 문안** — 「[Phase 3B {일자}] Step {N}은 상용 DB 필드가 아니라 원문 또는 §4-B.4 대리 지표로 재판정하였다. 회사별 근거·티어는 「재판정 근거」 열 참조.」

4. **정본 소스 표기** — 필드군별 정본 소스를 헤더 주석 또는 범례에 명시한다.

5. 방어 패키지 1(최종 검색과정 표)과 8(정밀 검토 조서)은 이 열을 매개로 1:1 상호 참조가 성립해야 한다. **T3 사안은 대리 지표표(항목별 대리 한계 포함)가 방어 패키지 8의 필수 구성**이다.

게이트: 관할 티어 판별 완료(**T1-KR·T1-US 하위 경로 구분 + 회사별 티어 판정 근거 기재**), A·B군 전건 + C군 선별 검토(정정·재제출본 반영 최신 문서), 확인 항목 **7종**(T1·T2 — 항목 7은 T1-KR·T1-US 필수·그 외 원문 확보 시) 또는 대리 지표표(T3, **2축 충족** + 항목 7 미수행 한계 명시) 고정, **전 사안 과정표 재판정 근거 열(§4-B.6 7개 필드)·정본 소스 표기 완료**, **티어 × 확인 주체 상충 0건**, 검색기준 위반·수치 불일치 검출 시 1D 재판정.

## 5. Phase 4 — 결과의 경제적 타당성 검토

1. **극단치 실사** — PLI 분포의 상·하위 2~3개사 원인 확인(Phase 3B 결과 인용).
2. **민감도 분석**
   - **개별 회사 민감도(jack-knife) — 표본 10사 미만이면 전건 필수.** 1사씩 제외하며 사분위와 판정 변화를 측정한다. 작은 표본에서는 임계치 민감도보다 이쪽이 결정적이다(실전에서 결론을 좌우한 것은 임계치가 아니라 Q1을 형성하는 2개 회사였다).
   - **사분위 형성 회사의 식별** — Q1·중앙값·Q3가 각각 어느 회사의 값으로 산출되는지 명시한다. 이 목록이 Phase 3B A군의 대상이 된다.
   - **임계치 변경** — 매출 밴드, R&D·광고비 상한, 경계 사례 포함·제외.
   - **독립성 등급 조합 변경** — 「A·B 채택(표준)」 대비 「A 계열만」·「U 포함」 시나리오의 표본 수와 사분위 변동을 측정한다. 표준보다 좁힌 설계를 채택한 경우 그 근거로 사용한다.
   - **평가단위·지역 구성 변경** — 복수 평가단위·복수 지역 사안은 구성별 시나리오를 각각 측정한다.
   - **운전자본 조정 방식 변경** — 조정 항목별 적용·미적용.
3. **범위 검토** — Tested Party 실현 PLI의 범위 내 여부, **하사분위·상사분위와의 여유 폭**. 여유가 좁으면(예: 사분위 폭의 10% 미만) 그 사실과 함의를 명시적으로 보고한다.
4. **운전자본 조정 검토**(TPG paras. 3.47~3.54) — **조정 전후 값이 동일한 회사가 있으면 「조정 불필요」인지 「조정 미작동」인지 구분**한다(분모가 0이어서 산식이 정의되지 않고 오류 처리로 0이 되는 경우가 있다).

게이트: 민감도 분석 수행(jack-knife 포함), 과민 기준 존재 시 보고·확정.

## 10. 경계 (중요)

- 본 스킬은 검색 과정의 **검토**이지 검색 대행이 아니다.
- **Claude는 유료·회원제 자료원에 로그인하지 않고 자격증명을 입력하지 않는다.** 접근이 필요하면 §0-1 고지 문안으로 질문한다.
- Phase 3B에서 원본·대리 지표를 확인하되 **재무수치를 임의로 대체하지 않는다**.
- **T3에서 원본을 확보하지 못한 것을 「검증 완료」로 서술하지 않는다.** 대리 지표로 갈음한 사실과 그 한계를 반드시 병기한다.
- **독립성 등급 기준을 실무 표준(A·B 계열)보다 좁히거나 넓힐 때는 사유를 조서에 기록하고 민감도로 영향을 제시한다.** `+`/`−`를 독립성 강도로 오해하여 등급을 자르지 않는다.
- 회사 식별 시 동명이인에 주의한다. 영문명·등록번호·소재지·업종코드 중 최소 2개로 특정하고, 특정 근거를 조서에 기록한다.
- 원본 문서 인용 시 관할별 문서 식별번호(DART rcpNo, Companies House filing ID 등)와 제출일을 함께 기록하여 재현 가능하게 하고, **정정본이 있으면 최신본 기준임을 명시**한다.
- 국내 조문 인용(국조법·국조령·국조칙 조번호)은 **tp-case-law로 실재·적합 여부를 확인한 뒤** 사용하고, **반드시 표제를 병기**한다(예: 「국조법 §8(정상가격의 산출방법)」). 2020.12.22. 전부개정(법률 제17651호, 2021.1.1. 시행)으로 번호 체계가 전면 교체되었으며, **구 번호도 현행법에 실재하되 다른 내용을 규정**하므로 조번호 실재 확인만으로는 오류가 검출되지 않는다. 「~의2」 가지조문(예: 국조령 §15의2)은 특히 주의한다.
- **법령이 정하지 않은 임계치를 법령 근거로 서술하지 않는다.** 특수관계 비중 20%, 상품매출 비중, R&D 상한, **사분위 산정방식·보간법**, 최종 표본 6개 미만 기준, n.a. 30% 기준 등은 **국조법령에 규정이 확인되지 않는 실무 관행**이다. 관행임을 명시하고 채택 사유를 조서에 기록한다. ※ **비교대상 「둘 이상」은 관행이 아니라 법령 요건**이다 — 국조령 §15⑤(정상가격 산출방법의 적용)이 「둘 이상의 거래를 토대로 정상가격 범위를 산정」하도록 정하며, 범위 자체의 근거도 §15⑤·⑥이다.
- **게이트가 스스로 확인하지 않은 것을 확인된 것으로 조서에 옮기지 않는다.** 워크북·과정표·전기 조서의 기재를 인용할 때는 그것이 **기재 사실**임을 밝히고(§4-B.6 확인 주체 = `실무자기재`), 게이트의 확인과 구분하여 표기한다. 기록의 **존재**와 내용의 **진위**를 같은 칸에 담지 않는다.
- **티어를 낮춰 잡아 검증을 면제받지 않는다.** 원본 확보 가능성은 관할·법인 유형의 사실 문제이지 검토 편의의 문제가 아니다. T3 판정에는 **그 관할에서 무엇이 공개되지 않는가**를 근거로 적는다(§4-B.2). 대리 검증은 **확보가 불가능할 때 정당한 것**이지, 확보하지 않기로 한 선택을 정당화하지 않는다.
