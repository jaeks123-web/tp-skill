# 6단계 비교가능회사 검색전략 수립 절차

## Phase 0 — 무결성 확인 (본론 착수 전 1회)

본 스킬은 검증 규율을 누적해 온 파일이며, 다른 TP 스킬과 서로를 지목하며 맞물려 동작한다.
경고문이 지워지거나 구버전이 섞이면 오류를 검출하는 대신 **주입**하게 되므로, 본론에 들어가기
전에 정본 여부를 먼저 확인한다.

**실행 방법 — 스킬 폴더를 탐색해서 이동한 뒤 실행한다.**

```bash
D=$(find ~ / -maxdepth 8 -type d -name "comparable-search-strategy" -path "*skills*" 2>/dev/null | head -1)
cd "$D" && python3 scripts/verify_skills.py
```

⚠️ **스킬이 안내하는 base directory 경로를 그대로 쓰지 말 것.** 그 경로는 Windows 형식
(`C:\Users\...`)인데 명령을 실행하는 셸은 **Linux 경로 체계**를 쓴다. 같은 폴더인데 이름이
달라 `No such file or directory`가 난다(실행 검증에서 실제로 확인한 오류다).
위 탐색 방식은 **경로 체계와 무관하게 동작**하며 약 1초 걸린다.

폴더 안에서 실행하면 **인자가 필요 없다.** 스크립트가 루트와 대상 스킬을 스스로 판별한다.

- **합격** — 그대로 진행한다. 별도로 보고하지 않는다.
- **변조·누락** — **작업을 중단하고 사용자에게 고지**한다. 어느 파일이 정본과 다른지 알린다.
  사용자가 진행을 지시하면 「무결성 미확인 상태」임을 답변에 명시하고 진행한다.
- **실행 불가**(경로·스크립트·매니페스트 없음) — 검증을 **생략하되 침묵하지 않는다.**
  한 줄로 「무결성 확인 미실행」을 알리고 진행한다.
- **`[미설치] tp-case-law`가 보이면** — 본 스킬이 조문·판례 검증을 tp-case-law에 맡기는
  부분은 실행되지 않는다. 해당 단계에서 그 사실을 고지하고, 조문 인용은 「확인 필요」로 표기한다.

⚠️ **이 절차는 변조를 막지 못한다. 드러나게 할 뿐이다.** 매니페스트(`scripts/MANIFEST.sha256`)가
함께 바뀌면 검증은 통과한다. 배포 시에는 매니페스트를 변경 이력이 남는 곳에도 보관하고 대조한다.

## 0. 본 스킬의 위치 (먼저 확인할 것)

본 스킬은 **제작 라인** 도구다. 검색을 실행하기 전에 실행안을 만든다.

```
[제작 라인] 워크북 작성 → ★comparable-search-strategy★ → 실무자 DB 검색 실행 → Tap15 기재
[검토 라인] industry-analysis-review → characterization-gate → comparable-search-review
            → workbook-validator → tp-report-writer
                     └ Phase 1D 「전면 재검색」 판정 시에만 제작 라인으로 반송
```

**본 스킬은 스스로 실행 필요성을 판단하지 않는다.** 이미 검색이 수행된 케이스(Tap15에 실적이 기재된 상태)에서 본 스킬을 실행하면 산출된 실행안의 소비처가 없다.

### 착수 전 진입 경로 확인 (게이트)

| 경로 | 조건 | 조치 |
|---|---|---|
| **A. 신규 케이스** | Tap15가 비어 있거나 검색 실적이 없음 | 정상 진행 |
| **B. CSR 반송** | comparable-search-review(또는 -inbound) Phase 1D에서 「① 전면 재검색」 판정 | 판정표를 인수한 후 진행. 아래 0-1 특칙 적용 |
| **C. 해당 없음** | Tap15에 검색 실적이 있으나 1D 판정이 없음 | **진행하지 않는다.** comparable-search-review 실행을 안내하고, 그럼에도 진행을 지시하면 산출물이 워크북에 반영되지 않는 참고자료임을 명시한 후 진행 |

### 0-1. 경로 B(반송) 특칙

1. **무효화 범위를 착수 전에 고지**한다 — Tap15, Tap17, Tap18 §3, workbook-validator 합격 판정, 보고서 제VII·VIII장. (Inbound 사안은 Tap18이 없으므로 Tap15·17로 한정)
2. 신규 표본 확정 후 **comparable-search-review Phase 1부터 재실행**해야 한다. 반송 전의 1A~1C 산출물은 모집단이 달라졌으므로 재사용하지 않는다.
3. 기존 표본·검색 이력은 삭제하지 않고 이력 시트로 보존한다.

### 0-2. 유료·로그인 자료원 접근 원칙 (전 Step 공통 · 필수)

**Claude는 사용자 계정으로 로그인하지 않으며 아이디·비밀번호 등 자격증명을 입력하지 않는다.** 로그인이 필요한 자료원에 접근해야 하는 상황이 발생하면 **작업을 중단하고 사용자에게 질문 형식으로 고지**한다. 임의로 우회하거나, 미확인 상태로 조용히 진행하거나, 추정값으로 대체하지 않는다.

**대상 자료원 (예시)**: Orbis / TP Catalyst (Moody's·구 Bureau van Dijk) · Compustat · S&P Capital IQ · RoyaltyStat · ktMINE · **NiceBiz · NiceValue** · KIS-Line · TS2000 · 그 밖의 유료 기업정보·신용정보 서비스.

**본 스킬에서 이 상황이 발생하는 전형적 지점**
- Step 3(5_3·4단계) — 확정 산업코드의 **현행 코드 체계 존재 여부·모집단 규모**를 상용 DB에서 사전 확인하려는 경우
- Step 4(시트 8) — 실행안의 **예상 기업수**를 실제 조회로 검증하려는 경우
- Step 0·Step 4 — 기존 Tap15 실적과 대조하기 위해 **원본 추출조건을 재조회**하려는 경우

**고지 문안 표준**

```
[자료원 접근 확인 필요]
① 필요 자료 : {DB명} — {항목}  (예: Orbis — NACE 2620 + 독일 + Independence Indicator A·B, 2024년 기준 모집단 수)
② 사용 목적 : Step {N} {항목} — 이 값이 없으면 {실행안 항목}을 {예상치/미기재}로 둘 수밖에 없음
③ 대체 가능성 : {지식DB 선례 분포·공개 통계 등으로 갈음 가능 여부와 그 한계}
④ 선택지
   (a) 직접 조회 후 값 전달 — 사용자가 해당 DB에서 조회하여 수치를 알려준다
   (b) 무료 대체 소스·선례 분포로 우회 (권장, 가능한 경우)
   (c) 미확인 처리 — 「예상 기업수: 미확인」으로 기재하고 사유를 실행안 비고와 시행 로그에 명시
```

**본 스킬의 산출물은 실행안이므로 (c)가 허용된다.** 예상 기업수·모집단 규모는 실무자가 실제 검색을 실행하면 확정되는 값이다. 다만 **미확인 사실과 사유를 실행안 비고 및 Step 6 시행 로그에 반드시 기록**하여, 이후 comparable-search-review가 「검증되지 않은 예상치」임을 알 수 있게 한다.

0. **진입 경로(A/B/C)를 §0에 따라 확인·기록한다.** 경로 C이면 진행하지 않는다.
1. 케이스 워크북 Header·Tap14(Inbound는 Tap16)에서 평가단위 목록(G1/S1/T1 등)을 확인한다.
2. 사용자에게 **분석 평가단위를 확정**받는다. 복수 평가단위는 작업파일을 분리한다.
3. 필수 검토 Tap 존재 확인: Tap1-1, Tap3, Tap3-1, Tap3-2, Tap5, Tap6, Tap9, Tap9-1, Tap9-2, Tap9-3, Tap12-1, Tap14, Tap15(있는 경우), Tap16(있는 경우). 누락 시 사용자에게 보고 후 진행 여부 확인. (Inbound는 Tap12-1·Tap14 부재가 정상)
4. **자료원 접근성 확인** — 상용 DB 조회가 필요할 것으로 예상되면 §0-2 고지 문안으로 착수 시점에 질문한다.

## Step 1. 사전절차 (1A → 1B → 1C, 순서 고정 · 게이트)

### 1A. 거래분석
- Tap3·Tap14에서 거래코드·거래유형·당사자·금액·평가단위를 전사한다.
- 확정 평가단위 거래만 "포함", 나머지는 "제외(사유)" 표기.
- 통합(Aggregation) 판단 체크리스트 5항목: ①거래 상호연관성(국조법 시행령·OECD TPG 3.9) ②상대방 동일성 ③가격결정 구조 동일성 ④무형자산 거래 분리(T1) ⑤결론 및 Tap14 일치 확인. **국내 조문 인용은 tp-case-law로 실재·적합 확인 후 사용한다.**
- Tap3-1에서 내부 CUP 존재 여부를 확인해 기재.

### 1B. Tested Party 및 특성 결정
- B-1: Tap9의 기능·자산·위험 Scale을 거래 당사자 쌍으로 전사, 비교 판단 기재.
- B-2: 당사자별 특성(Characterization) 결정. **Tap12-1 §3-2의 정량 기여율·기능/위험/DEMPE 수준·특성 분류를 반드시 전사(B-2a)**하고 FAR 기반 분류와 일치 여부를 확인한다. (Inbound는 Tap12 정성 Scale 대비로 갈음)
- B-3: Tested Party 선정 판단 5기준(①기능 복잡성 ②비교자료 가용성 ③재무자료 신뢰성 ④검증 방향 ⑤결론). 근거 출처(Tap 번호)를 기재하고, 워크북에 없는 논리는 **[추론]으로 명시**. 양 당사자 모두 기능이 복잡하면 "덜 복잡한 당사자" 원칙 대신 비교자료 가용성·재무 신뢰성이 결정 기준임을 명시한다.
- 결론을 Tap14(Inbound는 Tap16)의 Tested Party 지정과 대조하고 불일치 시 보고.

### 1C. 기능유사성 판별
- Tap5·Tap6·Tap9에서 Tested Party의 기능 프로파일을 전사한다.
- 지식DB [검색세션] 거래유형 값 기준으로 **주 기능군(3점)/보조 기능군(2점)/1점 조건/배제 기능군(0점)**을 확정한다. 이 판별이 Step 2 채점의 유일한 기준이며, 변경 시 재채점한다.

## Step 2. 세션 채점 (지식DB 전수)

[검색세션] 전 세션을 4축으로 채점한다 (스크립트 사용, 수기 금지):

- 기능일치 0~3: 1C 판별표 적용
- 산업유사 0~3: 3=동일 산업 / 2=동일 산업군 / 1=유사 제품·공정 특성 / 0=상이
- 지역일치 0~2: 2=동일 / 1=인접·확장 가능 / 0=상이
- 시기근접 0~2: 2=5년 이내 / 1=10년 이내 / 0=초과

Tier: 합계 8~10=Tier1(직접 준용) / 5~7=Tier2(벤치마크) / 3~4=Tier3 / 0~2=Tier4.
채택=Tier1, 참고=Tier2 중 산업유사≥2. 점수 5 이상 전 세션을 3_1단계 시트에 기재하고, 제외 건수를 하단에 주기한다.

**자기참조 점검(필수)**: 최고점 세션이 본 케이스의 선행 검색인지 확인한다. 해당 시 "자기참조 소지" 표기하고, 모든 확정 기준에 **독립 선례를 반드시 병기**한다.

### 2-1. 선례의 회사별 데이터를 그대로 승계하지 않는다 (중요)

선례에서 **기준·임계값**을 준용하는 것과 선례에 적힌 **회사별 실측 데이터**(주주현황·지분율·재무비율)를 그대로 옮겨 쓰는 것은 전혀 다르다. 후자는 재확인 없이 승계하지 않는다.

> 실측(2026-08): 선례 시트와 현재 DB를 10개사 표본으로 대조했더니 **17건이 어긋났다.** 표본 전체(76개사) 기준으로는 80~130건 규모가 예상되어, 단순 보완이 아니라 **전면 재검증** 성격의 작업이 되었다.

불일치는 네 유형으로 갈리며, **유형별로 대응이 정반대**다.

| 유형 | 성격 | 대응 |
|---|---|---|
| ① 실제 지분 변동 | 상장사는 기간 경과로 지분이 바뀐다. 선례에만 있는 주주·현재에만 있는 주주가 동시에 발생 | **현재 값이 맞다.** 기준일을 명시하고 당해 분석연도 기준으로 재취득 |
| ② 표시 한도로 인한 누락 | 선례 작성 시점에 이미 잘려 있었을 수 있다(아래 3-2 참조) | 주주 **수**와 **합계 지분율**을 함께 대조하면 검출된다 |
| ③ 전기(轉記) 오류 | 27.64 ↔ 27.54처럼 한 자리만 어긋난다 | **선례가 틀린 것.** 소수점 이하까지 기계적으로 대조 |
| ④ 표기 오기 | 주주명 철자 오류(지분율은 일치) | **선례가 틀린 것.** 이름 불일치를 곧바로 「다른 주주」로 판단하지 않는다 |

①을 오류로, ③·④를 실제 변동으로 오인하면 정정 방향이 반대가 된다. 뭉뚱그려 「선례 갱신」으로 처리하지 말고 **유형을 판정한 뒤 처리**한다.

**대조 전에 교집합부터 확인한다.** 선례 목록과 현재 대상 목록의 회사 구성이 다를 수 있다(실측: 76개사 중 60개사만 겹침). 겹치지 않는 회사를 「불일치」로 집계하면 수치가 왜곡된다.

## Step 3. 단계별 추출 (시트 4~7)

채택·참고 세션의 [검색단계]를 2_매핑정의의 분류 매핑에 따라 추출한다. 모든 행에 **세션ID-단계ID + 검색기준 원문 발췌**를 기재한다.

- 4_2단계: 데이터출처 집계 → DB 우선순위 확정 (1차분류 2·15·18)
- 5_3·4단계: DB코드 추출 → 코드체계·버전(KSIC/NACE/SIC 차수) 구분 → 구코드의 현행 코드 승계 연속성 확인 → 확정 코드 요약 (1차분류 3·4). **현행 코드의 실재·모집단 규모 확인에 상용 DB가 필요하면 §0-2로 질문한다.**
- 6_5단계: 정량 임계값 추출(1차분류 5·6·7·8·9·10·11) → 선례 분포 기재 → [케이스 적용값 확정] 블록에 기준유형별 확정값 + 복수 근거 기재. 케이스 특수성은 사유를 비고에 명시
- 7_6단계: 정성 기준 추출(1차분류 12·13·14·16·19·20·21) → 케이스 FAR 근거(Tap9-3, Tap12-1 §3-2) 연결 → 적용 강도(필수/고려) 결정

'기타(미분류)' 단계는 검색방법 키워드로 개별 판단하여 배분한다.

### 3-1. DB 선택 — 스크리닝 적합성 (실측 기록)

4_2단계에서 DB 우선순위를 정할 때 아래를 전제로 한다.

| DB | 비교사 스크리닝 | 근거 |
|---|---|---|
| **Orbis / TP Catalyst** | **적합** | 산업코드·재무·독립성 지표를 한 화면에서 필터링. 리스트 컬럼으로 대량 취득 가능 |
| **S&P Capital IQ (웹 Screener)** | **부적합** | 2026-08 실측: 동일 취지의 조건을 적용했을 때 후보가 **353사 → 11사**로 급감. 비상장 커버리지와 필터 구조가 TP 표본 구성에 맞지 않는다 |
| **CIQ MCP (Kensho LLM-ready API)** | **불가** | 스크리닝 기능 자체가 없다. 제공 데이터셋 5종은 **회사명을 특정한 질의**를 전제로 한다 |

### 3-2. 주주 데이터 취득 시 함정 — 기본 표시 행수 (실측 기록)

Orbis / TP Catalyst의 개별회사 주주 화면은 **기본 25행**만 표시한다. 주주가 많은 회사는 2페이지 이하가 잘리는데, **그 사실이 화면에 뚜렷하게 표시되지 않는다.**

> 실측(2026-08): 실제 주주가 26명인 회사에서 기본 25행 때문에 **법인주주 0.13%가 통째로 누락**되었다. 지분 기준 독립성 판정의 입력값이 빠지는 것이므로 단순 편의 문제가 아니다.

- 표시 행수를 **먼저 100으로 올린다.** 한 번 설정하면 이후 회사에도 유지된다.
- 주주 수가 표시 한도에 근접하면 **다음 페이지 존재 여부를 반드시 확인**한다.
- 주주 화면의 **Type 컬럼(C 법인 / I 개인 / Z 공중 / L 기타)** 이 「주주 특수관계 검증」의 1차 근거다. 법인주주(C)만 추려 지배관계를 확인하면 된다.
- 개별회사 화면은 리스트를 클릭해 순회하지 않고 **URL의 순번 파라미터로 직접 이동**할 수 있는 경우가 있다(회사당 이동 1회). 다만 **순번은 현재 리스트의 정렬·필터에 종속**되므로, 리스트 조건이 바뀌면 대응 관계를 다시 확인한다. 순번을 고정 식별자로 취급하지 않는다.
- 취득 항목은 주주명·국가·Type·Direct %·Total %·Source·Date·그룹지위(GUO/Independent)까지 함께 남긴다. **Source와 Date가 없으면 뒤에 유형 판정(2-1)을 할 수 없다.**

### 3-3. 독립성 기준 설계 시 유의 (검토 라인 연동 · 중요)

비교군 지역이 해외이고 Orbis 등 해외 DB를 쓸 예정이면, **특수관계 거래액 필드가 제공되지 않아 거래 기준 독립성(특수관계 매출 비중)을 검증할 수 없다.** 따라서 실행안 단계에서부터 **지분 기준 독립성을 명시적 필터로 설계**해야 한다. 사후에 붙이면 「검색 때는 보지 않았는데 나중에 갖다 붙인」 상태가 되어 방어가 어렵다.

**BvD Independence Indicator 등급 정의**

| 등급 | 정의 |
|---|---|
| **A** (A+ · A · A−) | 직접·합산 지분 **25% 초과 주주가 없음** |
| **B** (B+ · B · B−) | 25~50% 주주는 있으나 **50% 초과 주주가 없음** |
| **C** (C+ · C) | 합산·계산합산 지분 **50% 초과** 주주 존재 |
| **D** | **직접 지분 50% 초과** 주주 존재 |
| **U** | 독립성 정도 불명 |

⚠️ **`+` / `−`는 독립성 강도가 아니라 지표의 신뢰도(정보 출처·식별된 주주 수)를 나타낸다.** A−가 A보다 덜 독립적인 것이 아니므로, +/−로 등급을 자르는 설계는 근거가 없다.

**실무 채택 기준 (표준)**

> **A+, A, A−, B+, B, B− 채택 / C+, C, D, U 배제** — 즉 **「50% 초과 지배주주가 없는 회사」**

A 계열만으로 좁히면 모집단이 과도하게 축소되어 표본 확보가 어려워진다. 25~50% 주주가 있다는 사실만으로 거래 독립성이 부정되지도 않는다. 표준보다 좁히거나 넓힐 때는 **사유를 실행안 비고에 기재**하고, comparable-search-review Phase 4의 민감도 시나리오로 검증받도록 남긴다.

이 설계가 있어야 comparable-search-review Phase 3B(T3 대리 지표 검증)에서 다음과 같은 방어 서술이 성립한다.

> 「비교가능회사 소재 관할에서는 특수관계자 거래 내역이 공개되지 않아 거래 기준 독립성을 직접 검증할 수 없다. 이에 지분 기준 독립성(Independence Indicator A·B 계열, 즉 50% 초과 지배주주 부재)을 적용하여 갈음하였으며, OECD TPG paras. 3.30~3.34가 인정하는 공개정보의 제약에 따른 것이다.」

⚠️ Independence Indicator를 필터로 쓰더라도, **개별 주주 명세를 확인해야 하는 경우에는 3-2의 표시 행수 문제가 그대로 적용**된다. 지표 등급만 보고 명세 확인을 생략하면 ②유형 누락이 검출되지 않는다.

## Step 4. 최종 실행안 (시트 8, Tap15 호환)

- Step 1(모집단)~Step N(정성 최종확정) 순으로 작성. 단계 수는 케이스에 따라 가감.
- 각 Step: 실행 항목 / 기준(확정값) / 예상·실제 기업수 / 근거(세션ID-단계ID) / 비고.
- **방법론(TP method)·PLI는 "추후결정 (Tap16 확정 후 기재)"로 유보**한다.
- 기존 Tap15 검색 실적이 있으면 단계별 기준·임계값·기업수를 전 항목 대조하고 정합/불일치를 비고에 기재한다.
- **예상 기업수를 상용 DB 조회 없이 기재한 경우** 「선례 분포 기반 추정」 또는 「미확인」임을 비고에 명시한다 (§0-2 (c) 처리).
- 해외 DB 사안은 **Independence Indicator 채택 등급을 실행안에 명시**한다(예: 「A+·A·A−·B+·B·B− 채택」).
- 주주 명세 확인이 실행안에 포함되면 **표시 행수 설정(100)과 페이지 확인 절차를 실행 항목으로 명시**한다(3-2).

## Step 5. 근거로그 (시트 9) 및 검증

- 실행안 전 Step에 대해 지식DB 근거(세션ID-단계ID) ↔ 선례 파일명 ↔ 케이스 워크북 반영 위치의 3방향 추적 로그를 작성하고 작성일·작성자를 기재한다.
- 선례의 회사별 데이터를 인용한 경우 **2-1 유형 판정 결과를 함께 기록**한다(승계인지 재취득인지).
- 수식 포함 파일은 recalc 검증(오류 0) 후 저장한다.

## Step 6. 절차 시행 로그 (docx) 생성

**엑셀 내용 전체를 전사하지 않는다** — 요약 기록이 목적이다. 포함 항목:

1. 절차 시행 일자·시간 (분 단위)
2. 케이스 식별: 케이스ID, 평가단위, Tested Party, 지식DB 버전, 템플릿 버전
3. 사전절차 결론 요약: 포함 거래, 통합/구분 결론, Tested Party 선정 사유(1줄), 특성 분류, 주 기능군
4. 채점 결과 요약: Tier1/Tier2 건수, 채택 세션ID 목록, 자기참조 점검 결과
5. 확정 기준 요약: 확정 산업코드·DB, 정량 기준유형별 확정값, **독립성 채택 등급** (표 1개)
6. 실행안 요약: Step 수, 최종 예상(또는 실적) 기업수, Tap15 대조 결과
7. 유보·특이사항: 방법론 유보 상태, [추론] 표기 항목, **§0-2로 미확인 처리한 항목과 사유**, **선례 데이터 재확인 결과(2-1 유형별 건수)**, 후속 확인 필요 사항
8. 산출 파일 경로 2건

## 금지·주의 사항

- 케이스 회사명 등 고유정보는 1_Case_Profile과 로그에만 기재하고 공용 시트에 하드코딩하지 않는다.
- 선례 인용 시 세션ID-단계ID 없는 인용 금지.
- **선례의 회사별 실측 데이터를 재확인 없이 승계 금지**(2-1). 기준·임계값 준용과 데이터 승계는 다르다.
- 워크북 원문에 없는 판단은 반드시 [추론] 표기.
- 지식DB에 없는 사전절차 선례는 케이스 Tap에서 직접 도출한다.
- **검토 게이트 체인의 고정 단계로 실행하지 않는다.**
- 본 스킬의 산출물은 **실행안**이지 확정 표본이 아니다.
- **Claude는 유료·회원제 자료원에 로그인하지 않고 자격증명을 입력하지 않는다.** 접근이 필요하면 §0-2 고지 문안으로 질문한다. 추정으로 기재한 값은 반드시 「추정」임을 표기한다.
- DB 화면의 뷰(컬럼 구성·정렬)를 임시로 바꾼 경우 **저장하지 않는다.** 공용 뷰가 바뀌면 다른 작업자의 순번·컬럼 기준이 함께 어긋난다.
