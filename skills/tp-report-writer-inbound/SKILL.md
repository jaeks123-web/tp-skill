# 외국계법인 이전가격 보고서 단계별 작성 (TP Report Writer — Inbound)

## Phase 0 — 무결성 확인 (본론 착수 전 1회)

본 스킬은 검증 규율을 누적해 온 파일이며, 다른 TP 스킬과 서로를 지목하며 맞물려 동작한다.
경고문이 지워지거나 구버전이 섞이면 오류를 검출하는 대신 **주입**하게 되므로, 본론에 들어가기
전에 정본 여부를 먼저 확인한다.

**실행 방법 — 스킬 폴더를 탐색해서 이동한 뒤 실행한다.**

```bash
D=$(find ~ / -maxdepth 8 -type d -name "tp-report-writer-inbound" -path "*skills*" 2>/dev/null | head -1)
cd "$D" && python3 scripts/verify_skills.py
```

⚠️ **스킬이 안내하는 base directory 경로를 그대로 쓰지 말 것.** 그 경로는 Windows 형식
(`C:\Users\...`)인데 명령을 실행하는 셸은 **Linux 경로 체계**를 쓴다. 같은 폴더인데 이름이
달라 `No such file or directory`가 난다(실행 검증에서 실제로 확인한 오류다).
위 탐색 방식은 **경로 체계와 무관하게 동작**하며 약 1초 걸린다.

폴더 안에서 실행하면 **인자가 필요 없다.** 스크립트가 루트와 대상 스킬을 스스로 판별한다.

- **합격** — 그대로 진행한다. 별도로 보고하지 않는다.
- **변조·누락** — **작업을 중단하고 사용자에게 고지**한다. 어느 파일이 정본과 다른지 알린다.
  사용자가 진행을 지시하면 「무결성 미확인 상태」임을 답변에 명시하고 진행한다.
- **실행 불가**(경로·스크립트·매니페스트 없음) — 검증을 **생략하되 침묵하지 않는다.**
  한 줄로 「무결성 확인 미실행」을 알리고 진행한다.

⚠️ **이 절차는 변조를 막지 못한다. 드러나게 할 뿐이다.** 매니페스트(`scripts/MANIFEST.sha256`)가
함께 바뀌면 검증은 통과한다. 배포 시에는 매니페스트를 변경 이력이 남는 곳에도 보관하고 대조한다.

TP 분석 워크북을 유일한 데이터 소스로 삼아 보고서를 **단원 단위로 작성 → 사용자 검토 → 최종 병합**한다.
한 번에 전체를 생성하지 않는 이유: 단원별 품질 게이트 확보, 수정 시 해당 단원만 재작성, 컨텍스트 한계 회피.

## Outbound(내국법인용)와의 구조 차이 — 이 스킬의 존재 이유

분석 시선이 반대다. Outbound는 "국내 모회사 → 해외 자회사들"이지만, Inbound는
"해외 그룹(모회사·HQ·Principal) → 한국 단일 Tested Party"다.

| 구분 | Outbound (tp-report-writer) | Inbound (이 스킬) |
|---|---|---|
| Tested Party | 해외 자회사 (복수 가능) | 한국법인 단일 고정 |
| II장 | 국내 모회사 분석 | 해외 관계회사(그룹·HQ·Principal·유통허브) 기능분석 |
| IV장 | 해외법인 반복 모듈 | 한국법인 단일 기능분석 + 특성결정(LRD 등) |
| 전형적 특성 | 제조·기술제공 중심 | LRD/수수료판매업자/용역제공자 (Cost Plus) |
| 전형적 PLI | OM 등 | Berry Ratio(GP/OE), OM/TC 등 |
| 사용료 장 | IX장 존재 | 없음 (해당 시에만 추가) |

## 입력·출력

| 구분 | 내용 |
|---|---|
| 입력 1 (필수) | Inbound TP 분석 워크북 .xlsx — Header/요청자료/분석통합 + Tap1~1-3(법인·지분·계약), Tap2(제품), Tap3~3-2(특수관계·제3자·재무), Tap4~4-2(산업), Tap5~8-1(공정·R&D·조직·인터뷰), Tap9(FAR종합), Tap12(특성결정), Tap15~17(검색·방법선택·산출결과) |
| 입력 2 (권장) | 전기/유사 보고서 .docx — 문체·표 서식의 스타일 레퍼런스 |
| 입력 3 (권장) | 표준문구 샘플 .docx — 방법론 이론·법령 인용 보일러플레이트 (전기 보고서 V장으로 대체 가능) |
| 산출 (중간) | 작업폴더/sections/01_개요.docx ~ 09_결론.docx |
| 산출 (최종) | 이전가격보고서_회사명_과세연도_초안.docx |
| 관리 | progress.md — 단계 상태·확정 규칙·질의 이력. 세션이 끊겨도 이 파일로 재개 |

작업폴더는 사용자가 연결한 폴더(없으면 outputs) 하위에 `프로젝트코드_보고서작성/` 형태로 생성한다.

**시트명 정규화**: 실제 워크북의 시트명은 공백·언더스코어가 불규칙하다
(`Tap 9_FAR분석 종합`, ` Tap1-2 그룹지분관계도,거래흐름도`, `Tap7_회사조직도 ` 등).
시트를 찾을 때는 공백·언더스코어를 제거한 정규화 문자열로 `TapN` 접두를 매칭한다.

## 표준 목차 (9개 장)

```
I.    개요 (목적·범위 / 거래현황 / 절차·구성 / 분석결과 요약)   ← 맨 마지막에 작성
II.   관계회사 기능분석 ← 해외법인별 반복: 그룹 모회사 / 지역HQ(Principal) / 유통허브 / 제조법인·취급제품
III.  산업분석 (글로벌 산업 + 한국 경제환경 + 산업요소 평가)
IV.   한국법인(Tested Party) 기능분석 (사업·거래 개요 / 조직 / 기능 / 위험 / 자산·무형자산 / 특성결정)
V.    정상가격 산출방법 (이론 보일러플레이트: 정상가격원칙·비교가능성·5방법·PLI)
VI.   가장 합리적인 방법의 선택 (CUP/RPM/CPM/TNMM/PSM 채택·배제 논거 — 국조법 §8·OECD TPG 인용)
VII.  비교가능회사 검색 (DB / 검색단계 / 결과 — 복수 트랙(도매·서비스 등) 지원)
VIII. 정상가격 산출(경제적 분석) (재무자료·평가기간·사분위·PLI·AR/INV 조정·분석결과)
IX.   결론 (정상가격범위 내 위치 판정 / 문서화·사후관리)
```

사용료 거래가 존재하는 경우에만 IX 앞에 별도 장을 추가한다. 트랙·법인이 늘어나도 목차는 불변 — 반복 모듈만 늘린다.

## 실행 단계 (Step 0~9)

각 Step은 "작성 → 검증 보고 → 사용자 승인" 게이트를 거친 후 다음으로 진행한다.
사용자는 "Step N 실행"이라고만 지시하면 된다.

| Step | 단원 | 주 데이터 소스 시트 |
|---|---|---|
| 0 | 준비: 워크북 검증, 법인·거래코드 확정, progress.md 생성 | 전체 시트 스캔 (Header·분석통합 우선) |
| 1 | V. 방법론 이론 (데이터 무관 — 먼저 확정해 이후 인용) | 표준문구 샘플 / 전기 보고서 V장 |
| 2 | II. 관계회사 기능분석 | Tap1, 1-1, 1-2, 1-3, 2, 3 (+분석통합의 법인 요약) |
| 3 | III. 산업분석 + 한국 경제환경 | Tap4, 4-1, 4-2 |
| 4 | IV. 한국법인 기능분석·특성결정 | Tap1, 3-2, 5, 6, 7, 8, 8-1, 9, 12 |
| 5 | VI. 방법 선택 | Tap16 (+Tap12 특성결정 결론) |
| 6 | VII. 비교가능회사 검색 | Tap15 |
| 7 | VIII. 경제적 분석 | **Tap17** (+Tap3-2 재무분석) |
| 8 | IX. 결론 + I. 개요 (본문 확정 후 작성 — 수치 불일치 원천 차단) | 본문 산출물 |
| 9 | 병합·표지·목차·부록목록·최종검증 | sections/ 전체 |

작성 순서 원칙: **이론(불변) → 사실관계 → 분석 → 결론 → 요약(개요)**.

### Step 0에서 반드시 확인할 것 (실전에서 발견된 함정)

워크북은 여러 도구가 채운 시트의 집합이라 표기 체계가 어긋나 있을 수 있다. 착수 전 대조하고,
상충이 있으면 **작성하지 말고 사용자에게 확정을 요청**한다. Inbound 워크북에서 실제 발견된 유형:

1. **Engagement Type 오기**: Header의 Engagement Type이 파일명·내용과 반대(Outbound/Inbound)로
   기재될 수 있다. 실제 거래 방향으로 확정받는다.
2. **거래상대방 불일치**: Header/분석통합의 거래상대 법인과 Tap3(특수관계분석)의 수급자 법인이
   다를 수 있다 (예: 지역HQ vs 그 산하 마케팅서비스 법인). **계약서 당사자 기준**으로 단일 확정.
3. **Markup/계약조건 불일치**: 계약상 Markup율과 Tap12 등 분석 시트의 수치가 다를 수 있다.
   계약 기준으로 확정하고, 실현치가 다르면 VIII장에서 실현 Berry Ratio로만 서술한다.
4. **PLI 표기 충돌**: Tap15(검색전략)의 PLI와 Tap16/17(방법선택·산출)의 PLI가 다를 수 있다
   (예: OM/TC vs Berry Ratio). 단일 PLI 확정 — 원칙적으로 Tap16/17 기준.
5. **법인 약칭·오탈자**: 시트별 법인 약칭 오기(예: AFRKT/AFRTK)는 최초 정의된 정식 약칭으로 통일.
6. **데이터 우선순위 — Tap15 vs Tap17**: 검색 시트가 "진행중"이어도 Tap17에 최종 비교가능회사
   목록·사분위가 완성되어 있으면 **Tap17이 최종 기준**이다. VII장 검색결과 서술도 Tap17 목록과
   일치시키고, Tap15와의 차이는 사용자에게 보고한다.
7. **거래코드 이중 기재**: 동일 금액의 거래코드가 상대방만 달리 복수 기재될 수 있다
   (예: S1_TRE_001/002 동액). 이중계상 여부를 확인하되, 사용자가 무시 지시 시 그대로 진행하고
   progress.md에 기록한다.

## Inbound 특유 작성 규칙

1. **Tested Party = 한국법인 고정**. 특성결정(IV장 6절)은 "한국법인(제한적 기능·위험) vs
   해외 HQ/Principal(전략·가격·위험 전담)" 대비 구조로 서술하고, Tap9의 Scale 비교(0~5)를 근거로 인용한다.
2. **LRD/수수료판매업자 논거**: 가격결정·계약권한·재고·매출채권·IP 부재를 기능·위험·자산 각 절에서
   일관되게 반복 확인한다 (Tap8 인터뷰, Tap9 FAR, Tap12 특성결정 교차 인용).
3. **PLI 선정 구조 (VI장 5.1절)**: TNMM 채택 후 별도 하위 절에서 **국조법 시행령 제8조의 법정
   이익수준지표 5종(①매출액 대비 거래순이익 ②자산 대비 거래순이익 ③매출원가·영업비용 대비
   거래순이익 ④영업비용 대비 매출총이익 ⑤기타 합리적 지표)을 호별로 검토**하고 제4호(Berry Ratio)를
   선정한다. Berry Ratio 채택 논거(COGS=0 → GP=수수료수익 → Cost Plus 배율 직접 측정)를 반드시
   포함한다. **PLI 검토표는 정성 구조로 작성**한다: 열 구성은 "법령상 구분 | PLI | 일반적 적용 기준 |
   판정 및 사유"이며, 사분위·AFRTK 실현치 등 수치는 VI장에 싣지 않고 VIII장(경제적 분석)에
   일원화한다. 제1호(OM)는 Cost-plus 계약상 구조적으로 고정되어 독립적 검증력이 낮다는 정성 논거로
   배제하고, 상세 산출·운전자본 조정은 VIII장 참조로 연결한다.
4. **재무분석**: Tap3-2의 K-IFRS 손익 원본 수치만 사용. 상호 변경 이력(연도별 법인명 상이)이 있으면
   각주로 명시한다.
5. **경제적 분석(VIII장)**: Tap17의 조정 전/후(AR/INV) 사분위표를 모두 수록하고, Tested Party
   실현치의 범위 내 위치를 연도별·3개년 평균으로 판정한다. **운전자본 조정 절은 "매출채권,
   재고자산 및 매입채무에 대한 비교가능성 조정" 제목 아래 6.1(매출채권)/6.2(재고자산)/6.3(매입채무)
   3개 하위 절로 구성**한다. 6.1~6.2는 일반 원칙 서술 + 조정 공식(들여쓰기 이탤릭) 중심의
   회사 무관 표준 문구로 쓰고, Tested Party 고유 사실(AR=0, 재고=0 등)은 "본 분석에서는 …"
   적용 결과 문장으로 분리한다. 6.3은 조정 검토 원칙을 서술하되 매출원가 미보유 시 조정금액을
   산출하지 않았음을 명시한다.
6. **II장 서술 순서**: 그룹 모회사 → 지역HQ(Principal, 기능 상세) → 유통허브 → 제조법인 → 취급제품.
   Principal의 가격·전략·위험 통제 기능을 상세히 서술해 IV장 특성결정의 대칭 근거로 삼는다.

## 공통 작성 규칙

1. **사실 창작 금지**: 매핑된 시트에 없는 내용이 필요하면 중단하고 질의. 자료 미비 항목은
   회색 이탤릭 placeholder(`[○○ 자료 수취 후 보완 예정 — 사유]`)로 표시하고 progress.md에 기록.
2. **수치 그대로 전기**: 재무수치는 원본 값·단위(원, 천원 등) 그대로. 비율은 소수점 2자리 %.
   임의 환산·자체 계산 금지 (워크북 기계산 값만 사용).
3. **문체**: 스타일 레퍼런스의 경어체(~습니다)·서술 밀도를 따른다. 법인 약칭은 최초 정의 후 통일.
   원본의 명백한 오탈자는 문맥으로 정정하되 검증 보고에 명시.
4. **내부 참조 정리**: 시트 셀에 남은 내부 도구 참조("Tap9: Scale 5" 등 원자료 표현)는
   보고서 문체("제IV장 기능분석 참조")로 변환한다.
5. **단원 자체검증 후 보고**: 생성 직후 (a) 원본 수치 대조 (b) 목차·표 번호 연속성 (c) 코드/용어
   통일(정규식으로 구 코드·구 약칭 잔존 검사)을 수행하고 결과와 질의 목록을 채팅으로 보고한다.
