# Inbound 특성분류 검토 게이트 (Characterization Gate — Inbound)

## Phase 0 — 무결성 확인 (본론 착수 전 1회)

본 스킬은 검증 규율을 누적해 온 파일이며, 다른 TP 스킬과 서로를 지목하며 맞물려 동작한다.
경고문이 지워지거나 구버전이 섞이면 오류를 검출하는 대신 **주입**하게 되므로, 본론에 들어가기
전에 정본 여부를 먼저 확인한다.

**실행 방법 — 스킬 폴더를 탐색해서 이동한 뒤 실행한다.**

```bash
D=$(find ~ / -maxdepth 8 -type d -name "characterization-gate-inbound" -path "*skills*" 2>/dev/null | head -1)
cd "$D" && python3 scripts/verify_skills.py
```

⚠️ **스킬이 안내하는 base directory 경로를 그대로 쓰지 말 것.** 그 경로는 Windows 형식
(`C:\Users\...`)인데 명령을 실행하는 셸은 **Linux 경로 체계**를 쓴다. 같은 폴더인데 이름이
달라 `No such file or directory`가 난다(실행 검증에서 실제로 확인한 오류다).
위 탐색 방식은 **경로 체계와 무관하게 동작**하며 약 1초 걸린다.

폴더 안에서 실행하면 **인자가 필요 없다.** 스크립트가 루트와 대상 스킬을 스스로 판별한다.

- **합격** — 그대로 진행한다. 별도로 보고하지 않는다.
- **변조·누락** — **작업을 중단하고 사용자에게 고지**한다. 어느 파일이 정본과 다른지 알린다.
  사용자가 진행을 지시하면 「무결성 미확인 상태」임을 답변에 명시하고 진행한다.
- **실행 불가**(경로·스크립트·매니페스트 없음) — 검증을 **생략하되 침묵하지 않는다.**
  한 줄로 「무결성 확인 미실행」을 알리고 진행한다.
- **`[미설치] tp-case-law`가 보이면** — 본 스킬이 조문·판례 검증을 tp-case-law에 맡기는
  부분은 실행되지 않는다. 해당 단계에서 그 사실을 고지하고, 조문 인용은 「확인 필요」로 표기한다.

⚠️ **이 절차는 변조를 막지 못한다. 드러나게 할 뿐이다.** 매니페스트(`scripts/MANIFEST.sha256`)가
함께 바뀌면 검증은 통과한다. 배포 시에는 매니페스트를 변경 이력이 남는 곳에도 보관하고 대조한다.

## 0. 기본 원칙

- **Inbound 전제 (Outbound와의 구조 차이 — 이 스킬의 존재 이유)**:
  1. **ABC_TP_Tool 미적용** — 산업요소→가치창출활동→기여율의 정량 스코어링이 없다.
     특성결정의 근거는 Tap12의 **정성적 FAR Scale 대비**(예: HQ 5 / 한국법인 0~1)다.
  2. **분석대상법인(Tested Party) = 한국 소재 외국인투자법인 단독**이 통상이다.
     복수 현지법인 반복 구조가 없으므로 평가단위 배분 검증이 아니라
     "한국법인 단일 특성의 일관성" 검증이 중심이 된다.
  3. **Tap12-1·Tap14·Tap18이 없다.** 특성결정은 Tap12, 방법·Tested Party·PLI 확정은 Tap16이
     담당한다. 따라서 본 게이트의 하류 정합 검증 대상은 Tap14가 아니라 **Tap16**이다.
- **역할**: 실무자(또는 AI 분석)가 작성한 Tap12·Tap16의 수치·논리 정합성을 **검토·자문**하며,
  **최종 판단 권한은 항상 사람에게 있다**. 본 스킬은 검증이지 특성결정 대행이 아니다.
- **게이트 원칙**: 모든 Phase는 「검토 → 발견사항 보고 → 사용자 확정」을 거친다. 확정 사항은
  `progress.md`에 기록한 후 다음 Phase로 진행한다.
- **구동 방식**: 채팅 지시어 "Phase N 실행". 순서는 0 → 1 → 2 → 3 → 4 → 5.
  순서를 건너뛰려는 요청이 있으면 선행 게이트 미통과 사실을 고지하고 사용자 확인 후 진행한다.
- **규범 쟁점**: 법령·TPG 해석이 필요하면 tp-case-law 스킬로 확인하고 출처(조문·문단 번호)와
  함께 인용한다. **조문은 반드시 표제를 병기**한다(예: 「국조법 §8(정상가격의 산출방법)」) —
  2020년 전부개정으로 번호 체계가 전면 교체되었고, 구 번호도 현행법에 실재하되 다른 내용을
  규정하므로 조번호 실재 확인만으로는 오류가 검출되지 않는다.
- **연계**: tp-report-writer-inbound Step 4(제IV장 한국법인 기능분석·특성결정)·Step 5(제VI장
  방법 선택)는 본 게이트 Phase 5 완료를 전제로 실행한다. Phase 4 산출물(Tested Party 결정
  논거 요약표)은 comparable-search-review-inbound Phase 0-B에 그대로 공급된다.
- **시트명 정규화**: Inbound 워크북의 시트명은 공백·언더스코어가 불규칙하다
  (`Tap 12_이전가격특성결정_AI`, `Tap 9_FAR분석 종합`, `Tap7_회사조직도 ` 등).
  시트를 찾을 때는 공백·언더스코어를 제거한 정규화 문자열로 `TapN` 접두를 매칭한다.

### 검토 대상 논리 사슬

```
산업분석(Tap4 계열) → 인터뷰(Tap8·8-1) → FAR분석 종합(Tap9, Scale 0~5)
  → Tap12: 기능·자산·위험 3축 Scale 대비(해외 HQ/Principal vs 한국법인)
  → Tap12 §5: Entity Characterization (한국법인 + 해외 관계회사 각각)
  → Tap16: 방법 선택(5방법 채택·배제) · Tested Party · PLI 확정
```

이 사슬의 어느 고리가 끊겨도 하류 전체(비교가능회사 검색 Tap15·경제적 분석 Tap17·보고서
IV·VI~VIII장)가 무효가 된다. Tap12와 Tap16을 하나의 게이트로 묶는 이유다.

### 참조 시트 (역할 기준 매핑)

| 역할 | 시트 (사안별 명칭 상이 가능) |
|---|---|
| 특성결정 본문 (검토 대상 1) | Tap12 이전가격특성결정 — 기능·자산·위험 비교표 + §5 특성 결론 |
| 방법·Tested Party·PLI 확정 (검토 대상 2) | Tap16 가장합리적인방법선택 |
| FAR 근거 (1차 소스) | Tap9 FAR분석 종합 (Scale 0~5) |
| 정성 근거 (모순 검증용) | Tap8·8-1 인터뷰, Tap5 생산공정, Tap6 연구개발, Tap7 조직도 |
| 거래·계약 근거 | Tap3 특수관계분석, Tap1-3 거래계약서 및 증빙, 분석통합 |
| 재무 근거 | Tap3-2 재무분석 |

시트를 찾을 수 없으면 사용자에게 위치를 질문한다.

## 1. Phase 0 — 입력물 인수 기준

검토 착수 전 아래 4종을 점검한다. **미비하면 검토를 개시하지 않고** 부족 항목을 보고한다.

1. **Inbound TP 워크북 원본 xlsx** — 수식 보존 상태(값 붙여넣기 금지).
2. **Tap12 특성결정 시트** — 분석 개요 / 기능·자산·위험 3축 비교표 / 특성 결론(§5)의 전 구조 완비.
3. **Tap9 FAR분석 종합** — Phase 1·2의 1차 소스.
4. **Tap16 방법선택 시트** — Phase 4의 검증 대상 (미완성이면 Phase 3까지만 진행 가능함을 고지).

**착수 전 확정 사항 (실전에서 발견된 함정)**:

- **Engagement Type 확인** — Header의 Outbound/Inbound 표기가 파일명·내용과 반대로 기재될 수
  있다. 실제 거래 방향(해외 그룹 → 한국 Tested Party)을 확정받는다. Outbound 사안이면 본 스킬이
  아니라 characterization-gate로 전환한다.
- **거래상대방 확정** — Header/분석통합의 거래상대 법인과 Tap3의 수급자 법인이 다를 수 있다
  (예: 지역HQ vs 그 산하 법인). **계약서(Tap1-3) 당사자 기준**으로 단일 확정.
- **법인 약칭 정본 확정** — 시트별 약칭 오기(예: AFRKT/AFRTK)는 최초 정의된 정식 약칭으로 통일.

게이트: 인수물 4종 완비 + 거래 방향·상대방·약칭 확정 → progress.md 기록.

## 2. Phase 1 — Scale·수치 표기 정합성 검증 (스크립트 전수 검증)

ABC_TP_Tool이 없으므로 Score 재계산은 존재하지 않는다. 대신 **정성 Scale과 계약 수치의
표기 정합성**을 openpyxl 등으로 전수 대조한다. 표본 검사가 아니라 **전수 대조**한다.

검증 항목 4종:

1. **Scale 대조** — Tap12 비교표의 기능·자산·위험별 Scale(예: HQ 5 / 한국법인 0~1)이
   Tap9 FAR분석 종합의 Scale과 항목별로 일치하는지. 불일치 시 어느 쪽이 정본인지 확정 대상.
2. **Scale·서술 방향 일치** — 각 행의 서술("권한 전혀 없음", "전적 통제")과 부여된 Scale의
   방향이 모순되지 않는지 (예: "권한 없음" 서술에 Scale 3 이상 부여).
3. **보상구조 수치 대조** — Tap12 분석 개요의 Markup율·보상조건이 계약서(Tap1-3)·Tap3
   거래금액·Tap3-2 실현 수치와 일치하는지.
   ⚠️ **실전 검출례**: 계약상 Cost Plus 10%인데 특정 연도 실현치(예: 18.6%)가 계약률처럼
   기재된 사안. 계약률과 실현치를 구분 표기하도록 확정한다.
4. **거래코드·금액 대조** — Tap12·16이 인용하는 거래코드(TR00n 등)와 금액이 Tap3 거래목록과
   일치하는지, 동일 금액의 이중 기재(상대방만 다른 중복 코드)가 없는지.

발견된 불일치는 **각각에 대해 사용자가 택일 확정**: ① Tap12/16을 수정 ② 근거 시트를 수정
③ 의도된 것이므로 논거 보강. 특성분류가 바뀔 수 있는 항목은 최우선 확정 대상.

게이트: 불일치 전건 사용자 확정, 대조 로그 보존.

## 3. Phase 2 — 근거 시트 일관성 검토

목적: Tap12의 정성 판정(3축 Scale 대비·특성 결론)이 워크북의 정성 근거(인터뷰·FAR·공정·조직)와
모순되지 않는지 확인한다.

**검토 방식 — 목적 지향 추출** (전수 정독 금지): Tap9 FAR 종합을 1차 소스로 읽고,
상세 시트(Tap5·6·7·8·8-1)는 요약과의 모순 검증용으로만 스캔한다.

| 검사 항목 | 대조 대상 | 모순 신호 예시 |
|---|---|---|
| 가격결정권 | Tap12 Pricing 행 vs Tap8 인터뷰 서술 | "가격 협상 권한 없음" 판정인데 인터뷰에 할인 재량 언급 |
| 계약권한 | Tap12 Contract 행 vs Tap1-3 계약서 당사자 | 계약 체결 당사자가 한국법인인데 "계약 권한 없음" 판정 |
| 재고·매출채권 | Tap12 위험·자산 행 vs Tap3-2 재무제표 | "재고 미보유·AR=0" 판정인데 재무상태표에 재고·매출채권 계상 |
| 마케팅 무형자산 | Tap12 자산 행 vs Tap6·8 서술 | "로컬 무형자산 없음" 판정인데 자체 마케팅 투자·고객DB 구축 서술 |
| 인력·조직 정합 | Tap12 기능 행 vs Tap7 조직도·인원 | "판매지원만 수행" 판정인데 조직도에 R&D·기술 부서 존재 |

모순 발견 시 근거 위치(시트·셀)를 명시해 보고한다. Scale 값 자체의 재평가는 범위 밖이며,
모순은 「발견사항 보고 → 사용자 확정」으로만 처리한다.

게이트: 검사 항목 5종 완료, 모순 전건 확정.

## 4. Phase 3 — Entity Characterization 검토

특성분류(Tap12 §5)가 기능·위험·자산 3축 판정과 정합한지 검토한다
(OECD TPG Ch.I FAR 분석, Ch.VI DEMPE, Ch.IX 사업 특성화 — 세부 인용은 tp-case-law로 확인).

1. **분류 라벨 적정성 (Inbound 라벨 사전)** — 한국법인 라벨이 3축 판정과 일치하는지:
   - **LRD (Limited Risk Distributor)**: 재고·매출채권 보유하되 가격·시장위험 제한
   - **수수료판매업자 (Commissionaire/Commission Agent)**: 재고·소유권 미이전, 수수료 보상
   - **판매지원용역제공자 (Sales Support Service Provider, Cost Plus)**: 매출채권·재고 전무,
     주문조율·시장정보 중심, COGS=0
   - **계약제조업자/임가공업자** (제조 Inbound 사안)
   경계 검사: 재고·AR 보유 여부(Tap3-2)와 라벨의 정의 요건이 어긋나는 기계적 전사 오류
   (예: 재고 미보유 법인에 LRD 라벨).
2. **대칭 논거** — 해외 HQ/Principal 측 특성(Entrepreneur/Principal, 잔여이익 귀속)이
   한국법인 특성과 거울상으로 성립하는지. 한쪽에만 기능이 배정되지 않는 "기능 공백"
   (양쪽 모두 Scale 0인 핵심 기능)이 없는지.
3. **방법 예고의 정합** — Tap12 §5의 적용 방법론 예고(TNMM·PLI 후보)가 특성분류와 모순되지
   않는지 (예: COGS=0 용역제공자에 RPM 전제의 매출총이익률 예고).
4. **경계 사례** — 판정이 갈릴 수 있는 기능(예: 시장정보 수집이 핵심 기여로 서술된 경우
   단순 용역 vs 마케팅 무형자산 기여 쟁점)은 분류가 바뀔 경우의 하류 영향(비교군·PLI)을
   정성 보고한다.

게이트: 법인별(한국법인 + 해외 관계회사) 특성분류 확정표(3축 근거 요약 포함) 사용자 확정.

## 5. Phase 4 — Tap16 정합 검증

1. **전사 일치** — Tap12 §5의 확정 특성·결론이 Tap16 분석 개요·채택 논거에 변형 없이
   반영되었는지 전수 대조 (기능 프로파일·보상구조·COGS=0 등 핵심 사실관계).
2. **방법 채택·배제 논거** — 5방법(CUP/RPM/CPM/TNMM/PSM) 채택·배제 사유가 확정된 특성분류와
   정합하는지, 법적 근거가 올바른지. **표준 인용 체계**는 다음과 같다:

   | 서술 대상 | 인용 조문 (표제 병기 필수) |
   |---|---|
   | 5방법의 법정 근거 | **국조법 §8①(정상가격의 산출방법)** 각 호 |
   | 방법 선택 논거 | **국조령 §14(정상가격 산출방법의 선택)** — ②항이 비교가능성 평가방법 |
   | 비교가능성·PLI 적합성 | **국조칙 §6(비교가능성 및 적합성 평가 등)** — ①비교가능성 7요소 ②방법별 적합성 **③PLI 선택 기준(4호 = Berry 적용요건: 「재고에 대한 부담 없이 단순 판매활동…단순 중개활동 등」)** |
   | TNMM 채택 시 PLI 5종 | **국조령 §8(거래순이익률방법)** ①각 호 |
   | 분석절차·복수연도·차이조정 | **국조령 §15(정상가격 산출방법의 적용)** — ①분석절차(칙 §7) ③다년도(칙 §9) ④차이 조정 |
   | 정상가격 범위·비교대상 「둘 이상」 | **국조령 §15⑤·⑥** (사분위 산정방식은 법령 사항 아님 — TPG 3.55~3.66) |
   | 거래 통합평가 논거 | **국조칙 §8(개별 거래 통합평가)** — 영 §15② 위임 |

   ⚠️ **국조칙 §8을 TNMM·Berry Ratio의 근거로 인용하지 않는다** — **「개별 거래 통합평가」**(영 §15②
   위임) 조문이며, 개별 거래를 통합하여 평가하는 논거를 쓸 때에만 인용한다. **이익분할방법의 적합성
   근거는 국조칙 §6②5호**(특수관계인 양쪽이 특수한 무형자산 형성에 관여하는 등 고도로 통합된 기능
   수행)이며, 방법 자체는 국조령 §9(이익분할방법)다.
   ⚠️ **「우선순위」로 서술하지 않는다** — 2010년 이후 엄격한 서열식이 아니라 「가장 합리적인
   방법」 기준으로 운영되므로, 서열이 아니라 **선택 논거**를 서술한다.
   (조문 번호는 **표제까지** tp-case-law로 확인 — 조번호 실재만으로는 오류가 검출되지 않는다.)
3. **Tested Party 선정** — 더 단순한 당사자 원칙(TPG paras. 3.18~3.19)에 따라 한국법인이

   **기계적 속단은 금지** — 논거 성립을 확인하고 예외 사안(한국법인이 복잡한 당사자인 경우)은
   별도 보고한다. 비교군 지역 = 한국(Tested Party 소재지) 확인.
4. **필수 코드·표기 체크리스트** (보고서 단계 이전 차단 목적):

   - PLI 표기 통일 — Tap12·15·16·17 간 명칭·산식 일치

   - 법인 약칭 — Phase 0 확정 약칭의 전 시트 통일

## 8. 경계 (중요)

### 사안 착수 규율 3항 (전 게이트 공통)

**1. 01(회사 원본자료) → 03(워크북) 전기 대조 조서를 인수한다.**
게이트 체인은 워크북 **내부**의 정합성만 본다. 원천에서 워크북으로 옮겨 적는 구간의 오류는
전 시트가 같은 값을 옮겨 적으므로 **내부 대조로는 원리상 검출되지 않는다**.
- 대조 조서(「원천값 → 산식 → 워크북 재기재 → 통제합계 잔액」 3블록 대조표)는
  **workbook-validator(-inbound) Phase 0-α**가 작성한다. 본 게이트는 그 조서의 **존재와 대상 범위만
  확인**하고 대조 자체를 대행하지 않는다.
- 조서가 없으면 **조건부로만 진행**하고 그 사실을 조서 첫머리에 적는다. 「대조 결과 이상 없음」이
  아니라 **「미실시」**로 적는다 — 둘은 다른 진술이다.

**2. 02 결정기록을 Phase 0에서 함께 읽는다.**
사안 폴더에 `02_결정기록*.xlsx`가 있으면 인수한다. 결정의 이유가 남지 않으면 매 회차 처음부터
재조사하게 되고 같은 쟁점이 판본마다 다르게 정리된다.
- 「채택」 행은 **재판단하지 않고 인수**한다. 재판단이 필요하면 기존 행을 고치지 않고
  **새 행(D-nn)으로 제안**한다.
- 「제외」·「미결」 항목을 **확정 사실처럼 인용하지 않는다.** 미결은 「잠정」 표기와 회사 확인요청
  번호를 함께 적는다.
- 02는 5칸(쟁점 → 대안 → 채택 → 이전가격상 이유 → 03 위치)을 유지하고, 「03 위치」는 `시트!범위`
  형식으로 적어 스크립트 대조가 가능하게 한다. **진행 경위·내부 논의·세무조사 언급은 02에 쓰지
  않는다** — 02는 제출되어도 무방한 문서로 유지한다(아래 R2).

**3. 사안 착수 규칙 R1~R4를 적용한다.**

| 규칙 | 내용 |
|---|---|
| **R1 기준연도** | 분석 기준연도 **이후**의 회사 자료(경영진 보고자료·차년도 실적)는 **참조용으로만** 읽고 분석·서술의 근거로 쓰지 않는다 |
| **R2 비인용** | 세무조사 결과·소명서·합의 내용은 02·03 어디에도 인용하지 않는다 |
| **R3 정본 경로** | 검색·산출 파일은 **지정 폴더의 것만** 쓴다. 회사 폴더의 유사 파일은 해시 대조 후 이력으로만 둔다 |
| **R4 원문 정본** | 비교가능회사 재무·감사보고서 원문은 지정 폴더 기준으로 하나만 둔다. 선행 사례 폴더는 **복사만 하고 이동·삭제·수정하지 않는다**(동결) |

⚠️ 실전 근거(Case 002 재설정): Tap3의 거래별 금액이 감사보고서 주석의 **상대방별 총액**이었고,
사용료율 3.00%는 그 오인 금액에서 **역산된 비율**이었으며, Tap3-2·3-3의 「HTO」 재무 블록은 실제로는
**다른 법인(HPO)의 자료**였다. 세 건 모두 워크북 내부에서는 완전히 일관하여 게이트 체인을 통과했다.

### 검증 규율 2항 (전 게이트 공통)

**1. 원자료를 확인하기 전에 「통제 부재」를 단정하지 않는다.**
게이트가 「통제가 없다」·「기준이 이름만 있다」·「설계가 잘못되었다」고 **판정하려면, 그 판정을
뒤집을 수 있는 원자료를 먼저 확인**한다. 집계 지표(결측률·분포·비율·공란 개수)만으로 설계
결함을 단정하지 아니한다.
- 판정을 조서에 **기재하기 전에** 「이 수치가 정상 설계에서도 나올 수 있는가」를 1회 자문한다.
- 원자료를 확인할 수 없으면 **「미확인」으로 적는다. 「없다」로 적지 않는다** — 둘은 다른 진술이다.
- 이 규율은 **발견을 줄이려는 것이 아니다.** 틀린 A등급은 진짜 A등급의 신뢰를 함께 떨어뜨린다.

**2. 다른 게이트·다른 단위의 판단을 원용할 때는 그 현재 상태를 직접 확인한다.**
「선행 게이트에서 해소되었다」·「같은 기준을 적용하였다」·「전기 조서에서 확인되었다」는 기재는
**그 자체가 검증 대상**이다. 원용하기 전에 그 판단의 현재 상태를 직접 확인하고, 확인 방법을
조서에 적는다.
- **기록과 실제는 갈릴 수 있다.** 「해소」로 적힌 것이 미해소일 수 있고, 「동일 기준」이라 적힌
  것이 실제로는 다른 기준일 수 있다.
- 확인하지 못했으면 **원용하지 않는다.** 원용을 생략하고 직접 판단하거나, 미확인 사실을 함께 적는다.

⚠️ 실전 검출례(Case 002 · **Outbound 실전례이나 같은 유형**) — 규율 1: 스코어링 보조점수를 「방문값의
재기술」로 단정한 판정이 재검정 후 철회되었다. 규율 2: 선행 게이트 조서가 「해소」로 기록한 라벨이
실제로는 미해소였다.


- 본 스킬은 특성결정의 **검증**이지 결정 대행이 아니다. Scale 값 자체의 재평가, 방법 선택(Tap16)
  논거의 신규 작성, 비교가능회사 검색은 범위 밖이다 (각각 실무자 판단, tp-report-writer-inbound
  Step 5, comparable-search-strategy / comparable-search-review-inbound의 소관).
- Tap17 수치(사분위·운전자본 조정)의 재계산은 workbook-validator-inbound 소관이다. 본 스킬은 Tap16이
  인용하는 결론 수치의 표기 일치까지만 확인한다.
- 검토 결과가 특성분류 변경을 시사하더라도 Claude가 직접 변경하지 않는다 — 하류 영향
  (비교군·PLI·검색전략)을 함께 보고하고 사용자 확정을 받는다.
- **조문 인용은 표제까지 대조한다.** 조번호만 확인하고 통과시키면 구 번호(2020년 전부개정 전)나
  표제가 다른 조문이 그대로 남는다. 확인되지 않은 조번호는 「확인 필요」로 표기하고 추정하지 않는다.
- Outbound 사안(ABC_TP_Tool·Tap12-1·Tap14 존재)은 본 스킬 범위 밖 — characterization-gate로
  전환한다.
