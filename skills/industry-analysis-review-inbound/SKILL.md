# Inbound 산업분석 검토 게이트 (Industry Analysis Review — Inbound)

## Phase 0 — 무결성 확인 (본론 착수 전 1회)

본 스킬은 검증 규율을 누적해 온 파일이며, 다른 TP 스킬과 서로를 지목하며 맞물려 동작한다.
경고문이 지워지거나 구버전이 섞이면 오류를 검출하는 대신 **주입**하게 되므로, 본론에 들어가기
전에 정본 여부를 먼저 확인한다.

**실행 방법 — 스킬 폴더를 탐색해서 이동한 뒤 실행한다.**

```bash
D=$(find ~ / -maxdepth 8 -type d -name "industry-analysis-review-inbound" -path "*skills*" 2>/dev/null | head -1)
cd "$D" && python3 scripts/verify_skills.py
```

⚠️ **스킬이 안내하는 base directory 경로를 그대로 쓰지 말 것.** 그 경로는 Windows 형식
(`C:\Users\...`)인데 명령을 실행하는 셸은 **Linux 경로 체계**를 쓴다. 같은 폴더인데 이름이
달라 `No such file or directory`가 난다(실행 검증에서 실제로 확인한 오류다).
위 탐색 방식은 **경로 체계와 무관하게 동작**하며 약 1초 걸린다.

폴더 안에서 실행하면 **인자가 필요 없다.** 스크립트가 루트와 대상 스킬을 스스로 판별한다.

- **합격** — 그대로 진행한다. 별도로 보고하지 않는다.
- **변조·누락** — **작업을 중단하고 사용자에게 고지**한다. 어느 파일이 정본과 다른지 알린다.
  사용자가 진행을 지시하면 「무결성 미확인 상태」임을 답변에 명시하고 진행한다.
- **실행 불가**(경로·스크립트·매니페스트 없음) — 검증을 **생략하되 침묵하지 않는다.**
  한 줄로 「무결성 확인 미실행」을 알리고 진행한다.
- **`[미설치] tp-case-law`가 보이면** — 본 스킬이 조문·판례 검증을 tp-case-law에 맡기는
  부분은 실행되지 않는다. 해당 단계에서 그 사실을 고지하고, 조문 인용은 「확인 필요」로 표기한다.

⚠️ **이 절차는 변조를 막지 못한다. 드러나게 할 뿐이다.** 매니페스트(`scripts/MANIFEST.sha256`)가
함께 바뀌면 검증은 통과한다. 배포 시에는 매니페스트를 변경 이력이 남는 곳에도 보관하고 대조한다.

## 0. 기본 원칙

- **전제**: Tap4(요소 평가)·Tap4-1(서술)은 AI 분석으로 생성되고 실무자가 보정한다.
  Claude는 수치·논리·사실 정합성을 **검토·자문**하며, **최종 판단 권한은 항상 사람에게 있다**.
  점수 자체의 재평가 대행이 아니라 근거·일관성의 검증이다.
- **Inbound 체계 전제**: ABC_TP_Tool을 적용하지 않으므로 조정점수가 가치사슬 Score 산식에
  곱해지지 않는다. 그러나 Tap4의 산업 판단(경쟁강도·수익성·무형자산 집중도)은
  **Tap12(특성결정)와 보고서 제III장 서술의 정성 근거**가 되므로 동일하게 사전 확정한다.
  Outbound 사안(ABC_TP_Tool·Tap12-1 존재)으로 판명되면 industry-analysis-review로 전환한다.
- **실행 시점**: Tap4 계열 완성 직후 · Tap12(이전가격특성결정) 착수 전.
- **게이트 원칙**: 각 Phase는 「검토 → 발견사항 보고 → 사용자 확정」후 `progress.md`에
  기록한다. 구동 지시어 "Phase N 실행", 순서 0 → 1 → 2 → 3 → 4.
- **규범·사실 쟁점**: 법령·TPG 해석은 tp-case-law 스킬로, 외부 경제지표·산업 통계의
  사실 확인은 웹서치로 검증하고 출처를 인용한다.
- **연계**: 본 게이트의 「산업 판단 확정표(조정점수 정본 포함)」는 characterization-gate-inbound
  Phase 0의 배경 자료가 된다. tp-report-writer-inbound Step 3(제III장 산업분석)은
  본 게이트 완료를 전제로 실행한다.

### 검토 대상 구조

```
Tap4-2 (Scale 1~5 기준 사전: 대분류 5개 × 산업요소 25개 + 수익률강도 정의)
  → Tap4 (요소별 시장강도·수익률강도 평가 + 조정점수 + Scale 근거 서술)
  → Tap4-1 (산업·경제환경 서술 + TP 시사점)
  → [하류] Tap12 특성결정·Tap16 방법선택·보고서 제III장 (산업 판단을 정성 근거로 인용)
```

## 1. Phase 0 — 인수 기준

1. **워크북 원본 xlsx** — Tap4·Tap4-1·Tap4-2 완비. **Engagement Type 확정** — Header 표기가
   실제와 반대인 실전 사례가 있으므로 거래 방향으로 확인한다 (Outbound 판명 시
   industry-analysis-review로 전환).
2. **조정점수 산식 확인** — 조정점수가 시장강도·수익률강도에서 어떻게 산출되는지
   (예: 가중평균 0.6×시장 + 0.4×수익률) 명문화된 정의를 확인. 정의가 없으면 값에서
   역산해 추정치를 제시하고 **사용자에게 산식을 확정**받는다 (산식 미기록 자체가 발견사항).
3. **ABC_TP_Tool 미적용 확인** — Inbound는 미적용이 표준이므로 스코어링 파일을 요청하지 않고,
   미적용 사실만 progress.md에 기록한다.
4. **분석대상 산업 정의 — 이중 관점 확정** — Inbound 판매지원 사안은
   ⓐ 취급 제품의 산업(예: 제지) ⓑ 한국법인의 기능 산업(판매지원·중개·서비스)
   두 관점을 확정한다. Tap4가 어느 관점으로 작성되었는지, 비교가능회사 검색(Tap15)의
   기능 관점과 어떻게 연결되는지를 명시한다.


**5. 산업 자료원 접근성 점검** — 산업지표 대조(Phase 3-1-1)에 사용할 자료원의 접근 가능 여부를 착수 시점에 확정한다.

| 자료원 | 접근 | 확인 사항 |
|---|---|---|
| 웹 공개 통계 (OECD·IMF·World Bank·각국 통계청·업종 협회) | 무료 | 해외·글로벌 산업의 1차 경로 |
| **NICE BizLINE 「산업 → 산업 요약」** | **유료·로그인 필요** | **국내 산업(KSIC 기준)**의 시장 규모·시장집중도(HHI/CR)·계량산업등급·부도/연체/휴폐업률·산업 평가의견. 접근이 필요하면 아래 고지 문안으로 질문한다 |

⚠️ **URL을 기록·재사용하지 않는다.** BizLINE의 `/workspace/...` 경로는 **세션마다 새로 생성되는 토큰**이며(실측: 같은 화면이 `7Uct`→`3zhe`로 변경) 산업코드에 대응하는 영구 링크가 아니다. **반드시 「산업 → 산업 요약」에서 대상 KSIC 코드로 직접 조회**하고, 조서에는 URL이 아니라 **조회한 KSIC 코드와 조회일**을 기록한다.

**로그인 자료원 고지 문안** — Claude는 사용자 계정으로 로그인하지 않는다. 필요 시:
```
[산업 자료원 접근 확인 필요]
① 필요 자료 : NICE BizLINE 산업 요약 — {KSIC 코드}({산업명})의 {항목}
② 사용 목적 : Phase 3 산업지표 대조 — Tap4 {시장강도/수익률강도} 근거 검증
③ 대체 가능성 : 공개 통계로 일부 대체 가능하나 HHI·계량산업등급은 BizLINE 고유
④ 선택지 (a) 직접 조회 후 값 전달 (b) 공개 통계로 우회 (c) 미확인 처리 후 한계 명시
```

게이트: 인수물 확인 + Engagement Type(Inbound) 확정 + 조정점수 산식 확정 + 산업 이중 관점 확정 + **산업 자료원 접근성 확정**.

## 2. Phase 1 — 구조·수치 정합성 (스크립트 전수 검증)

1. **요소 목록 완전성** — Tap4의 산업요소가 Tap4-2 기준 사전(표준 25개)과 1:1 대응하는지.
   누락·추가·명칭 불일치 검출. Inbound는 Tap12-1이 없으므로 대응 기준은 **Tap4-2 사전 단독**이다.
2. **점수 유효성** — 시장강도·수익률강도가 1~5 범위의 유효값인지, 대분류 배정이
   Tap4-2와 일치하는지.
3. **조정점수 재계산** — Phase 0 확정 산식으로 전 요소를 독립 재계산해 기재값과 대조.
4. **대분류 구성** — 5개 대분류(시장구조/수익성/기술·무형/생산·공급/규제·제도)별 요소 수와
   순서가 Tap4-2 구조와 일치하는지.

불일치는 각각 사용자 택일 확정(① 점수 수정 ② 기준 사전 수정 ③ 의도된 것 논거 보강).

게이트: 25개 요소 완전성 확보, 조정점수 전수 재계산 일치.

## 3. Phase 2 — Scale 기준 적용 검토

Tap4의 요소별 근거 서술이 Tap4-2 기준 사전을 올바로 적용했는지 검토한다.

1. **라벨 일치** — 서술 내 "시장 N(라벨)" 표기의 N이 시장강도 열 값과 일치하는지,
   라벨이 Tap4-2의 해당 Scale 정의와 부합하는지 (동의어 수준 차이는 허용, 등급 상이는 오류).
2. **수익률강도 판정 근거** — 수익률강도 값이 Tap4-2의 수익률강도 정의(1: 영향 없음 ~
   5: 초과이익 핵심 원천)와 실무 판정 기준에 비추어 서술과 정합하는지.
   특히 4~5점(고마진·잔여이익 요인) 부여 요소는 무형자산·DEMPE 논거와 연결되므로 중점 검토.
   **무형자산 귀속 일관성 (Inbound 핵심)**: 무형자산 집중도가 높게 평가된 산업에서 한국법인이
   판매지원업자·LRD로 특성화되는 사안은, 그 무형자산이 **해외 HQ/Principal에 귀속**된다는
   서술이 Tap4-1과 Tap12에서 일관되게 나타나는지 확인한다
   (산업의 고마진 ≠ 한국법인의 고마진 — 이 구분이 무너지면 특성결정 논거가 흔들린다).
3. **사실 근거 대조** — 서술이 인용하는 회사 사실(판매지원 구조, Cost Plus 보상, 재고·AR
   미보유, 거래 흐름 등)이 워크북 근거 시트(Tap2·3·5·8)와 모순되지 않는지
   — 목적 지향 추출로 확인.
4. **점수 간 논리 일관성** — 상충 신호 검출 (예: '무형 집중도' 상위 점수인데
   '기술 무형자산 중요성'이 하위, '대체재 존재' 낮음인데 '시장 경쟁 강도' 극심 등).
   상충은 오류 단정이 아니라 설명 요구 사항으로 보고한다.

게이트: 요소별 적용 검토표 완성, 상충 전건 확정.

## 4. Phase 3 — 서술(Tap4-1) 검토

보고서 제III장의 원천이 되는 서술의 품질을 검토한다. Inbound 제III장은
「글로벌 산업 + 한국 경제환경」 이중 구성이 표준이다.

1. **사실·수치 검증** — 외부 인용 통계(물가상승률, 기준금리, GDP 전망, 시장 규모 등)를
   웹서치로 확인: 수치의 정확성, 출처 실재, **기준 시점의 최신성**(분석기준일 대비 구 데이터
   사용 여부). **글로벌 통계와 한국 통계의 기준 시점·출처를 각각 검증**하고 결과를
   출처 링크와 함께 기록한다.
1-1. **산업지표 대조 (자료원 확보 시)** — Tap4의 시장강도·수익률강도 근거를 외부 산업지표와 대조한다.

   | 대조 항목 | 대응 Tap4 요소 | 자료원 |
   |---|---|---|
   | 시장 규모·규모 추이 | 시장강도(시장 규모·성장성) | 공개 통계 / BizLINE 「산업 규모 추이」 |
   | **시장집중도(HHI·CR)** | 시장강도(경쟁 정도) — **국조칙 §6①6호 「경제 여건: 시장의 경쟁 정도」**에 직접 대응 | BizLINE 「시장 집중도」 |
   | 계량산업등급 · 부도율/연체율/휴폐업률 | 수익률강도·산업 위험 | BizLINE 「산업 위험」 |
   | 산업 평가의견(정성 진단) | Tap4-1 서술의 사실 검증 | BizLINE 「산업 설명 — 평가의견」 |

   **대조 시 필수 확인 3종** (미확인 시 인용 금지):
   - ⓐ **산업코드 일치** — 화면에 표시된 자료가 **대상 KSIC의 것인지** 확인한다. 세분류에 대응 자료가 없으면 **상위·유사 코드 자료가 대체 표시**된다. 실측례: 대상이 **G46750**(종이 원지·판지·종이상자 도매업)인데 「NICE 최신 산업 보고서」는 **G4680000**(상품 종합 도매업), 「최신 산업 통계」는 산업명이 **「종합상사」**에 갱신일 **2015.01.12**였다. 그대로 인용하면 본 Phase가 잡아야 할 출처 불일치를 스스로 만들게 된다.
   - ⓑ **기준연월 병기** — 항목마다 기준 시점이 다르다(실측: 산업 규모 2025 / 연관 코드 2023 / 산업 위험 2026.06). **과세연도와의 정합**을 확인하고 조서에 기준연월을 함께 적는다.
   - ⓒ **관점 한계 명시** — BizLINE은 **KSIC 기준, 즉 제품 관점**만 제공한다. **기능 관점 동종회사는 보완되지 않으므로**(Phase 0 산업 이중 관점 참조) 기능 관점 근거는 별도 확보한다.

   ⚠️ **산업지표는 근거 자료이지 점수 산출기가 아니다.** 시장강도·수익률강도 Scale은 Tap4-2 기준에 따른 실무자 판단이며, 본 스킬은 **근거와의 정합성 검증까지만** 한다(§8 경계).
   ※ 기업 목록·산업 내 매출 순위·상장/외감 구분은 산업분석 소관이 아니다 — **comparable-search-review(-inbound) Phase 1B 모집단 교차검증·Phase 3B C군 발굴로 이관**한다.

2. **Tap4 점수와 논조 일치** — 서술의 강도 표현이 점수와 어긋나지 않는지
   (예: '완만한 성장' 서술 ↔ 성장률 점수, '치열한 경쟁' ↔ 경쟁강도 점수).

   **Tap16의 실제 방법 결정**과 일치하는지. 한국 경제환경 시사점(고인플레·금리 →
   비교가능성 조정 필요)이 Tap15 검색전략·Tap17 조정계산(운전자본 조정 기준금리 등)에
   실제로 반영되었는지 확인 — 반영 여부만 확인하고, 조정의 타당성 판단은

## 8. 경계 (중요)

### 사안 착수 규율 3항 (전 게이트 공통)

**1. 01(회사 원본자료) → 03(워크북) 전기 대조 조서를 인수한다.**
게이트 체인은 워크북 **내부**의 정합성만 본다. 원천에서 워크북으로 옮겨 적는 구간의 오류는
전 시트가 같은 값을 옮겨 적으므로 **내부 대조로는 원리상 검출되지 않는다**.
- 대조 조서(「원천값 → 산식 → 워크북 재기재 → 통제합계 잔액」 3블록 대조표)는
  **workbook-validator(-inbound) Phase 0-α**가 작성한다. 본 게이트는 그 조서의 **존재와 대상 범위만
  확인**하고 대조 자체를 대행하지 않는다.
- 조서가 없으면 **조건부로만 진행**하고 그 사실을 조서 첫머리에 적는다. 「대조 결과 이상 없음」이
  아니라 **「미실시」**로 적는다 — 둘은 다른 진술이다.

**2. 02 결정기록을 Phase 0에서 함께 읽는다.**
사안 폴더에 `02_결정기록*.xlsx`가 있으면 인수한다. 결정의 이유가 남지 않으면 매 회차 처음부터
재조사하게 되고 같은 쟁점이 판본마다 다르게 정리된다.
- **없으면 본 배포본의 양식을 복사해 만들도록 안내한다** — `workbook-validator/references/02_결정기록_템플릿.xlsx`
  (Inbound 사안은 `workbook-validator-inbound/references/` 아래 같은 파일). 사용법은 같은 폴더의
  `02_결정기록_템플릿_사용안내.md`에 있다. **게이트는 02를 만들지 않는다 — 읽고 인수하며, 없으면 위치를 알린다.**
  양식이 사안마다 달라지면 인수 규칙과 전달본 변환 규격을 매번 다시 써야 한다.
- 「채택」 행은 **재판단하지 않고 인수**한다. 재판단이 필요하면 기존 행을 고치지 않고
  **새 행(D-nn)으로 제안**한다.
- 「제외」·「미결」 항목을 **확정 사실처럼 인용하지 않는다.** 미결은 「잠정」 표기와 회사 확인요청
  번호를 함께 적는다.
- 02는 5칸(쟁점 → 대안 → 채택 → 이전가격상 이유 → 03 위치)을 유지하고, 「03 위치」는 `시트!범위`
  형식으로 적어 스크립트 대조가 가능하게 한다. **진행 경위·내부 논의·세무조사 언급은 02에 쓰지
  않는다** — 02는 제출되어도 무방한 문서로 유지한다(아래 R2).
- **「사용자 판정」 어휘는 채택 / 채택(잠정) / 미결 / 철회 4종으로 고정한다.** 「유지」·「표현수정」은
  채택의 하위 표기이므로 비고에 적는다. 어휘가 갈리면 종결 시 상태 축약 규칙을 사안마다 다시 쓰게 된다.
  **사안 종결 전에 판정 공란이 0이어야 한다** — 공란이면 전달본의 「확정 상태」가 빈 채로 나간다.
- **결정을 02에 적는 같은 회차에 「결정·검증 색인」도 채운다** — 검증 유형 · 수행일 · 매칭 근거(조서 위치).
  사후 작성은 조서를 거슬러 읽는 일이라 비싸고 수행일·근거의 정확도가 떨어진다(실전: 색인이 없어 25건을
  사후 작성했다). 이 색인이 종결 시 **검증확인표**의 원천이 된다(사안 종결 규율 4).

**3. 사안 착수 규칙 R1~R4를 적용한다.**

| 규칙 | 내용 |
|---|---|
| **R1 기준연도** | 분석 기준연도 **이후**의 회사 자료(경영진 보고자료·차년도 실적)는 **참조용으로만** 읽고 분석·서술의 근거로 쓰지 않는다 |
| **R2 비인용** | 세무조사 결과·소명서·합의 내용은 02·03 어디에도 인용하지 않는다 |
| **R3 정본 경로** | 검색·산출 파일은 **지정 폴더의 것만** 쓴다. 회사 폴더의 유사 파일은 해시 대조 후 이력으로만 둔다 |
| **R4 원문 정본** | 비교가능회사 재무·감사보고서 원문은 지정 폴더 기준으로 하나만 둔다. 선행 사례 폴더는 **복사만 하고 이동·삭제·수정하지 않는다**(동결) |

⚠️ 실전 근거(Case 002 재설정): Tap3의 거래별 금액이 감사보고서 주석의 **상대방별 총액**이었고,
사용료율 3.00%는 그 오인 금액에서 **역산된 비율**이었으며, Tap3-2·3-3의 「HTO」 재무 블록은 실제로는
**다른 법인(HPO)의 자료**였다. 세 건 모두 워크북 내부에서는 완전히 일관하여 게이트 체인을 통과했다.

### 검증 규율 3항 (전 게이트 공통)

**1. 원자료를 확인하기 전에 「통제 부재」를 단정하지 않는다.**
게이트가 「통제가 없다」·「기준이 이름만 있다」·「설계가 잘못되었다」고 **판정하려면, 그 판정을
뒤집을 수 있는 원자료를 먼저 확인**한다. 집계 지표(결측률·분포·비율·공란 개수)만으로 설계
결함을 단정하지 아니한다.
- 판정을 조서에 **기재하기 전에** 「이 수치가 정상 설계에서도 나올 수 있는가」를 1회 자문한다.
- 원자료를 확인할 수 없으면 **「미확인」으로 적는다. 「없다」로 적지 않는다** — 둘은 다른 진술이다.
- 이 규율은 **발견을 줄이려는 것이 아니다.** 틀린 A등급은 진짜 A등급의 신뢰를 함께 떨어뜨린다.

**2. 다른 게이트·다른 단위의 판단을 원용할 때는 그 현재 상태를 직접 확인한다.**
「선행 게이트에서 해소되었다」·「같은 기준을 적용하였다」·「전기 조서에서 확인되었다」는 기재는
**그 자체가 검증 대상**이다. 원용하기 전에 그 판단의 현재 상태를 직접 확인하고, 확인 방법을
조서에 적는다.
- **기록과 실제는 갈릴 수 있다.** 「해소」로 적힌 것이 미해소일 수 있고, 「동일 기준」이라 적힌
  것이 실제로는 다른 기준일 수 있다.
- 확인하지 못했으면 **원용하지 않는다.** 원용을 생략하고 직접 판단하거나, 미확인 사실을 함께 적는다.

⚠️ 실전 검출례(Case 002 · Outbound 실전례이나 같은 유형) — 규율 2: 산업 판단의 정본 원천이 두 곳에
기재되어 갱신이 어긋났다. 하류(Tap12·16)에 공급하기 전에 어느 쪽이 마스터인지 확인한다.

**3. 본인 또는 선행 게이트가 신설·정정한 산출물을 검증 대상에서 제외하지 아니한다.**
신설 시트·덧붙임 블록·정정 부기도 표준 체계 대비 **「추가」로 전건 열거**하고,
**누가·언제·왜 신설했는지와 그 시트가 인용되는 위치**를 함께 기록한다.
- 자기가 만든 것은 눈에 띄지 않는다. **「내가 만들었으니 맞다」가 가장 흔한 누락 사유**다.
- 선행 게이트가 만든 `IAR_*`·`CG_*`·`CSR_*`·`WV_*` 계열 시트와 실무자 요청으로 신설한 근거 시트도
  같은 규율을 적용한다 — 존재를 보고하고, 원천과 인용 위치를 적는다.

⚠️ 실전 검출례(Case 003 Inbound 재설정) — 규율 3: 게이트 2가 회사 구 워크북에서 회수해 신설한
`Tap9-1` 시트가 표준 체계(Tap1~17)에 없는 추가 시트인데도 게이트 4 「시트 완비성」 보고에서 **누락**
되었다. 검토자 본인이 만든 시트였다. 사용자 질문으로 드러났다.

### 사안 종결 규율 6항 (전 게이트 공통)

「사안 착수 규율 3항」과 짝을 이룬다. 게이트는 **「워크북이 정합한가」**를 보고, 본 규율은
**「이 문서가 밖으로 나가도 되는가」**를 본다. 어느 게이트에서 사안이 끝나든 적용한다.

**누가 수행하는가 — 문서를 내보내는 주체다.** 회계법인이 회사에 전달할 때는 회계법인이,
회사가 과세당국·감사인·모회사에 제출할 때는 회사가 수행한다. **같은 규율이고 제거 목록만 달라진다**(규율 1 말미).
⚠️ **본 배포본에는 규율만 있고 수단(export·기계 검사 도구)은 들어 있지 않다.** 게이트가 자기 산출물을
자기가 검사하면 「검증 규율 3항(자기 산출물 검증 면제 금지)」과 충돌하므로, 전달본 생성은 게이트 밖에서 한다.
스프레드시트 기능이나 별도 도구로 수행하되 **수행 사실과 검사 결과를 조서에 기록**한다 —
「규율은 읽었으나 수행하지 않았다」가 가장 흔한 실패다.

**1. 전달본(03 export)을 내부 판본에서 분리한다 — 흐름은 한 방향뿐이다.**

**정본 → export → 전달본 → 패키지.** 전달본을 직접 고치는 순간 정본이 뒤처지고,
「정본은 회계법인이 갖고 회사에는 사본을 준다」는 전제가 깨진다.
**전달본에서 발견한 것은 전달본에서 고치지 않고 정본으로 반송한다**(게이트 반송과 같은 구조).
반송 → 정본 정정 → **전달본 재생성** → 직전 전달본과의 diff가 의도한 것뿐인지 확인.

변경을 두 종류로 가른다 — **판별이 전부다.**

| | 성격 | 어디서 |
|---|---|---|
| **(가) 사실·판단의 정정** | 셀 위치 오기, 수치, 문구의 정확성, **어휘 순화**, 시트명 | **정본에서.** 전달본은 재생성 |
| **(나) 전달 형태의 변환** | 시트·열 제거, 내부 식별자 제거, 수식→값, 상태 축약, 서식 | **export 단계에서 스크립트가** |

- **어휘 순화가 (가)인 이유** — 02는 「제출되어도 무방한 문서」이므로 기밀·조사대응 어휘는
  **정본에도 있으면 안 된다.** 전달본에서만 고치면 정본이 틀린 채로 남는다.
- **「뜻을 더하는 치환」은 (나)가 아니다.** `[Phase 3B 2026-08-03]` → `[2026-08-03]`까지가 export의
  몫이고, `[감사보고서 원문 확인 2026-08-03]`으로 바꾸는 것은 **의미를 더하는 일**이므로 정본에 쓴다.
  이 경계를 지켜야 아래 반송 목록이 기계적으로 뽑힌다.
- **전달본에서 행·열을 옮기지 아니한다.** 02의 「03 반영 위치」 토큰이 통째로 어긋난다.
  레이아웃 편집은 반송 대상이 아니라 **결함**으로 본다. 예외는 **02의 위치 토큰이 가리키는 자리로
  옮긴 경우**뿐이다(그것은 정합을 맞춘 것이다).
- **export는 결정적이어야 한다.** 변환 규칙(제거 목록·치환표·시트명 규칙·서식 규칙)을 전부
  **설정 파일**로 두고 「정본 + 설정 → 산출」로 언제든 재생성되게 한다. 재생성이 두려우면
  사람이 전달본을 직접 고치게 되고 악순환이 시작된다.

**(가) 반송 목록을 뽑는 절차** — 현행 전달본·패키지본이 이미 있으면 기계적으로 뽑힌다.

```
① 정본으로 export            → 전달본(재생성)
② 재생성 ↔ 현 전달본 diff
③ 남는 차이 = (가) 반송 목록   ← (나)는 ①에서 이미 같아졌다
④ 정본에 반영 → ①로 복귀      → 「의도한 차이」만 남을 때까지
```

⚠️ 실전(Case 003): 이 절차가 **게이트를 통과한 워크북의 구값**을 찾아냈다 — Tap16 서술의
영업이익률 사분위 「0.6%~8.4%」가 같은 워크북 정본 블록(0.4% / 1.4% / 8.0%)과 달랐고,
전달본에만 고쳐져 있었다. 반송 목록은 **무엇을 반송했고 무엇을 반송하지 않았는지**를 이유와 함께 남긴다.

전달본에서 **제거**한다
- ① 정정이력 시트 — 판본별 「정정 전 → 정정 후 → 근거」 기록 전부
- ② 게이트 산출 시트 — 접두는 사안마다 다르다(`IAR_`·`CG_`·`CSR_`·`WV_`·`PILOT_` 계열,
  사안에 따라 `G1_`~`G5_`·`V6_` 등). **그 사안의 게이트 접두를 설정에 등록**하고,
  시트 제거와 토큰 검사(규율 2)가 **같은 등록값**을 쓰게 한다
- ③ 산출 원본의 「보고서 대조」 시트 — 전달본과의 차이를 항목별로 정리한 표
- ④ 보고서 정정표 — 전달본의 오류를 열거한 문서
- ⑤ 내부 식별자 — 판본번호(vNN)·게이트 번호·Phase·발견번호(`G-`·`C-`·`W-`·`I-`·`G5-`)
- ⑥ 「미검증」·「재검정」·「종전 기재가 틀렸다」·「~는 잔재였다」류 **경위 서술**
- ⑦ 02 결정기록의 내부 열 (규율 4)
- ⑧ **Phase 0-α 01→03 전기 대조표의 A블록**(회사 원본자료의 거래별 명세·원가상세·인보이스 항목) —
  워크북 시트로 남아 있다. **누구에게 내보내느냐에 따라 판단이 갈리는 유일한 항목**이다(아래 「회사판」)

전달본에 **남긴다**
- 「정본 아님(종전 산출 기준)」 표시 — 종전 표가 물리적으로 남아 있으면 오독 방지에 필요하다
- 현재 상태의 지시(어느 블록이 정본인가) — 다만 판본·게이트 번호를 떼고 적는다

⚠️ **주기 셀에 「회사에 필요한 안내」와 「내부 경위」를 한 셀에 섞지 아니한다.** 섞여 있으면
기계적으로 가를 수 없어 export가 예외 처리를 두어야 한다. **게이트가 주기를 쓸 때부터 두 셀로 나눈다.**
실전: 「※ 잠정 표시 2건은 회신 후 확정한다. [v33] 가산액을 … 교체 4.35%→4.28%」 — 앞은 남겨야 하고
뒤는 지워야 하는데 한 셀이었다.

⚠️ **시트명에 작업 접미를 붙이지 아니한다** — `_AI`·`_작업`·판본 접미. 셀 검사로는 잡히지 않고,
전달본에서만 지우면 정본이 틀린 채로 남는다. 이미 있으면 **정본에서 개명**하고 **02의 위치 토큰과
「03위치 검증」을 함께 재실행**한다(개명은 (가)다).

⚠️ **오류를 숨기는 것이 아니다.** 정정 결과는 재발행 문서 자체가 담고, 정정 경위는 회계법인이 보관한다.
회사 파일에 「무엇이 틀렸었는지」를 시계열로 남기지 아니한다. 전달본에 정정표를 넣지 않는 대신
**「갱신 예정 안내」**로 현재 상태를 알린다.
※ 「원본을 덮지 않는다」(정정은 원 시트를 덮지 않고 신설 시트·덧붙임 블록·새 버전으로 하며 원 시트는
이력으로 보존한다)는 원칙과 **충돌하지 아니한다.** 정정이력은 **만들되 내보내지 않는다** —
회계법인이 보관하고, 전달본에서만 분리한다.

**회사판 — 회사가 자기 제출본을 만들 때.** 제거 목록만 바뀌고 절차는 같다.

| | 제거 대상 |
|---|---|
| 회계법인 → 회사 | 정정이력 · 게이트 산출 시트 · 보고서 대조 시트 · 정정표 · 내부 식별자 · 경위 서술 · 02 내부 열 |
| 회사 → 과세당국·감사인 | **+ Phase 0-α 대조표 A블록(원가상세·거래별 명세) · 인터뷰 원문 · 내부 발표자료 인용** |

⚠️ **원가 재검증을 회사에 권할수록 이 분리의 필요가 커진다 — 두 문제는 같은 문제의 양면이다.**
Phase 0-α는 회사 원가상세·인보이스·원장을 워크북 시트로 남기며, **원자료를 쥔 회사가 회계법인보다 잘 돌릴 수 있는**
검증이다. 그러나 분리 수단 없이 권하면 회사가 그 워크북을 그대로 제출하게 된다.
**대조표를 만들라고 권하는 자리마다 「제출본에서는 A블록을 뺀다」를 함께 적는다.**

**2. 기계 검사 — 전 셀 텍스트를 7유형 패턴으로 훑는다.**

전달본 생성 후 **전 파일**을 대상으로 아래 7유형을 돌려 **잔여 0건**이어야 한다.
검사 대상은 공유문자열·inlineStr·수식 결과 문자열을 **전부** 포함하고, **시트명 자체도 검사한다.**

| ID | 패턴 | 뜻 |
|---|---|---|
| VER | `(?<![A-Za-z])v\d{1,2}(?![\d.])` | 내부 판본 |
| REV | `rev\d` | 보고서 판본 |
| WP | `WP\d` | 작업 단위 |
| PHASE | `Phase\s?\d` | 게이트 단계 |
| GATE | 등록된 게이트 접두 + `\b[GCWI]-\d{2}\b` · `\bG\d[-_]\d` | 게이트 산출 시트·발견번호 |
| PROC | `재실행\|재설정\|진행로그\|검토자\|게이트\|발견번호` | 경위 어휘 |
| CONF | `기밀\|정보\s?누출\|자료\s?유출\|공격 지점\|방어에 유리\|세무조사` | 결론을 수식하는 조사대응 어휘 |

- **예외는 명시 등록만 허용한다.** 현재 허용 = 근거 파일명 속 판본(`…_v3_16사.xlsx`)·연도(`FY2024`).
  「비어 있는 것이 정상」이며, 예외가 늘면 규칙이 아니라 변명이 된다.
- **GATE 패턴은 사안 설정의 게이트 접두에서 생성한다**(규율 1 ②와 같은 원천). 스킬 본문에 접두를
  박아 두면 명명이 다른 사안에서 그대로 통과한다 — 실전: `G1_`~`G5_`·`G-13`·`C-05`·`W-01`·`I-C`.
- **CONF의 경계는 「문서 종류」가 아니라 「무엇을 수식하는가」다.** 절차·기록을 수식하면 존치,
  결론·판단을 수식하면 금지. 산출물 고유명사(「방어 패키지」)는 걸리지 않게 둔다.
- 종전 정규식(`게이트|Phase\s*[0-9]|\[v[0-9]|…`)은 `v31 = v30 + …`·`rev3`·`WP5`·게이트 시트명 참조·
  경위 어휘를 놓친다. **실측 415건 중 상당수가 그 경로로 통과했다.**

**3. 내용 검사 — 정규식이 못 잡는 것을 잡는다.**

⚠️ **잔여 0건 상태에서 결함이 나왔다.** ① 02 「확정 상태」 열 공란 38/48행 ② 「03위치 검증」의
해석 시트명 23행이 전달본에 없는 시트. 둘 다 토큰 검사로는 원리상 잡히지 않는다.
전달본을 **읽기 전용**으로 검사한다 — 고치지 않는다(발견은 규율 1의 반송).

02
- 사실 필드(쟁점·검토 대안·채택·이전가격상 이유)가 정본과 **일치**
- 행수 = 정본 − 진행로그 − 철회
- 「확정 상태」 **공란 0**, 값은 확정·잠정·미결만
- 「03 반영 위치」의 해석 시트명이 **전달본 시트 목록에 실재**
- 요약 셀 = 표 집계 (정본 요약은 게이트 행을 포함하므로 **전달본 기준으로 재산출**한다)
- 검증확인표 행수·ID 집합 = 결정기록

워크북
- 게이트 시트 0 · 「안내」가 첫 시트
- **제거된 시트를 참조하는 수식 0**
- 정본 캐시값 = 전달본 값 (결론 수치 전건)
- 줄바꿈 문자가 있는 셀은 자동 줄바꿈이 켜져 있음
- 재계산(LibreOffice headless) 오류셀 0

  실전: 02가 `Tap3!A6`을 가리켰는데 정본 A6은 `—` 한 글자였고 실제 주기는 B6에 있었다.

**4. 02 결정기록의 전달본 규격.**

| 단계 | 내용 |
|---|---|
| 열 제거 | 게이트 코드·조서 참조(사안에 따라 게이트·원 발견번호) · **작성자 제안** · 표현수정 지시·비고 |
| 상태 축약 | 「사용자 판정」(날짜·주체 포함) → **「확정 상태」** = 확정 / 잠정 / 미결 |
| 행 제거 | 작성자 제안 = 「제외(진행로그)」, 사용자 판정 = 「철회」 |
| 토큰 제거 | 위치 열의 게이트 시트 토큰(전부 사라지면 「— (검증확인표 참조)」), 보고서 판본(`rev3`) |
| 시트 교체 | 「작성원칙」을 **회사판**으로 (내부 작성원칙을 내보내지 않는다) |
| 시트 생성 | **「검증확인표」** — 결정 ID · 검증 유형 · 대조한 자료 종류 · 수행일 · 수행 주체 |

- **검증확인표는 게이트 시트가 빠진 자리를 메우는 유일한 연결 수단이다.** 실측: 02→검증시트 연결의
  47%가 전달본에서 dangling 된다.
- **그 원천은 게이트가 만든다.** 각 게이트는 02에 결정을 기재할 때 같은 행(또는 색인 시트)에
  **검증 유형 · 수행일 · 매칭 근거(조서 위치)**를 함께 남긴다. 사후 작성은 조서를 거슬러 읽는 일이라
  비싸고 수행일·근거의 정확도가 떨어진다 — 실전: 색인이 없는 사안에서 25건을 사후 작성해야 했다.
  검증 유형 8종 — `원본자료 대조 (01→03)` / `재계산 (독립 재현)` / `법령·지침 원문 대조` /
  `표본 실체 확인` / `검색조건 재현·민감도` / `외부 수치 대조` / `시트 간 교차 정합` / `판단 검토 (정성)`

**5. 잠정 항목과 회사 확인요청의 대응표를 인계한다.**
workbook-validator(-inbound) Phase 4 「잠정 항목 목록」의 각 행이 **어느 회사 확인요청 번호에 걸려 있는지**를
전달패키지 안내문에 적는다. 확인요청 회신 전에는 어느 잠정 항목도 확정 문언으로 바꾸지 않는다.

**6. 정본 기준선·무결성 목록·파일명.**

- **정본 기준선을 명문으로 고지한다.** 어느 파일·어느 시트·어느 블록이 정본인지를 전달본 안내문에
  적는다. 판본·게이트 번호 없이 「현재 상태의 지시」로만 적는다(위 1의 「남긴다」).

  **종결의 마지막 단계**로 재산출한다. 패키지 파일이 하나라도 바뀌면 다시 만든다. 실측: 목록 산출 뒤
  같은 날 서식 수정이 들어가 3파일이 어긋난 채 남아 있었다.

  실제 식별자는 해시다.
- **재발행 간격을 늘리지 않는다.** 회사가 구본 위에 쌓은 작업이 많을수록 실효 통보가 아프다.
  재발행이 싸야 자주 할 수 있고, 자주 해야 사본의 포크가 깊어지지 않는다.

  구본 위에 쌓은 작업은 회사 책임으로 남는다. 대응은 구두·이메일 코멘트가 아니라 **별도 용역계약·
