# 수익성 분석 워크북 작성 (Profitability Analysis)

## Phase 0 — 무결성 확인 (본론 착수 전 1회)

본 스킬은 검증 규율을 누적해 온 파일이며, 다른 TP 스킬과 서로를 지목하며 맞물려 동작한다.
경고문이 지워지거나 구버전이 섞이면 오류를 검출하는 대신 **주입**하게 되므로, 본론에 들어가기
전에 정본 여부를 먼저 확인한다.

**실행 방법 — 스킬 폴더를 탐색해서 이동한 뒤 실행한다.**

```bash
D=$(find ~ / -maxdepth 8 -type d -name "profitability-analysis" -path "*skills*" 2>/dev/null | head -1)
cd "$D" && python3 scripts/verify_skills.py
```

⚠️ **스킬이 안내하는 base directory 경로를 그대로 쓰지 말 것.** 그 경로는 Windows 형식
(`C:\Users\...`)인데 명령을 실행하는 셸은 **Linux 경로 체계**를 쓴다. 같은 폴더인데 이름이
달라 `No such file or directory`가 난다(실행 검증에서 실제로 확인한 오류다).
위 탐색 방식은 **경로 체계와 무관하게 동작**하며 약 1초 걸린다.

폴더 안에서 실행하면 **인자가 필요 없다.** 스크립트가 루트와 대상 스킬을 스스로 판별한다.

- **합격** — 그대로 진행한다. 별도로 보고하지 않는다.
- **변조·누락** — **작업을 중단하고 사용자에게 고지**한다. 어느 파일이 정본과 다른지 알린다.
  사용자가 진행을 지시하면 「무결성 미확인 상태」임을 답변에 명시하고 진행한다.
- **실행 불가**(경로·스크립트·매니페스트 없음) — 검증을 **생략하되 침묵하지 않는다.**
  한 줄로 「무결성 확인 미실행」을 알리고 진행한다.

⚠️ **이 절차는 변조를 막지 못한다. 드러나게 할 뿐이다.** 매니페스트(`scripts/MANIFEST.sha256`)가
함께 바뀌면 검증은 통과한다. 배포 시에는 매니페스트를 변경 이력이 남는 곳에도 보관하고 대조한다.

## 0. 기본 원칙

- **범위**: 확정된 비교가능회사 표본을 전제로 **재무자료 입력 → PLI 산출 → 운전자본 조정 →
  정상가격범위 판정**까지를 수행한다. 표본의 선정·배제 타당성은 다루지 않는다.
- **살아있는 수식이 원칙**: 원자료 입력셀만 값이고 나머지는 전부 Excel 수식으로 만든다.
  차기연도 갱신·감사 대응·과세관청 자료제출 시 재사용할 수 있어야 하기 때문이다.
- **연도별과 다중연도를 병행**한다. 다중연도만 제시하면 「평균이 결과를 만들었다」는 반론을
  차단할 수 없다. 연도별로도 같은 결론이 나오는지 반드시 확인하고 기재한다.
- **모든 설계 선택은 사용자가 확정**한다(Phase 0). 특히 사분위 convention은 표본 수에 따라
  결과가 달라지므로 임의로 정하지 않는다.
- **산출 후 반드시 재계산 검증**한다(Phase 3). openpyxl은 수식을 쓰기만 하고 계산하지 않으므로
  값이 맞는지 알 수 없다.

번들 스크립트: `scripts/build_workbook.py` (CONFIG 블록만 수정하여 사용)

### ⚠️ 1.1. 사분위 convention 함정 (가장 중요)

실무 파일에 널리 쓰이는 **인접값 평균 산식**과 Excel `QUARTILE.INC`는 **표본 수에 따라
일치하기도, 갈리기도 한다.**

```
인접값 평균 산식: p = (n+2)/4 (Q1) / p = (3n+2)/4 (Q3)
                 p가 정수면 SMALL(range, p)
                 아니면 AVERAGE(SMALL(range, floor(p)), SMALL(range, ceil(p)))
```

| n | 인접값 평균 Q1 | QUARTILE.INC Q1 | 일치 여부 |
|---|---|---|---|
| 7 | 2·3번째 값 평균 | 2·3번째 값 평균 | **일치** |
| 4 | 1·2번째 값 평균 | 1번째 + 0.75×(2번째−1번째) | **불일치** |

→ **표본 수가 바뀌면 반드시 재확인**한다. 종전 파일이 n=7로 만들어졌고 표본이 4사로 줄었다면
convention이 조용히 바뀐 것이며, 보고서에 이미 인용된 수치가 어느 쪽인지 먼저 확인해야 한다.

### 1.2. 기간 비대칭 (정상적인 설계)

다음 비대칭은 오류가 아니라 의도된 설계인 경우가 많다. **그대로 두되 개요 시트에 근거를 명시**한다.

| 요소 | 전형적 기간 | 사유 |
|---|---|---|
| 비교가능회사 손익 | FY(n−2) ~ FY(n−1) 2개년 | 분석 시점에 최근 사업연도 재무자료 미공시 |
| 분석대상법인 손익 | FY(n−2) ~ FY(n) 3개년 | 자사 자료는 확보 가능 |
| 운전자본 | FY(n−3) ~ FY(n−1) 3개년 | 기초·기말 평균을 다시 복수 연도 평균 |
| 이자율 | 3개년 평균 | 기간 대응 |

※ 특정 연도 손익만 평균에서 제외되어 있다면(예: 「해당 연도는 수익성 비교가능성이 낮아 제외」)
그 사유가 원본에 기록되어 있는지 확인하고 개요 시트에 옮겨 적는다.

## 2. Phase 1 — 원자료 수집 및 검증

### 2.1. 필요 자료

| 구분 | 항목 | 단위 | 출처 |
|---|---|---|---|
| 손익 | 매출액 · 매출원가 · 판매비와관리비 | 원 | 감사보고서(DART) / 상용 DB 검색 과정표 |
| 재무상태 | 매출채권 · 재고자산 · 매입채무의 **연도말 잔액** | 원 | 감사보고서 (상용 DB 비율은 교차검증용 — 2.1.1) |
| 이자율 | 기업대출금리(신규취급액 기준) 연도별 | % | 한국은행 경제통계시스템 |

- 매출총이익·영업이익은 **입력하지 말고 수식**으로 산출한다(검산 효과).
- 상용 DB의 특수관계자거래 필드는 결측이 공란·0으로 표시되어 **거짓 통과**를 유발하므로
  판정 근거로 쓰지 않는다. 최종 표본은 감사보고서 원문으로 확인한다.

### 2.1.1. 상용 DB의 TP 비율 — 교차검증에만 사용

Orbis / TP Catalyst의 개별회사 리포트 **`Tp specific ratios`** 섹션은 아래 비율을
**10개년 시계열**로 제공한다(2026-08 실측). 리스트 컬럼으로도 취득할 수 있어 표본 전체를
한 번에 뽑을 수 있다.

| DB 제공 비율 | 본 스킬 조정 산식과의 대응 |
|---|---|
| `Receivables / Operating Revenue (%)` | **대응** — 매출채권 조정의 (AR ÷ 매출) |
| `Payables / COGS (%)` | **대응** — 매입채무 조정의 (AP ÷ 매출원가) |
| `Inventory / Total Assets (%)` | ❌ **대응하지 않는다** — 본 산식의 분모는 **매출**이다. 그대로 쓰면 재고자산 조정이 틀린다 |
| `Intangible Fixed Assets / Total Assets (%)` 등 | 조정 산식과 무관(표본 선정 단계의 지표) |

**용도는 교차검증에 한한다.** 감사보고서 연도말 잔액으로 계산한 비율이 위 값과 크게
어긋나면 입력 오류나 계정 매핑 차이를 의심한다.

**정본은 감사보고서 원자료다.** DB 비율을 조정 산식의 입력값으로 직접 대입하지 않는다 —
분모 정의(Operating Revenue vs 매출액, COGS vs 매출원가)가 회계기준·표시방법에 따라
어긋날 수 있고, 그 차이가 조정액에 그대로 전이되기 때문이다.

### 2.2. 기초잔액이 없을 때 — 역산 기법

운전자본은 **기초·기말 평균**이 필요하므로 분석 최초 연도의 **전년도말 잔액**이 있어야 한다.
검색 과정표에 없으면 종전 분석파일의 연도평균에서 역산한다.

```
전년도말 = 2 × 당해연도평균 − 당해연도말
```

**역산 후 반드시 재현 검증**한다 — 역산값으로 연도평균과 다년 평균을 다시 계산하여 종전
파일의 값과 전건 일치하는지 확인한다. 일치하면 역산이 옳고, 실제 출처는 각 사업연도
감사보고서의 **전기 비교표시 금액**이므로 그렇게 표기한다.

### 2.3. 단위 원칙

원자료는 **원 단위로 공표된 그대로** 입력하고, 분석 시트에서 `/1000`으로 천원 환산한다.
입력 단계에서 환산하면 대사(對査)가 어려워진다.

## 3. Phase 2 — 워크북 생성

`scripts/build_workbook.py`의 상단 `CONFIG` 블록(CASE · YEARS_* · PL · BS · 분석대상법인 손익 ·
RATE · CO · TOP_N · EXCL_INPUT · CROSSCHECK)만 수정하여 실행한다.

### 3.1. 시트 구성 (고정)

| 시트 | 내용 |
|---|---|
| `00_개요` | 분석 설계 · 산식 정의 · 시트 구성 · 검증 결과 |
| `01_원자료_손익` | 분석대상법인 + 비교가능회사 손익 (원 단위, 출처 표시) |
| `02_원자료_재무상태` | 비교가능회사 연도말 잔액 (원 단위, 출처 표시) |
| `03_이자율` | 연도별 및 기간 평균 |
| `04_운전자본평균` | 연도평균(기초·기말) 및 다년 평균 — 수식 |
| `05_FY(n−2)` · `06_FY(n−1)` | **연도별 분석** |
| `07_다중연도` | **다중연도 분석** |
| `08_정상범위요약` | 조정 전·후 × 연도별·다중연도 판정 + 층위별 검증 |
| `09_제외사` | 제외 회사 재무자료 및 배제 근거 (D-2에서 채택 시) |
| `10_보고서대조` | 보고서·TP 워크북 확정 수치와의 대조표 |

### 3.2. 분석 시트 레이아웃 (사내 표준 PLI 시트 형식 — 유지할 것)

```
A열: 구분코드   B열: 영문 항목명   C~E: Interquartile Range   F: Tested Party   G~: 비교가능회사
                                  (Lower / Median / Upper)      (연청색)
```

섹션 구분바(보라) 순서 — **이 순서를 바꾸지 않는다**:

1. **Profitability Ratios**

   | 코드 | 항목 |
   |---|---|
   | C/A | Gross margin |
   | 3/1 | adj. Gross margin (AR,Inv,AP) |
   | C/B | Cost-plus Markup Rate |
   | 3/2 | adj. Cost-plus Markup Rate I (AR,Inv,AP) |
   | **C/D** | **Berry Ratio** |
   | **3/4** | **adj. Berry Ratio** |
   | E/A | Operating margin |
   | 5/1 | Adj.operating margin(AR, Inv., AP) |
   | E/(B+D) | Cost Cover Ratio |
   | 5/(2+4) | adj Cost Cover Ratio(AP) |

2. **Diagnostic Ratios** — b/A×365 Days receivable · c/B×365 Days inventory ·
   j/B×365 Days payable · D/A Operating expenses/sales · (B+D)/A Total cost/sales ·
   j/B Accounts payable/cost of sales

3. **Income Statement** — A Net sales · B Cost of sales · C Gross profit ·
   D Operating expenses · E Operating profit

4. **Averaged Balance Sheet** — b 매출채권 · c 재고자산(계) · g 매입채무

5. **AR, INV, AP 조정** — 이자율 → 조정 전 매출 → AR 조정 → INV 조정 → 조정 후 매출 →
   조정 전 매출원가 → AP 조정 → 조정 후 매출원가 → 조정 후 1~5(매출·매출원가·매출총이익·영업비용·영업이익)

6. **판정** — 사분위범위 / 전 범위 / Tested Party / 판정 / 하한 대비 여유

서식: `adj.` 행은 **적색 글자**, Berry Ratio·adj. Berry Ratio 행은 **녹색 강조**,
Tested Party 열은 **연청색**, 0값은 `-`로 표시, 원자료 입력셀은 **연녹색**.

### 3.3. 산식 정본

```
Berry Ratio        = 매출총이익 ÷ 영업비용
매출채권 조정액     = [ (AR÷매출)TP − (AR÷매출)비교사 ] × 비교사 매출 × r ÷ (1+r)
재고자산 조정액     = [ (재고÷매출)TP − (재고÷매출)비교사 ] × 비교사 매출 × r
매입채무 조정액     = [ (AP÷매출원가)TP − (AP÷매출원가)비교사 ] × 비교사 매출원가 × r ÷ (1+r)
조정 후 매출        = 매출 + 매출채권 조정액 + 재고자산 조정액
조정 후 매출원가    = 매출원가 + 매입채무 조정액
adj. Berry Ratio   = (조정 후 매출 − 조정 후 매출원가) ÷ 영업비용
```

- 매출채권·매입채무는 `r/(1+r)`, 재고자산은 `r`을 적용한다(**할인계수가 다르다**).
  매출채권·매입채무는 이자상당액이 포함된 금액이므로 현재가치로 환원하기 위한 것이다.
- **재고자산 조정의 분모는 매출**이다. 상용 DB가 제공하는 `Inventory / Total Assets`와
  분모가 다르므로 그 값을 그대로 대입하지 않는다(2.1.1 참조).
- 분석대상법인이 매출원가를 보유하지 않으면 매입채무 조정의 분모가 정의되지 않으므로
  `IFERROR(...,0)`로 미적용한다. 이를 **보고서에 명시**한다(생략이 아니라 정의 불가).
- 모든 조정 수식은 **분석대상법인 열(F)에도 동일하게** 넣는다. 운전자본이 0이면 조정액도
  0이 되어 조정 전·후가 같아지므로, 수식을 빼면 조정 후 행이 공란이 되어 PLI가 0이 된다.

## 4. Phase 3 — 수식 재계산 검증

openpyxl은 계산하지 않으므로 **반드시 외부 엔진으로 재계산**한다.

```bash
soffice --headless --norestore --convert-to xlsx --outdir out <산출물>.xlsx
```

확인 항목:

| 항목 | 기준 |
|---|---|
| 오류값 스캔 | 전 시트에 `#REF!` `#NAME?` `#DIV/0!` `#VALUE!` **0건** |
| 분석대상법인 조정 전·후 | 운전자본 0이면 **동일해야 함** |
| 운전자본 평균 재현 | 연도말 잔액 → 연도평균 → 다년 평균이 원본과 일치 |
| 사분위 독립 재현 | 파이썬으로 별도 구현하여 조합 전건 대조 |
| DB 비율 교차대조 | 감사보고서 기준 AR÷매출·AP÷매출원가가 DB의 `Receivables/Operating Revenue`·`Payables/COGS`와 같은 자릿수인지(2.1.1) |

⚠️ **LibreOffice 라운드트립은 한글 폰트를 치환한다**(맑은 고딕 → Noto Sans CJK).
검증에만 쓰고 **정본은 openpyxl 산출물을 그대로 전달**한다. 계산값이 저장되지 않으므로
개요 시트에 「Excel에서 열면 자동 계산됩니다」 안내를 넣는다.

## 5. Phase 4 — 보고서 대조

`10_보고서대조` 시트에 이전가격보고서·TP 워크북의 **확정 수치를 상수로** 넣고
`=IF(ABS(계산값−확정값)<허용오차,"일치","불일치")`로 자동 판정한다.

대조 대상(최소): 비교가능회사별 adj. PLI(다중연도) · Q1 · 중앙값 · Q3 · Tested Party 실현치 ·
연도별 Q1·Q3.

전건 일치이면 **보고서 수치가 원자료로부터 재현됨**이 입증된 것이다. 불일치가 있으면
어느 쪽이 정본인지 사용자에게 확정받고, 보고서 수정과 워크북 수정 중 하나를 선택한다.

## 7. 알려진 함정

| 함정 | 증상 | 대응 |
|---|---|---|
| `QUARTILE.INC` 문자열 | Excel에서 `#NAME?` | openpyxl에서는 레거시 **`QUARTILE()`** 을 쓴다(동일 결과, 전 버전 호환) |
| 병합 셀 쓰기 | `MergedCell ... is read-only` | **값·서식을 먼저 쓰고 나중에 `merge_cells`** |
| 분석대상법인 조정행 누락 | PLI가 0으로 표시 | 조정 수식을 TP 열에도 넣는다 |
| 사분위 convention | 표본 수 변경 시 조용히 값이 달라짐 | Phase 0에서 확정, 개요 시트에 명시 |
| 기간 비대칭 | 오류로 오인하여 「수정」 | 의도된 설계인지 원본에서 확인 |
| **DB의 `Inventory/Total Assets` 오용** | 재고자산 조정액이 계통적으로 어긋남 | 본 산식의 분모는 **매출** — DB 비율을 그대로 대입하지 않는다(2.1.1) |
| 조정 전 결과가 범위 밖 | 숨기고 싶어짐 | **그대로 수록**하고 「비교 기준이 상이한 상태의 수치」임을 명시 |
| LO 폰트 치환 | 한글 폰트 깨짐 | 검증용으로만 사용 |
