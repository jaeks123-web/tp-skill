# 가치사슬·특성분류 검토 게이트 (Characterization Gate)

## Phase 0 — 무결성 확인 (본론 착수 전 1회)

본 스킬은 검증 규율을 누적해 온 파일이며, 다른 TP 스킬과 서로를 지목하며 맞물려 동작한다.
경고문이 지워지거나 구버전이 섞이면 오류를 검출하는 대신 **주입**하게 되므로, 본론에 들어가기
전에 정본 여부를 먼저 확인한다.

**실행 방법 — 스킬 폴더를 탐색해서 이동한 뒤 실행한다.**

```bash
D=$(find ~ / -maxdepth 8 -type d -name "characterization-gate" -path "*skills*" 2>/dev/null | head -1)
cd "$D" && python3 scripts/verify_skills.py
```

⚠️ **스킬이 안내하는 base directory 경로를 그대로 쓰지 말 것.** 그 경로는 Windows 형식
(`C:\Users\...`)인데 명령을 실행하는 셸은 **Linux 경로 체계**를 쓴다. 같은 폴더인데 이름이
달라 `No such file or directory`가 난다(실행 검증에서 실제로 확인한 오류다).
위 탐색 방식은 **경로 체계와 무관하게 동작**하며 약 1초 걸린다.

폴더 안에서 실행하면 **인자가 필요 없다.** 스크립트가 루트와 대상 스킬을 스스로 판별한다.

- **합격** — 그대로 진행한다. 별도로 보고하지 않는다.
- **변조·누락** — **작업을 중단하고 사용자에게 고지**한다. 어느 파일이 정본과 다른지 알린다.
  사용자가 진행을 지시하면 「무결성 미확인 상태」임을 답변에 명시하고 진행한다.
- **실행 불가**(경로·스크립트·매니페스트 없음) — 검증을 **생략하되 침묵하지 않는다.**
  한 줄로 「무결성 확인 미실행」을 알리고 진행한다.
- **`[미설치] tp-case-law`가 보이면** — 본 스킬이 조문·판례 검증을 tp-case-law에 맡기는
  부분은 실행되지 않는다. 해당 단계에서 그 사실을 고지하고, 조문 인용은 「확인 필요」로 표기한다.

⚠️ **이 절차는 변조를 막지 못한다. 드러나게 할 뿐이다.** 매니페스트(`scripts/MANIFEST.sha256`)가
함께 바뀌면 검증은 통과한다. 배포 시에는 매니페스트를 변경 이력이 남는 곳에도 보관하고 대조한다.

## 0. 기본 원칙

- **전제**: ABC_TP_Tool(스코어링 워크북)이 산업요소→가치창출활동→법인별 기여율의 정량 분석을 생성하고,
  실무자가 Tap12-1·Tap14를 작성한다. Claude는 그 결과의 수치·논리 정합성을 **검토·자문**하며,
  **최종 판단 권한은 항상 사람에게 있다**. 본 스킬은 검증이지 재스코어링 대행이 아니다.
- **게이트 원칙**: 모든 Phase는 「검토 → 발견사항 보고 → 사용자 확정」을 거친다. 확정 사항은
  `progress.md`에 기록한 후 다음 Phase로 진행한다.
- **구동 방식**: 채팅 지시어 "Phase N 실행". 순서는 0 → 1 → 2 → 3 → 4 → 5.
  순서를 건너뛰려는 요청이 있으면 선행 게이트 미통과 사실을 고지하고 사용자 확인 후 진행한다.
- **규범 쟁점**: 법령·TPG 해석이 필요하면 tp-case-law 스킬로 확인하고 출처(조문·문단 번호)와 함께 인용한다.
- **연계**: tp-report-writer Step 4~5(제IV장 기능분석)·Step 6(제VI장 방법 선택)은 본 게이트
  Phase 5 완료를 전제로 실행한다. Phase 4 산출물(Tested Party 결정 논거 요약표)은
  comparable-search-review Phase 0-B에 그대로 공급된다.

### 검토 대상 논리 사슬

```
산업분석(Tap4) → 산업요소 × 조정점수 → L2 가치창출활동 매핑(25개 연결)
  → Score = FAR × VC Scale × 조정점수 → 법인별 기여율(Share)
  → 법인별 FAR 종합(Tap9 시리즈와 대조) → Entity Characterization(Tap12-1 §3-2)
  → Tap14: 평가단위(거래 통합/구분) · 당사자 특성 전사 · Tested Party 선정
```

이 사슬의 어느 고리가 끊겨도 하류 전체(방법 선택·비교가능회사 검색·경제적 분석)가 무효가 된다.
Tap12-1과 Tap14를 하나의 게이트로 묶는 이유다.

### 참조 파일

| 파일 | 용도 |
|---|---|
| `references/workprocedure_가치사슬분석.md` | 가치창출 연계 분석의 표준 산출 형식·논리 구조 (Case 002 예시 — 수치는 사례일 뿐 기준이 아님) |
| `ABC_TP_Scoring_*.xlsx` (사안별) | 정량 기준 — 조정점수·VC Scale·FAR Scale·Score·기여율의 원본 |
| TP 워크북 (Tap 시트 체계) | Tap4(산업), Tap5·6·8·9·9-1·9-2·9-3(기능·위험 근거), Tap12·12-1(가치사슬), Tap14(평가방법 결정), Tap3(거래목록) |

파일을 찾을 수 없으면 사용자에게 위치를 질문한다. 스코어링 파일 버전이 복수이면 최신판 사용을 원칙으로 하되 Phase 0에서 확정한다.

## 1. Phase 0 — 입력물 인수 기준

검토 착수 전 아래 4종을 점검한다. **미비하면 검토를 개시하지 않고** 부족 항목을 보고한다.

1. **TP 워크북 원본 xlsx** — 수식 보존 상태(값 붙여넣기 금지).
2. **ABC_TP_Tool 스코어링 파일** — 파일명·버전 명기. 조정점수·Score·기여율의 산출 시트 포함.
3. **Tap12-1 분석문서** — 1단계(산업 의미)~3-2(특성 결정)의 전 구조 완비 여부.
4. **Tap9-3 기능·위험 요약** — Phase 2의 1차 소스.

**기준 버전 확정 (실전 교훈)**: 스코어링 파일의 조정점수와 워크북 Tap4의 실측 조정점수가 다를 수 있다
(예: Case 002에서 v2 스코어링 값과 Tap4 실측값 상이). 어느 쪽이 정본인지 **사용자에게 확정받은 후**
착수하고, 확정 결과를 모든 산출물에 기록한다.

게이트: 4종 완비 + 기준 버전 확정 → progress.md 기록.

## 2. Phase 1 — 수치 정합성 검증 (스크립트 전수 검증)

Claude가 openpyxl 등으로 원본 파일을 직접 스캔·재계산한다. 표본 검사가 아니라 **전수 대조**한다.

검증 항목 5종:

1. **조정점수 대조** — Tap4 산업요소별 조정점수 vs ABC_TP_Tool 적용값 (전 요소, Phase 0 확정 정본 기준).
2. **Score 재계산** — `Score = FAR × VC Scale × 조정점수`를 독립 재현하여 스코어링 파일 값과 대조.
3. **합계 검증** — 경로별 Share 합계 100%, L1 전략영역 합계, 법인별 기여율 합계 100%,
   L1×법인 매트릭스의 행합·열합 상호 일치.
4. **매핑 완전성** — 산업요소 ↔ L2 가치창출활동의 1:1 매핑(표준 25개 연결)에 누락·중복이 없는지,
   Anchor 코드(I·P·T 계열)가 유효한지.
5. **판정 임계값 적용** — 기능 수준 판정(상 ≥35% / 중 ≥20% / 하)이 실제 기여율과 일치하게
   적용되었는지, 임계값 근접(±3%p) 사례는 경계 사례로 별도 표기.

발견된 불일치는 **각각에 대해 사용자가 택일 확정**: ① 스코어링을 수정 ② 문서 서술을 수정
③ 의도된 것이므로 논거 보강. 기여율 순위나 특성분류가 바뀔 수 있는 항목은 최우선 확정 대상.

게이트: 불일치 전건 사용자 확정, 재계산 로그 보존.

## 3. Phase 2 — 근거 시트 일관성 검토

목적: ABC_TP_Tool의 정량 결과(주도법인·기여율)가 워크북의 정성 근거(공정·R&D·인터뷰·FAR)와
모순되지 않는지 확인한다.

**검토 방식 — 목적 지향 추출** (전수 정독 금지): Tap9-3 요약을 1차 소스로 읽고,
상세 시트(Tap5·6·8·9·9-1·9-2)는 요약과의 모순 검증용으로만 스캔한다.

| 검사 항목 | 대조 대상 | 모순 신호 예시 |
|---|---|---|
| 주도법인 배정 | L2별 주도법인 vs Tap8 인터뷰·Tap9 FAR 서술 | "영업기능 부재" 서술 법인이 채널·영업 L2의 주도법인으로 배정 |
| R&D 귀속 | Innovation 축 기여 vs Tap6 연구개발 수행 주체 | 기술을 전적으로 수입하는 법인에 높은 Innovation 기여 |
| 위험 배분 | Risk&Gov 축 기여 vs Tap8·9의 위험부담 서술 | 가격위험이 차단된(무상사급 등) 법인에 시장위험 통제 기여 |
| 설비·원가 | Ops&Cost 축 기여 vs Tap5 공정·투자 서술 | 자체 설비투자 없는 법인이 CAPEX 경로 주도 |
| DEMPE | 무형자산 판정 vs Tap6·9의 개발·활용 구조 | DEMPE 전 기능 수행 법인의 무형자산 판정이 '중' 이하 |

모순 발견 시 근거 위치(시트·셀)를 명시해 보고한다. FAR Scale 값 자체의 재평가는 범위 밖이며,
모순은 「발견사항 보고 → 사용자 확정」으로만 처리한다.

게이트: 검사 항목 5종 완료, 모순 전건 확정.

## 4. Phase 3 — Entity Characterization 검토

특성분류(Tap12-1 §3-2)가 기능·위험·무형자산(DEMPE)·기여율의 4축 판정과 정합한지 검토한다
(OECD TPG Ch.I FAR 분석, Ch.VI DEMPE, Ch.IX 사업 특성화 — 세부 인용은 tp-case-law로 확인).

1. **분류 라벨 적정성** — Entrepreneur / Licensed·Contract Manufacturer / Full-fledged
   Manufacturer / LRD 등 라벨이 4축 판정과 일치하는지. 템플릿 라벨의 기계적 전사 오류
   (예: 완전제조업자를 '판매법인' 열 라벨 그대로 특성화)를 검사한다.
2. **귀속 논리** — 잔여이익 귀속 주체·로열티 수취 논거가 DEMPE 판정과 연결되는지.
3. **방법 예고의 정합** — §3-2의 적용 방법 예고(TNMM·Tested Party·PLI 후보)가 특성분류와
   모순되지 않는지 (예: 완전제조업자에 단순 수탁제조 비교군 전제의 PLI 예고).
4. **경계 사례** — 임계값 근접 법인(Phase 1에서 이관)은 분류가 바뀔 경우의 하류 영향
   (Tested Party·비교군)을 정성 보고한다.

게이트: 법인별 특성분류 확정표(4축 근거 요약 포함) 사용자 확정.

## 5. Phase 4 — Tap14 정합 검증

1. **전사 일치** — Tap12-1 §3-2의 확정 특성이 Tap14 §3.1에 변형 없이 전사되었는지 전수 대조.
2. **거래 통합/구분** — 체크리스트 판단이 Tap3 거래목록과 일치하는지, 통합 논거가
   국조령·TPG paras. 3.9~3.12 수준에서 성립하는지.
3. **Tested Party 선정** — 더 단순한 당사자 원칙(TPG paras. 3.18~3.19) 적용의 타당성.
   ⚠️ **실전 교훈**: 완전제조업 현지법인 사안은 거래상대방(모회사) 측이 Tested Party로 선택될 수
   있고, 그 경우 **비교군 지역 = 모회사 소재지**. 검증대상을 현지법인으로 속단하지 말 것.
4. **필수 코드 체크리스트** (보고서 단계 이전 차단 목적):
   - 거래코드 체계 — Tap3/14의 TRE_00n vs Tap16 서술의 TR00n 대응표 확정
   - 평가단위 코드 vs 법인코드 중복·충돌 (예: G1이 법인이자 평가단위)
   - 거래방향 — 사용료 등 방향이 시트 간 반대로 기재되지 않았는지
   - PLI 명칭 — Tap14·16·17·18 간 표기 통일

**산출물 — 「Tested Party 결정 논거 요약표」** (평가단위별): 분석대상 거래 → 양 당사자 기능
프로파일(단순 vs 복잡) → Tested Party와 근거 → PLI → 비교군 지역 → FAR상 통제 방향.
이 요약표가 comparable-search-review Phase 0-B의 입력으로 그대로 공급된다.

게이트: 전사 일치 + 코드 체크리스트 전건 확정 + 요약표 사용자 확정.

## 6. Phase 5 — 문서화·게이트 확정

확정 내용을 검토조서로 고정한다. **검토조서 구성 5종**:

1. Phase 1 수치검증 로그 (재계산 결과·불일치 처리 내역)
2. Phase 2 모순 목록과 해소 내역 (근거 시트·셀 명시)
3. 법인별 특성분류 확정표 (4축 근거 요약)

## 8. 경계 (중요)

### 사안 착수 규율 3항 (전 게이트 공통)

**1. 01(회사 원본자료) → 03(워크북) 전기 대조 조서를 인수한다.**
게이트 체인은 워크북 **내부**의 정합성만 본다. 원천에서 워크북으로 옮겨 적는 구간의 오류는
전 시트가 같은 값을 옮겨 적으므로 **내부 대조로는 원리상 검출되지 않는다**.
- 대조 조서(「원천값 → 산식 → 워크북 재기재 → 통제합계 잔액」 3블록 대조표)는
  **workbook-validator(-inbound) Phase 0-α**가 작성한다. 본 게이트는 그 조서의 **존재와 대상 범위만
  확인**하고 대조 자체를 대행하지 않는다.
- 조서가 없으면 **조건부로만 진행**하고 그 사실을 조서 첫머리에 적는다. 「대조 결과 이상 없음」이
  아니라 **「미실시」**로 적는다 — 둘은 다른 진술이다.

**2. 02 결정기록을 Phase 0에서 함께 읽는다.**
사안 폴더에 `02_결정기록*.xlsx`가 있으면 인수한다. 결정의 이유가 남지 않으면 매 회차 처음부터
재조사하게 되고 같은 쟁점이 판본마다 다르게 정리된다.
- 「채택」 행은 **재판단하지 않고 인수**한다. 재판단이 필요하면 기존 행을 고치지 않고
  **새 행(D-nn)으로 제안**한다.
- 「제외」·「미결」 항목을 **확정 사실처럼 인용하지 않는다.** 미결은 「잠정」 표기와 회사 확인요청
  번호를 함께 적는다.
- 02는 5칸(쟁점 → 대안 → 채택 → 이전가격상 이유 → 03 위치)을 유지하고, 「03 위치」는 `시트!범위`
  형식으로 적어 스크립트 대조가 가능하게 한다. **진행 경위·내부 논의·세무조사 언급은 02에 쓰지
  않는다** — 02는 제출되어도 무방한 문서로 유지한다(아래 R2).

**3. 사안 착수 규칙 R1~R4를 적용한다.**

| 규칙 | 내용 |
|---|---|
| **R1 기준연도** | 분석 기준연도 **이후**의 회사 자료(경영진 보고자료·차년도 실적)는 **참조용으로만** 읽고 분석·서술의 근거로 쓰지 않는다 |
| **R2 비인용** | 세무조사 결과·소명서·합의 내용은 02·03 어디에도 인용하지 않는다 |
| **R3 정본 경로** | 검색·산출 파일은 **지정 폴더의 것만** 쓴다. 회사 폴더의 유사 파일은 해시 대조 후 이력으로만 둔다 |
| **R4 원문 정본** | 비교가능회사 재무·감사보고서 원문은 지정 폴더 기준으로 하나만 둔다. 선행 사례 폴더는 **복사만 하고 이동·삭제·수정하지 않는다**(동결) |

⚠️ 실전 근거(Case 002 재설정): Tap3의 거래별 금액이 감사보고서 주석의 **상대방별 총액**이었고,
사용료율 3.00%는 그 오인 금액에서 **역산된 비율**이었으며, Tap3-2·3-3의 「HTO」 재무 블록은 실제로는
**다른 법인(HPO)의 자료**였다. 세 건 모두 워크북 내부에서는 완전히 일관하여 게이트 체인을 통과했다.

### 검증 규율 3항 (전 게이트 공통)

**1. 원자료를 확인하기 전에 「통제 부재」를 단정하지 않는다.**
게이트가 「통제가 없다」·「기준이 이름만 있다」·「설계가 잘못되었다」고 **판정하려면, 그 판정을
뒤집을 수 있는 원자료를 먼저 확인**한다. 집계 지표(결측률·분포·비율·공란 개수)만으로 설계
결함을 단정하지 아니한다.
- 판정을 조서에 **기재하기 전에** 「이 수치가 정상 설계에서도 나올 수 있는가」를 1회 자문한다.
- 원자료를 확인할 수 없으면 **「미확인」으로 적는다. 「없다」로 적지 않는다** — 둘은 다른 진술이다.
- 이 규율은 **발견을 줄이려는 것이 아니다.** 틀린 A등급은 진짜 A등급의 신뢰를 함께 떨어뜨린다.

**2. 다른 게이트·다른 단위의 판단을 원용할 때는 그 현재 상태를 직접 확인한다.**
「선행 게이트에서 해소되었다」·「같은 기준을 적용하였다」·「전기 조서에서 확인되었다」는 기재는
**그 자체가 검증 대상**이다. 원용하기 전에 그 판단의 현재 상태를 직접 확인하고, 확인 방법을
조서에 적는다.
- **기록과 실제는 갈릴 수 있다.** 「해소」로 적힌 것이 미해소일 수 있고, 「동일 기준」이라 적힌
  것이 실제로는 다른 기준일 수 있다.
- 확인하지 못했으면 **원용하지 않는다.** 원용을 생략하고 직접 판단하거나, 미확인 사실을 함께 적는다.

⚠️ 실전 검출례(Case 002) — 규율 1: 「보조점수는 방문실사값의 재기술이고 0점에 바닥값을 부여했다」는
주장이 **순위 분할 검정 후 3건 중 2건 철회**되었다(방문 추종 28% vs 측정값 추종 26%로 독립, 척도
차이는 구조적, HO 방문 0점 91건 중 54건에 측정값 존재 — 보완 설계가 의도대로 작동). 규율 2: CG_4가
「해소」로 기록한 구 평가단위 라벨이 실제로는 **7개소 미해소**였다.

**3. 본인 또는 선행 게이트가 신설·정정한 산출물을 검증 대상에서 제외하지 아니한다.**
신설 시트·덧붙임 블록·정정 부기도 표준 체계 대비 **「추가」로 전건 열거**하고,
**누가·언제·왜 신설했는지와 그 시트가 인용되는 위치**를 함께 기록한다.
- 자기가 만든 것은 눈에 띄지 않는다. **「내가 만들었으니 맞다」가 가장 흔한 누락 사유**다.
- 선행 게이트가 만든 `IAR_*`·`CG_*`·`CSR_*`·`WV_*` 계열 시트와 실무자 요청으로 신설한 근거 시트도
  같은 규율을 적용한다 — 존재를 보고하고, 원천과 인용 위치를 적는다.

⚠️ 실전 검출례(Case 003 Inbound 재설정) — 규율 3: 게이트 2가 회사 구 워크북에서 회수해 신설한
`Tap9-1` 시트가 표준 체계(Tap1~17)에 없는 추가 시트인데도 게이트 4 「시트 완비성」 보고에서 **누락**
되었다. 검토자 본인이 만든 시트였다. 사용자 질문으로 드러났다.

### 사안 종결 규율 3항 (전 게이트 공통)

「사안 착수 규율 3항」과 짝을 이룬다. 게이트는 **「워크북이 정합한가」**를 보고, 본 규율은
**「이 문서가 밖으로 나가도 되는가」**를 본다. 어느 게이트에서 사안이 끝나든 적용한다.

**1. 전달본(03 export)을 내부 판본에서 분리한다.**

전달본에서 **제거**한다
- ① 정정이력 시트 — 판본별 「정정 전 → 정정 후 → 근거」 기록 전부
- ② 게이트 산출 시트 (`IAR_`·`CG_`·`CSR_`·`WV_`·`PILOT_` 계열)
- ③ 산출 원본의 「보고서 대조」 시트 — 전달본과의 차이를 항목별로 정리한 표
- ④ 보고서 정정표 — 전달본의 오류를 열거한 문서
- ⑤ 내부 식별자 — 판본번호(vNN)·게이트 번호·Phase·발견번호(G-·C-·W-·G5-)
- ⑥ 「미검증」·「재검정」·「종전 기재가 틀렸다」·「~는 잔재였다」류 **경위 서술**
- ⑦ 02 결정기록의 「게이트」·「원 발견번호」 열

전달본에 **남긴다**
- 「정본 아님(이력)」 표시 — 종전 표가 물리적으로 남아 있으면 오독 방지에 필요하다
- 현재 상태의 지시(어느 블록이 정본인가) — 다만 판본·게이트 번호를 떼고 적는다

**기계 검사** — 전달본 생성 후 **전 파일**을 대상으로 아래 정규식을 돌려 **잔여 0건**이어야 한다.
```
게이트|Phase\s*[0-9]|\[v[0-9]|\b[GCW]-[0-9]{2}\b|G5-[0-9]{2}|정정이력|미검증|재검정|정정 전|종전 기재|보고서 대조
```

⚠️ **오류를 숨기는 것이 아니다.** 정정 결과는 재발행 문서 자체가 담고, 정정 경위는 회계법인이 보관한다.
회사 파일에 「무엇이 틀렸었는지」를 시계열로 남기지 아니한다. 전달본에 정정표를 넣지 않는 대신
**「갱신 예정 안내」**로 현재 상태를 알린다.
※ 「원본을 덮지 않는다」(정정은 원 시트를 덮지 않고 신설 시트·덧붙임 블록·새 버전으로 하며 원 시트는 이력으로
보존한다)는 원칙과 **충돌하지 아니한다.** 정정이력은 **만들되 내보내지 않는다** — 회계법인이 보관하고,
전달본에서만 분리한다.

**2. 잠정 항목과 회사 확인요청의 대응표를 인계한다.**
workbook-validator(-inbound) Phase 4 「잠정 항목 목록」의 각 행이 **어느 회사 확인요청 번호에 걸려 있는지**를
전달패키지 안내문에 적는다. 확인요청 회신 전에는 어느 잠정 항목도 확정 문언으로 바꾸지 않는다.

**3. 정본 기준선을 명문으로 고지한다.**
어느 파일·어느 시트·어느 블록이 정본인지를 전달본 안내문에 적는다. 판본·게이트 번호 없이,
「현재 상태의 지시」로만 적는다(위 1의 「남긴다」).

⚠️ 실전 검출례(Case 003 Inbound 재설정): 전달본 워크북에 `V6_정정이력` 시트(94셀)가 그대로 들어갔다.
ⓐ 전달 보고서의 근거가 자기모순이었다는 기록 ⓑ 정상가격범위 하한 여유가 좁아진 경위 ⓒ 법령 오인용 이력
ⓓ 확정되지 않은 불리한 잠재 쟁점이 한 화면에 시계열로 정리되어 있었다. **어느 게이트도 검출하지 않았고
사용자 지적으로 발견되었다.** 같은 유형이 산출 원본 `11_보고서대조` 시트·보고서 정정표·02의 「원 발견번호」
열·전 시트의 내부 식별자 141셀에 있었고, Case 002(호원) 전달패키지에도 동일 유형(워크북 67셀·02 15셀·
산출 원본·과정표 11셀)이 확인되었다.


- 본 스킬은 스코어링·특성분류의 **검증**이지 결정 대행이 아니다. FAR Scale·VC Scale 값 자체의
  재평가, 방법 선택(Tap16) 논거 작성, 비교가능회사 검색은 범위 밖이다 (각각 실무자 판단,
  Tap16 프롬프트, comparable-search-strategy/review의 소관).
- 참조 workprocedure의 수치(기여율 44.0% 등)는 Case 002 예시이며 판단 기준이 아니다.
  판단 기준은 항상 해당 사안의 스코어링 파일과 워크북이다.
- 검토 결과가 특성분류 변경을 시사하더라도 Claude가 직접 변경하지 않는다 — 하류 영향
  (Tested Party·비교군·방법)을 함께 보고하고 사용자 확정을 받는다.
