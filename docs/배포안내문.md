# TP 스킬 플러그인 설치 안내

**tp-skills v1.5.0 — 스킬 13종** · Lim TP Technology · 2026년 9월

이 문서는 한 장짜리 설치 안내입니다. 스킬을 실제로 쓰는 방법은 **『TP 스킬 사용 설명서 v1.5.0』**을 보십시오.

---

## 0. 이번 판에서 실무가 달라지는 점 — 먼저 읽어 주십시오

설치 방법은 전과 같습니다. 다만 이번 판은 **사안을 끝내는 방법**이 새로 정해진 판입니다. v1.4.0이 「워크북에 들어오는 숫자」를 잡았다면, v1.5.0은 **「회사로 나가는 파일」**을 봅니다. 셋만 기억하시면 됩니다.

**① 회사에 보내는 전달본은 내부 판본과 분리해서 따로 만듭니다.**
정정이력 시트, 게이트가 만든 시트(`IAR_`·`CG_`·`CSR_`·`WV_` 계열), 산출 원본의 「보고서 대조」 시트, 보고서 정정표, 판본번호·게이트 번호·발견번호 같은 **내부 식별자**, 「미검증」·「종전 기재가 틀렸다」류의 **경위 서술**은 전달본에서 뺍니다. 게이트가 전달본 전 파일을 정규식으로 훑어 **잔여 0건**인지 셉니다(사안 종결 규율).

> 왜 생겼는가 — 어떤 사안에서 전달본 워크북에 **정정이력 시트(94셀)**가 그대로 들어갔습니다. 전달 보고서의 근거가 자기모순이었다는 기록, 정상가격범위의 여유가 좁아진 경위, 법령 오인용 이력, 확정되지 않은 불리한 쟁점이 한 화면에 시계열로 정리되어 있었고, 어느 게이트도 잡지 않았습니다. **오류를 숨기는 것이 아닙니다.** 정정 결과는 재발행 문서가 담고, 경위는 회계법인이 보관합니다. 정정이력은 **만들되 내보내지 않습니다.**

**② 워크북에 「정본」 표시가 둘이면 그 자체로 [등급 A]입니다.**
표본이 같아도 기간·원천·조정 적용이 다른 블록이 나란히 있으면 정본을 하나로 확정해야 합니다. 판본 사이에 바뀐 숫자가 **다른 시트의 표에 남아 있어도** [등급 A]입니다(숫자 셀까지 전 시트를 스캔합니다). 그리고 **새로 만든 시트는 누가·언제·왜 만들었는지** 적어야 합니다 — 검토자가 직접 만든 시트도 예외가 아닙니다.

> 실제로 표본이 같은 두 블록에 **둘 다 「[정본]」**이 붙어 있었고, 정정이 한 시트의 4개 셀에만 적용되어 **6개소가 구 수치**로 남은 채 보고서에 전기된 일이 있었습니다.

**③ 판례는 인용 방향부터, 「자료 미확보」는 원문으로 확인한 뒤에만.**
판례를 인용하기 전에 **납세자가 이겼는지 과세관청이 이겼는지, 우리가 채택한 방법을 그 사건이 인정했는지 부정했는지**를 먼저 봅니다. 사실관계가 비슷할수록 방향이 반대일 때의 손해가 큽니다. 「미공시」·「DB에 없음」·「분석 당시 확보되지 않아」라는 기재는 **그 자체가 검증 대상**이며, DART 원문으로 반증한 뒤에만 인정됩니다.

> 판매지원용역·Berry Ratio 사안을 **채택 논거로** 인용했는데 그 사건이 반대 취지였던 예, 「FY2025 자료 미확보」라고 적혀 있었으나 4사 전건이 이미 공시되어 있던 예가 있었습니다.

> 예전 판본에서 통과한 사안을 다시 돌리면 새 [등급 A]가 잡힐 수 있습니다 — **결함이 아니라 판본 차이**입니다. 자세한 것은 사용 설명서 **§6.6·§6.7**과 **§8.10**에 있습니다. 진행 중인 사안이 있으시면 **그 절만이라도 먼저** 봐 주십시오.

## 1. 받으신 파일

파일 이름에 **본인 성함**이 붙어 있습니다.

| 파일 | 용도 |
|---|---|
| `tp-skills_홍길동.plugin` | **설치하는 파일.** 이것 하나만 설치하시면 됩니다 |
| `tp-skills_홍길동.plugin.sha256` | 파일이 도중에 바뀌지 않았는지 확인하는 값 |

> **왜 이름이 붙어 있는가** — 배포본은 **수령자마다 다른 사본**입니다. 안에 수령자 표식(`RECIPIENT.txt`)이 들어 있고, 그래서 파일 전체의 해시도 사람마다 다릅니다. **스킬의 동작에는 아무 영향이 없습니다.**
>
> 이 사본은 **본인에게만 제공된 것**입니다. 다른 사람에게 전달하지 마십시오. 필요한 분이 있으면 관리자에게 요청하시면 그분 이름의 사본을 발급합니다.

**필요 조건** — 유료 플랜(Pro·Max·Team·Enterprise) + Claude 데스크톱 앱 또는 Cowork.
**무료 플랜에서는 플러그인이 설치되지 않습니다.**

---

## 2. 설치 (5단계)

1. Cowork를 쓰신다면 **「Cowork」 탭**을 엽니다.
2. 왼쪽 사이드바에서 **「Customize」**를 엽니다.
3. **「Plugins」 탭**으로 이동합니다.
4. **「+」 버튼** → 커스텀 플러그인 파일 업로드 → **본인 이름이 붙은 `.plugin`** 선택.
5. 목록에 `tp-skills`가 나타나면 완료입니다.

> **먼저 지워야 할 것이 있습니다.** 같은 이름의 스킬을 **개별로** 설치해 두셨다면 Customize → Skills에서 지운 뒤 플러그인만 남기십시오. 두 벌이 남으면 **구버전이 섞여** 동작합니다. 이전 버전 플러그인(v1.4.0 이하)도 마찬가지로 먼저 제거하십시오.

---

## 3. 설치 확인 — 두 가지

**① 버전** — Customize → Plugins의 `tp-skills` 항목이 **`1.5.0`**으로 보이면 정상입니다.

**② 스킬 목록** — 대화창에서 **「/」**를 입력하면 `tp-case-law`·`workbook-validator` 등 **13종**이 보입니다.

---

## 4. 정본 확인 — 받은 파일이 진짜인가

설치 **전에** PowerShell에서 한 줄이면 됩니다. 파일이 있는 폴더에서(파일명은 본인 것으로):

```
Get-FileHash .\tp-skills_홍길동.plugin -Algorithm SHA256 | Format-List
```

출력된 `Hash` 값이 함께 받으신 **`.sha256` 파일의 내용과 같아야** 합니다.

**다르면 설치하지 마시고 관리자에게 연락하십시오.**

> **왜 이걸 하는가** — 파일이 전달 과정에서 깨지거나 바뀌었는지 보는 절차입니다. 값이 조금이라도 다르면 다른 파일입니다.
>
> **값은 사람마다 다릅니다.** 수령자별 사본이므로 동료의 값과 비교하시면 당연히 다릅니다. 반드시 **본인이 받은 `.sha256`**과 대조하십시오.
>
> **한 가지 더** — 해시 값과 플러그인 파일을 **같은 경로로** 받으셨다면, 그 확인은 「깨지지 않았다」까지만 보증합니다. 출처가 의심스러운 상황이라면 관리자에게 **다른 통로**(메신저·전화)로 값을 재확인하십시오.

## 5. 설치 후에는 자동으로 확인됩니다

각 스킬은 본격 작업에 들어가기 전에 **자기 파일이 정본과 같은지 스스로 확인**합니다(Phase 0 무결성 확인).

| 상황 | 표시 | 하실 일 |
|---|---|---|
| 정상 | **아무 말 없이 진행** | 없음 |
| 파일이 다름 | 「무결성 확인 — 변조·누락」 | **작업 중단 → 관리자 연락 → 재설치** |
| 확인 못 함 | 「무결성 확인 미실행」 | 중요한 산출물이면 재설치 후 다시 실행 |
| 공통 스킬 없음 | 「[미설치] tp-case-law」 | 그 답변의 **조문 인용은 미확인 상태**입니다. 플러그인 전체 재설치 |

## 6. 하지 말아야 할 것

- **스킬 파일을 직접 수정하지 마십시오.** 검증 규율이 누적된 파일이고, 수정하면 무결성 확인에서 「변조」로 검출됩니다. 개선 의견은 관리자에게 주시면 정본 저장소에 반영한 뒤 새 버전으로 배포합니다.
- **개별 스킬과 플러그인을 같이 두지 마십시오.** 어느 쪽이 동작할지 알 수 없습니다.
- **받으신 사본을 다른 사람에게 전달하지 마십시오.** 사내·사외를 가리지 않습니다. 배포본에는 **수령자 표식**이 들어 있어 사후에 출처를 확인할 수 있습니다. 필요한 분은 관리자에게 요청하시면 그분 이름의 사본을 발급받습니다.
- **`RECIPIENT.txt`를 지우지 마십시오.** 동작과 무관한 파일이며, 삭제하면 그 자체가 기록으로 남습니다.
- **내부 판본을 그대로 회사에 보내지 마십시오.** 〔v1.5.0〕 전달본은 §0 ①대로 따로 만들고, 게이트의 잔여 검사가 0건인 것을 확인한 뒤 보냅니다.
