# TP 스킬 플러그인 설치 안내

**tp-skills v1.6.0 — 스킬 13종** · Lim TP Technology · 2026년 9월

이 문서는 한 장짜리 설치 안내입니다. 스킬을 실제로 쓰는 방법은 **『TP 스킬 사용 설명서 v1.6.0』**을 보십시오.

---

## 0. 이번 판에서 실무가 달라지는 점 — 먼저 읽어 주십시오

설치 방법은 전과 같습니다. 다만 이번 판은 **사안을 끝내는 방법**이 다시 정해진 판입니다. v1.5.0이 **「전달본에서 무엇을 빼는가」**를 정했다면, v1.6.0은 **「누가·어디서·어떻게 빼는가」**를 정합니다. 사안 종결 규율이 **3항 → 6항**이 되었습니다. 그리고 **02 결정기록 양식이 처음으로 동봉**됩니다. 다섯만 기억하시면 됩니다.

**① 흐름은 한 방향뿐입니다 — 전달본에서 발견한 것은 전달본에서 고치지 마십시오.**
**정본 → 변환(export) → 전달본 → 패키지.** 전달본을 직접 고치는 순간 정본이 뒤처집니다. 발견은 **정본으로 되돌리고 전달본을 다시 만드십시오**(게이트 반송과 같은 구조). 변경은 두 종류뿐입니다 — **(가) 사실·판단의 정정**(수치, 문구, 어휘 순화, 시트명)은 **정본에서**, **(나) 전달 형태의 변환**(시트·열 제거, 내부 식별자 제거, 수식→값, 서식)은 **변환 단계에서** 합니다.

> 왜 생겼는가 — 전달본을 다시 만들다가, 시트명 정리·문언 수정·수치 정정이 **전달본에만** 적용되어 있어 **회사가 가진 사본이 회계법인 정본보다 정확한** 상태가 드러났습니다. 42셀을 정본으로 되돌린 뒤에야 재생성이 성립했습니다. 두 사안에서 같은 일이 있었습니다.

**② 기계 검사가 7유형으로 바뀌었고, 기계가 못 잡는 것을 눈으로 보는 검사가 생겼습니다.**
종전 정규식은 `v31 = v30 + …`·`rev3`·`WP5`·게이트 시트명 참조·경위 어휘를 놓쳤습니다. 이제 **VER · REV · WP · PHASE · GATE · PROC · CONF** 7유형으로 훑고, **시트명 자체와 수식 결과 문자열**도 대상입니다. 게이트 접두(`IAR_`·`CG_`·`G1_`·`V6_` …)는 **사안마다 다르므로 그 사안의 접두를 먼저 등록**하십시오. 그리고 **잔여 0건이어도** 02 「확정 상태」 공란·위치 열의 시트명 실재 여부·요약 = 표 집계·결론 수치 = 정본 값을 **읽기 전용으로** 확인합니다.

> 실제로 잔여 0건 상태에서 02 「확정 상태」가 48행 중 **38행 공란**이었고, 「03위치 검증」의 시트명 **23행이 전달본에 없는 시트**였습니다. 토큰 검사로는 원리상 잡히지 않습니다.

**③ 구값을 「문자열이 같은가」가 아니라 「같은 지표가 두 곳에서 다른 값을 말하는가」로 찾습니다.**
정본 블록의 지표마다 배수·백분율·범위 표기·자리수 변형을 만들어 전 시트에서 찾고, 지표별로 **어느 셀이 그 값을 인용하는지** 목록을 남깁니다.

> **게이트를 통과한 워크북**에서 나왔습니다. 서술의 영업이익률 사분위가 「0.6%~8.4%」였는데 같은 워크북의 정본 블록은 0.4% / 1.4% / 8.0%였습니다. 문자열이 달라 종전 검사에서는 통과했습니다.

**④ 회사가 자기 제출본을 만들 때의 제거 목록이 생겼습니다.**
규율을 수행하는 주체는 **문서를 내보내는 쪽**입니다. 회계법인이 회사에 줄 때는 회계법인이, **회사가 과세당국·감사인·모회사에 낼 때는 회사가** 수행합니다. 같은 규율이고 **제거 목록만 달라집니다** — 회사판에는 **Phase 0-α 전기 대조표의 A블록(원가상세·거래별 명세)·인터뷰 원문·내부 발표자료 인용**이 더 빠집니다.

> 원가 재검증(§6.5)을 권할수록 이 분리가 필요해집니다. 대조표는 회사 원가상세·인보이스를 **워크북에 시트로 남기기** 때문입니다. **대조표를 만드시는 자리마다 「제출본에서는 A블록을 뺀다」를 함께 적어 두십시오.**

**⑤ 02 결정기록 양식이 플러그인에 동봉되었습니다.**
`workbook-validator\references\02_결정기록_템플릿.xlsx`(외국계법인 사안은 `workbook-validator-inbound\references\` 아래 같은 파일)를 사안 폴더의 `02_결정기록\`에 복사해 쓰십시오. 네 시트 — 작성원칙 · 결정기록(13열) · 03위치 검증 · **결정·검증 색인**입니다. **「사용자 판정」은 채택 / 채택(잠정) / 미결 / 철회 4종, 「검증 유형」은 8종으로 양식에서 고정**되고, **결정을 적는 같은 회차에 색인을 함께** 채웁니다. **게이트는 여전히 02를 만들지 않습니다** — 읽고 인수하며, 없으면 위치를 알려 드립니다. 판정은 담당자 몫입니다.

> 양식이 사안마다 달라 열 이름과 판정 어휘가 갈렸고, 색인이 없던 사안에서는 **검증 기록 25건을 나중에** 조서를 거슬러 만들어야 했습니다. 동봉 파일은 플러그인에 함께 설치되므로 **별도 폴더 연결이 필요 없습니다.**

> ⚠️ **이 배포본에는 (02 양식 말고는) 규율만 있고 도구는 들어 있지 않습니다.** 게이트가 자기 산출물을 자기가 검사하면 검증 규율 3항(자기 산출물 검증 면제 금지)과 충돌하므로, **전달본 생성은 게이트 밖에서** 하십시오 — 스프레드시트 기능이나 별도 도구로 수행하시되 **수행 사실과 검사 결과를 조서에 남기십시오.** 가장 흔한 실패는 **「규율은 읽었으나 수행하지 않았다」**입니다.

> 예전 판본에서 통과한 사안을 다시 돌리면 새 [등급 A]가 잡힐 수 있습니다 — **결함이 아니라 판본 차이**입니다. 자세한 것은 사용 설명서 **§6.5-1**(02 양식)·**§6.6**(전면 개정)과 **§6.7·§8.10**에 있습니다. 진행 중인 사안이 있으시면 **그 절만이라도 먼저** 봐 주십시오.

## 1. 받으신 파일

파일 이름에 **본인 성함**이 붙어 있습니다.

| 파일 | 용도 |
|---|---|
| `tp-skills_홍길동.plugin` | **설치하는 파일.** 이것 하나만 설치하시면 됩니다 |
| `tp-skills_홍길동.plugin.sha256` | 파일이 도중에 바뀌지 않았는지 확인하는 값 |

> **왜 이름이 붙어 있는가** — 배포본은 **수령자마다 다른 사본**입니다. 안에 수령자 표식(`RECIPIENT.txt`)이 들어 있고, 그래서 파일 전체의 해시도 사람마다 다릅니다. **스킬의 동작에는 아무 영향이 없습니다.**
>
> 이 사본은 **본인에게만 제공된 것**입니다. 다른 사람에게 전달하지 마십시오. 필요한 분이 있으면 관리자에게 요청하시면 그분 이름의 사본을 발급합니다.

**필요 조건** — 유료 플랜(Pro·Max·Team·Enterprise) + Claude 데스크톱 앱 또는 Cowork.
**무료 플랜에서는 플러그인이 설치되지 않습니다.**

## 2. 설치 (5단계)

1. Cowork를 쓰신다면 **「Cowork」 탭**을 엽니다.
2. 왼쪽 사이드바에서 **「Customize」**를 엽니다.
3. **「Plugins」 탭**으로 이동합니다.
4. **「+」 버튼** → 커스텀 플러그인 파일 업로드 → **본인 이름이 붙은 `.plugin`** 선택.
5. 목록에 `tp-skills`가 나타나면 완료입니다.

> **먼저 지워야 할 것이 있습니다.** 같은 이름의 스킬을 **개별로** 설치해 두셨다면 Customize → Skills에서 지운 뒤 플러그인만 남기십시오. 두 벌이 남으면 **구버전이 섞여** 동작합니다. 이전 버전 플러그인(v1.5.0 이하)도 마찬가지로 먼저 제거하십시오.

## 3. 설치 확인 — 두 가지

**① 버전** — Customize → Plugins의 `tp-skills` 항목이 **`1.6.0`**으로 보이면 정상입니다.

**② 스킬 목록** — 대화창에서 **「/」**를 입력하면 `tp-case-law`·`workbook-validator` 등 **13종**이 보입니다.

**③ 동봉 양식** 〔v1.6.0〕 — 02 결정기록 양식의 위치를 모르시겠으면 **「02 결정기록 양식 어디 있나요」**라고 물어보십시오. 게이트가 설치 경로를 알려 드립니다.

---

## 4. 정본 확인 — 받은 파일이 진짜인가

설치 **전에** PowerShell에서 한 줄이면 됩니다. 파일이 있는 폴더에서(파일명은 본인 것으로):

```
Get-FileHash .\tp-skills_홍길동.plugin -Algorithm SHA256 | Format-List
```

출력된 `Hash` 값이 함께 받으신 **`.sha256` 파일의 내용과 같아야** 합니다.

**다르면 설치하지 마시고 관리자에게 연락하십시오.**

> **왜 이걸 하는가** — 파일이 전달 과정에서 깨지거나 바뀌었는지 보는 절차입니다. 값이 조금이라도 다르면 다른 파일입니다.
>
> **값은 사람마다 다릅니다.** 수령자별 사본이므로 동료의 값과 비교하시면 당연히 다릅니다. 반드시 **본인이 받은 `.sha256`**과 대조하십시오.
>
> **한 가지 더** — 해시 값과 플러그인 파일을 **같은 경로로** 받으셨다면, 그 확인은 「깨지지 않았다」까지만 보증합니다. 출처가 의심스러운 상황이라면 관리자에게 **다른 통로**(메신저·전화)로 값을 재확인하십시오.

## 5. 설치 후에는 자동으로 확인됩니다

각 스킬은 본격 작업에 들어가기 전에 **자기 파일이 정본과 같은지 스스로 확인**합니다(Phase 0 무결성 확인).

| 상황 | 표시 | 하실 일 |
|---|---|---|
| 정상 | **아무 말 없이 진행** | 없음 |
| 파일이 다름 | 「무결성 확인 — 변조·누락」 | **작업 중단 → 관리자 연락 → 재설치** |
| 확인 못 함 | 「무결성 확인 미실행」 | 중요한 산출물이면 재설치 후 다시 실행 |
| 공통 스킬 없음 | 「[미설치] tp-case-law」 | 그 답변의 **조문 인용은 미확인 상태**입니다. 플러그인 전체 재설치 |

## 6. 하지 말아야 할 것

- **스킬 파일을 직접 수정하지 마십시오.** 검증 규율이 누적된 파일이고, 수정하면 무결성 확인에서 「변조」로 검출됩니다. 개선 의견은 관리자에게 주시면 정본 저장소에 반영한 뒤 새 버전으로 배포합니다.
- **개별 스킬과 플러그인을 같이 두지 마십시오.** 어느 쪽이 동작할지 알 수 없습니다.
- **받으신 사본을 다른 사람에게 전달하지 마십시오.** 사내·사외를 가리지 않습니다. 배포본에는 **수령자 표식**이 들어 있어 사후에 출처를 확인할 수 있습니다. 필요한 분은 관리자에게 요청하시면 그분 이름의 사본을 발급받습니다.
- **`RECIPIENT.txt`를 지우지 마십시오.** 동작과 무관한 파일이며, 삭제하면 그 자체가 기록으로 남습니다.
- **내부 판본을 그대로 회사에 보내지 마십시오.** 〔v1.5.0〕 전달본은 §0 ①대로 따로 만들고, 잔여 검사가 0건인 것을 확인한 뒤 보냅니다.
- **전달본을 직접 고치지 마십시오.** 〔v1.6.0〕 고칠 것은 정본에서 고치고 전달본을 다시 만드십시오. 전달본에서 **행·열을 옮기는 것**도 하지 마십시오 — 02의 「03 반영 위치」 토큰이 통째로 어긋납니다.
- **시트명에 작업 접미(`_AI`·`_작업`·판본 접미)를 붙이지 마십시오.** 〔v1.6.0〕 셀 검사로는 잡히지 않고, 전달본에서만 지우면 정본이 틀린 채로 남습니다.
- **정본 02에서 열을 지우지 마십시오.** 〔v1.6.0〕 제거는 전달본을 만드는 단계에서 합니다. 정본 02는 전 열을 그대로 둡니다.
